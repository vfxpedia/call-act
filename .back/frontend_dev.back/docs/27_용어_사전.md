## 1. 시스템 용어

### CALL:ACT
**Call Assistance with Live-Learning Technology**

카드사 상담사를 위한 AI 기반 실시간 상담 지원 시스템. STT(음성인식)와 RAG(검색증강생성) 기술을 결합하여 상담사가 고객과 대화하는 동안 실시간으로 필요한 정보를 칸반보드 형태로 제공합니다.

**핵심 기능**:
- 실시간 STT (음성 → 텍스트 변환)
- 키워드 자동 추출 및 태깅
- RAG 기반 문서 검색
- 수평 슬라이딩 칸반보드
- Step 자동 전환
- AI 자동 요약

---

### MVP (Minimum Viable Product)
최소 기능 제품. 현재 CALL:ACT는 MVP 단계로, 핵심 기능만 구현하여 검증 중입니다.

**현재 MVP 범위**:
- ✅ 로그인/인증
- ✅ 실시간 상담 시뮬레이션
- ✅ 키워드 태깅
- ✅ 칸반보드 (42개 카드)
- ✅ 사원 관리
- ✅ 통계 대시보드
- ❌ 실제 STT API 연동 (예정)
- ❌ 실제 DB 연동 (예정)

---

### Phase (단계)
프로젝트 개발 단계를 구분하는 용어입니다.

| Phase | 내용 | 상태 |
|-------|------|------|
| Phase 1-2 | 기본 구조 및 페이지 구현 | ✅ 완료 |
| Phase 3 | 칸반보드 및 데이터 확장 | ✅ 완료 |
| Phase 4 | fullText 약관 확장 | ✅ 완료 |
| **Phase 5** | **문서화** | 🔄 진행 중 |

| Phase 7 | STT API 연동 | 📅 예정 |
| Phase 8 | 배포 및 최적화 | 📅 예정 |

## 2. 기술 용어

### STT (Speech-to-Text)
음성을 텍스트로 변환하는 기술.

**CALL:ACT에서의 활용**:
- 실시간 상담 중 음성을 텍스트로 변환
- 상담사와 고객의 대화 내용을 실시간으로 화면에 표시
- 키워드 추출의 기반 데이터

**현재 구현**: 
- 시뮬레이션 모드 (mockData의 sttDialogue 순차 재생)
- 추후 실제 STT API (Google Cloud Speech-to-Text 등) 연동 예정

---

### RAG (Retrieval-Augmented Generation)
검색 증강 생성. 외부 지식베이스에서 관련 정보를 검색한 후, 그 정보를 바탕으로 답변을 생성하는 기술.

**CALL:ACT에서의 활용**:
- 키워드 기반 문서 검색
- 칸반보드 카드 추천
- 유사 상담 사례 검색
- AI 자동 요약 생성

**기술 스택**:
- PostgreSQL + pgvector (벡터 DB)
- OpenAI Embeddings (텍스트 → 벡터 변환)
- FastAPI (검색 엔드포인트)

---

### 칸반보드 (Kanban Board)
작업을 시각화하여 관리하는 보드. 일반적으로 To-Do, In Progress, Done 같은 열(Column)로 구성됩니다.

**CALL:ACT에서의 칸반보드**:
- **전통적 칸반**: 세로 누적 방식 (To-Do → In Progress → Done)
- **CALL:ACT 칸반**: 수평 슬라이딩 방식 (Step 1 → Step 2 → Step 3)

**특징**:
- 각 Step은 "현재 상황" 카드 2개 + "다음 단계" 카드 2개로 구성
- 키워드 태깅 조건 충족 시 다음 Step으로 자동 전환
- 우→좌 슬라이딩 애니메이션 (Motion/Framer Motion)

---

### Step (단계)
칸반보드의 각 단계. 상담 프로세스를 3단계로 나눔.

**예시 (카드분실 시나리오)**:
- **Step 1: 문제 파악** - 분실 확인, 마지막 사용 위치 확인
- **Step 2: 즉시 조치** - 카드 정지, 부정 사용 확인
- **Step 3: 후속 처리** - 재발급 안내, 임시 카드 발급

---

### 키워드 태깅 (Keyword Tagging)
STT로 변환된 텍스트에서 중요한 키워드를 자동으로 추출하여 태그로 표시하는 기능.

**동작 원리**:
1. STT 메시지 수신
2. wordQueueProcessor에서 키워드 사전 매칭
3. 매칭된 키워드를 화면에 태그로 표시
4. 카테고리별 색상 구분 (예: 분실 → 빨강, 해외결제 → 파랑)

**예시**:
```
고객: "카드를 잃어버렸어요"
→ 키워드 추출: #분실, #카드
→ 태그 표시: [분실] [카드] (빨강 배경)
```

---

### Mock Data (모의 데이터)
실제 API/DB 연동 전에 사용하는 가짜 데이터.

**CALL:ACT의 Mock Data**:
- `employeesData`: 50명 사원 정보
- `consultationsData`: 100건 상담 이력
- `scenariosData`: 6개 시나리오 (카드분실, 해외결제 등)
- `kanbanCards`: 42개 카드 (6 시나리오 × 7 카드)

**파일 위치**: `/src/data/mockData.ts`

---

### LocalStorage
브라우저에 데이터를 저장하는 웹 스토리지 API.

**CALL:ACT에서의 활용**:
- 사용자 인증 정보 저장 (`employeeId`, `userRole`, `isAdmin`)
- 사원 목록 저장 (`employees`)
- 공지사항 저장 (`notices`)
- 상담 이력 저장 (`consultations`)

**특징**:
- 영구 저장 (브라우저 닫아도 유지)
- 문자열만 저장 가능 (객체는 `JSON.stringify()` 필요)
- 용량 제한: 약 5-10MB

## 3. 도메인 용어 (콜센터)

### ACW (After Call Work)
상담 후처리. 통화 종료 후 상담 내용을 정리하고 다음 조치를 준비하는 작업.

**CALL:ACT의 ACW 기능**:
- AI 자동 요약 생성
- 유사 상담 사례 검색 (RAG)
- 후속 조치(Next Action) 제안
- 상담 메모 작성

**목표**: 상담사의 후처리 시간을 50% 단축

---

### FCR (First Call Resolution)
첫 통화 해결률. 고객이 첫 번째 전화로 문제를 해결한 비율.

**계산 방식**:
```
FCR = (첫 통화로 해결된 건수 / 전체 상담 건수) × 100
```

**예시**:
- 오늘 상담 100건 중 89건이 첫 통화로 해결 → FCR 89%

**CALL:ACT 목표**: FCR 95% 달성 (업계 평균 85%)

---

### AHT (Average Handling Time)
평균 상담 처리 시간. 한 건의 상담을 처리하는 데 걸리는 평균 시간.

**계산 방식**:
```
AHT = (총 상담 시간 + 총 후처리 시간) / 총 상담 건수
```

**예시**:
- 평균 상담 시간: 4분 35초 (4:35)

**CALL:ACT 목표**: AHT 30% 단축 (6:00 → 4:12)

---

### 대기 콜 (Waiting Call)
상담사 배정을 기다리고 있는 고객 전화.

**CALL:ACT에서의 표시**:
```
카드분실 - 대기 3건 - 평균 대기시간 02:35 - 우선순위: 긴급
해외결제 - 대기 2건 - 평균 대기시간 01:20 - 우선순위: 보통
```

**우선순위**:
- **긴급** (urgent): 대기시간 2분 이상, 분실/도난 등
- **보통** (normal): 대기시간 2분 미만, 일반 문의

---

### IVR (Interactive Voice Response)
자동 음성 응답 시스템. 고객이 전화를 걸면 음성 안내에 따라 번호를 눌러 상담 카테고리를 선택합니다.

**예시**:
```
"안녕하세요. 테디카드입니다.
1번: 카드 분실/도난 신고
2번: 해외 사용 문의
3번: 포인트 조회
4번: 한도 증액
5번: 기타 문의"
```

**CALL:ACT 연동**: IVR에서 선택한 카테고리를 상담사에게 자동 전달 (인입 키워드)

---

### 인입 키워드 (Incoming Keywords)
고객이 IVR에서 선택한 카테고리 또는 상담 초기에 파악된 주요 키워드.

**예시**:
- IVR에서 "1번: 카드 분실/도난 신고" 선택
- → 인입 키워드: `["분실", "카드", "신고"]`
- → 상담사 화면에 자동으로 태그 표시

---

### 약관 (Terms and Conditions)
카드사의 서비스 이용 규정. CALL:ACT의 카드 fullText는 약관 형식으로 작성됩니다.

**예시**:
```
제34조 (카드 분실 및 도난)
① 회원이 카드를 분실하거나 도난당한 경우 즉시 회사에 신고하여야 합니다.
② 분실 신고 접수 시점부터 회사는 카드 사용을 정지합니다.
③ 분실 신고 이전에 발생한 부정 사용 금액은 회원이 부담할 수 있습니다.
단, 회원의 고의 또는 과실이 없는 경우 회사가 부담합니다.
```

## 5. UI 컴포넌트 용어

### 레이아웃 컴포넌트

**MainLayout**
- 메인 레이아웃 컴포넌트
- Header + Sidebar + Main Content 구조
- 모든 Protected 페이지에서 사용

**Header**
- 상단 헤더 (높이 60px)
- 로고, 사용자 정보, 알림, 로그아웃 버튼

**Sidebar**
- 좌측 사이드바 (너비 200px 또는 56px)
- 네비게이션 메뉴
- 확장/축소 가능
- 데스크톱: 항상 표시
- 모바일: 숨김

---

### 모달 (Modal)

**Dialog**
- 범용 다이얼로그 컴포넌트 (shadcn/ui)
- 배경 오버레이 + 중앙 모달
- ESC 키 또는 배경 클릭으로 닫기

**AddEmployeeModal**
- 사원 추가 모달
- 입력: 이름, 팀, 직급, 이메일, 전화번호
- 유효성 검사 + 자동 포맷팅 (전화번호)

**EditEmployeeModal**
- 사원 수정 모달
- 기존 데이터 표시 + 수정 가능

**ConsultationDetailModal**
- 상담 상세 모달
- 전체 대화 내용, 태그, FCR 여부, 메모 표시

**AnnouncementModal**
- 공지사항 상세 모달
- 제목, 내용, 작성자, 작성일, 조회수

---

### 카드 (Card)

**카드 종류**:
- **StatCard**: 통계 카드 (대시보드)
- **ConsultationCard**: 상담 카드 (상담 이력)
- **EmployeeCard**: 사원 카드 (모바일 뷰)
- **KanbanCard**: 칸반보드 카드 (실시간 상담)
- **WaitingCallCard**: 대기 콜 카드

**KanbanCard 구조**:
```tsx
{
  id: string;
  title: string;           // 제목
  summary: string;         // 요약 (1줄)
  fullText: string;        // 상세 내용 (약관 형식)
  requiredChecks: string[];// 필수 확인 사항
  exceptions: string[];    // 예외 사항
  systemPath: string;      // 시스템 경로
  regulation: string;      // 근거 규정
  category: string;        // 카테고리
  priority: 'high' | 'normal' | 'low';
  relatedKeywords: string[];
}
```

---

### 버튼 (Button)

**Variant (변형)**:
- `default`: 기본 (파란색 배경)
- `outline`: 테두리만 (투명 배경)
- `ghost`: 배경 없음
- `destructive`: 삭제/경고 (빨간색)
- `secondary`: 보조 (회색)

**Size (크기)**:
- `sm`: 작음 (h-8)
- `default`: 기본 (h-10)
- `lg`: 큼 (h-12)

**예시**:
```tsx
<Button variant="default" size="default">기본 버튼</Button>
<Button variant="outline" size="sm">작은 아웃라인</Button>
<Button variant="destructive">삭제</Button>
```

```tsx
interface PaginationProps {

  totalPages: number;
  onPageChange: (page: number) => void;
  totalItems: number;
  itemsPerPage: number;
}
```

## 8. 기타 용어

### Protected Route
인증이 필요한 페이지. 로그인하지 않으면 접근 불가.

**구현**:
```tsx
<Route element={<ProtectedRoute />}>
  <Route path="/dashboard" element={<DashboardPage />} />
  <Route path="/consultation/live" element={<RealTimeConsultationPage />} />
  {/* ... */}
</Route>
```

---

### shadcn/ui
Tailwind CSS 기반 UI 컴포넌트 라이브러리.

**특징**:
- 복사/붙여넣기 방식 (npm install 불필요)
- 완전한 커스터마이징 가능
- Radix UI 기반 (접근성 우수)

**사용 컴포넌트**:
- Button, Input, Select, Dialog, Checkbox, Label, Table 등

---

### Tailwind CSS
유틸리티 우선 CSS 프레임워크.

**예시**:
```html
<div class="flex items-center justify-between p-4 bg-white rounded-lg shadow-sm">
  Content
</div>
```

**CALL:ACT 버전**: v4.0 (최신)

---

### Motion (Framer Motion)
React 애니메이션 라이브러리.

**CALL:ACT에서의 활용**:
- 칸반보드 슬라이딩 애니메이션
- 페이드 인/아웃
- 로딩 인디케이터 회전

**예시**:
```tsx
<motion.div
  initial={{ x: '100%' }}
  animate={{ x: 0 }}
  exit={{ x: '-100%' }}
  transition={{ duration: 0.5 }}
>
  Content
</motion.div>
```

---

### React Router
React 라우팅 라이브러리.

**주요 훅**:
- `useNavigate()`: 페이지 이동
- `useLocation()`: 현재 경로 정보
- `useParams()`: URL 파라미터 추출

---

### Lucide React
아이콘 라이브러리.

**예시**:
```tsx
import { Phone, PhoneOff, Save, Edit2, Trash2 } from 'lucide-react';

<Phone className="w-5 h-5 text-blue-600" />
```

---

### Recharts
React 차트 라이브러리.

**CALL:ACT에서의 활용**:
- AdminStatsPage의 통계 차트
- LineChart, BarChart, PieChart
