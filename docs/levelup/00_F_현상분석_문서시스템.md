## 2. 발견된 근본 문제들

### 문제 A: 문서 ID 체계의 단절 (Critical)

```
Mock 세계:   card-1-1-1, SEARCH-POINT-001  (시나리오 기반 ID)
Real 세계:   rag-1739000000-0              (타임스탬프 기반 임시 ID)
DB 세계:     doc_id from consultations DB   (서버 관리 ID)
```

**영향**: DocumentDetailModal이 문서를 찾는 순서:
1. scenarios에서 ID 검색 → Mock ID만 찾을 수 있음
2. searchMockData에서 ID 검색 → Mock ID만 찾을 수 있음
3. 외부 documentData 사용 → **Real 데이터는 여기서만 작동**
4. 제목 유사 검색 (fallback)

**결론**: Real 데이터가 들어오면, 1-2단계는 무조건 실패하고 3단계 fallback에 의존.
이전에 저장된 상담 내역의 문서를 다시 열 때, DB에서 fullText를 못 가져오면 빈 모달 표시.

### 문제 B: 필드 이름 불일치 (High)

| Backend (snake_case) | Frontend (camelCase) | 변환 위치 |
|---------------------|---------------------|----------|
| `doc_id` | `id` / `documentId` | `ConsultationDetailModal:201` |
| `full_text` | `fullText` | `ConsultationDetailModal:207` |
| `doc_type` | `documentType` | 변환 없음 (**누락**) |
| `step_number` | `stepNumber` | `RealTimeConsultationPage:2054` |
| `view_count` | `viewCount` | `RealTimeConsultationPage:2058` |
| `source_table` | 없음 (documentType 추론용) | `convertRagToScenarioCard` |

**결론**: 변환 로직이 각 컴포넌트에 분산되어 있고, `doc_type` → `documentType` 변환이 누락됨.

### 문제 C: DocumentType 추론의 취약성 (High)

현재 추론 로직 (`DocumentDetailModal.tsx:29-55`):
```typescript
// 제목에 '카드'+'추천' 포함 → product-spec
// 제목에 '분석' 포함 → analysis-report
// 제목에 '가이드' 포함 → guide
// 제목에 '약관' 또는 내용에 '제1조' → terms
```

**문제**: 실제 데이터 제목이 이 패턴에 맞지 않을 가능성 높음.
- "테디카드 하이패스 자동충전 서비스" → guide? product-spec? 추론 실패 → general
- Backend의 `source_table`이 가장 정확하지만 프론트에서만 추론 시도

### 문제 D: FAQ 문서 연결의 하드코딩 (Medium)

`frequentInquiriesDetail.ts`:
```typescript
relatedDocument: {
  document_id: 'card-1-1-1',  // ← 시나리오 카드 ID에 하드코딩
  title: '카드 즉시 사용 정지',
}
```

Real 모드에서 FAQ 데이터가 API에서 올 때, `document_id`가 실제 DB 문서 ID여야 함.
현재는 시나리오 Mock ID에 묶여있어서 Real 모드에서 문서 상세보기 불가능.

### 문제 E: fullText 부재 시 빈 모달 (Medium)

DocumentDetailModal이 `fullText`를 기대하지만:
- RAG 응답의 `content`는 요약문 (2-3줄)
- `fullText`는 전체 약관/가이드 본문 (마크다운)
- Real 백엔드가 fullText를 보내지 않으면 → 모달에 요약문만 표시

### 문제 F: localStorage 의존성 (Medium)

문서 참조 흐름: 상담 중 → localStorage → 후처리 페이지 → API 저장

```
상담 중 카드 클릭 → localStorage['clickedDocuments']
상담 종료 시     → localStorage['referencedDocuments']
후처리 로드 시   → localStorage에서 읽기
저장 시          → API POST (referencedDocuments 배열)
```

**문제**: 브라우저 새로고침, 탭 전환, 네트워크 오류 시 localStorage 유실 가능.
상담 중 수집된 참조 문서가 후처리까지 전달되지 않을 위험.

## 3. 현재 프로덕션 상태 평가

### 잘 되어 있는 것
- DocumentType 5종 분류 체계 (terms, product-spec, guide, analysis-report, general)
- DocumentDetailModal의 타입별 UI 분기 (배경색, 아이콘, 레이아웃)
- InfoCard의 source별 배지 (ai-recommend, search-result, next-step)
- RAG WebSocket 연동 및 Step 히스토리 관리
- 모달 중첩 처리 (ESC 키 계층 관리)
- 클릭 추적 및 우선순위 정렬 (후처리 시)

### 개선이 필요한 것
- 문서 ID 체계 통일 (Mock ID vs Real ID vs DB ID)
- 필드 변환 로직 중앙화 (각 컴포넌트에 분산됨)
- DocumentType을 백엔드에서 확정적으로 전달
- fullText 보장 (백엔드 협의 필요)
- FAQ 문서 연결을 API 기반으로 전환
- 문서 참조 전달의 안정성 (localStorage → 더 안정적 방법)

                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   ┌──────────┐   ┌──────────┐   ┌──────────────┐
   │ RAG API  │   │ 상담 API │   │ FAQ API      │

   └────┬─────┘   └────┬─────┘   └──────┬───────┘
        │               │                │
   변환 필요        변환 필요        변환 필요
   (RAGCard→       (snake→          (document_id→
    ScenarioCard)   camelCase)       실제 doc_id)
        │               │                │
        ▼               ▼                ▼
   ┌──────────────────────────────────────────┐
   │        ScenarioCard (통합 인터페이스)       │
   │  id | title | content | fullText |       │
   │  documentType | keywords | ...           │
   └──────────────────────┬───────────────────┘
                          │
    ┌────────┬────────┬───┴───┬────────┬────────┐
    ▼        ▼        ▼       ▼        ▼        ▼
  칸반     검색     종료모달  후처리   상담내역   FAQ

Real 데이터 변환 시 빈틈이 있어서 일부 뷰에서 불완전하게 표시됨.
