# v25 작업 내역

## 작업 일자: 2026-02-06

---

## 핵심 변경 요약

v25는 **교육 시뮬레이션 TTS**, **RAG 카드 파이프라인 강화**, **검색 레이어 개선**, **STT 키워드 감지**를 중심으로 한 고도화 버전입니다.

| 영역 | 주요 변경 |
|------|----------|
| 교육 TTS | sLLM 고객 응답 + Qwen3-TTS 음성 생성 + WebSocket 전송 |
| RAG 카드 | structured JSONB 활용, 4개 카드 보장, 문서 타입 매핑 기초 |
| 검색 레이어 | 대기콜/다이렉트콜/대기중 3분기 정리, 실제 RAG API 연동 |
| STT 키워드 | 8개 카테고리 키워드 실시간 감지 + 컬러 태깅 |
| 후처리 | AfterCallWorkPage STT 전문 로드 + LLM 화자 분리 연동 |

## 1. 교육 시뮬레이션 TTS (백엔드)

### 1-1. 교육 WebSocket (`/ws/edu`)

| 파일 | 변경 |
|------|------|
| `backend_dev/app/api/v1/endpoints/edu_websocket.py` | STT 결과 프론트 전송, 시뮬레이션 모드 sLLM 응답 생성 |
| `backend_dev/app/llm/education/edu_handler.py` | `handle_agent_message()` — sLLM + TTS를 `asyncio.to_thread()`로 실행 |
| `backend_dev/app/llm/education/tts_speaker.py` | `process_agent_input()` — LLM 응답 → TTS 파일 생성 → audio_url 반환 |
| `backend_dev/app/llm/education/tts_engine.py` | `generate_speech()` — RunPod Qwen3-TTS `/tts` API 호출, WAV 파일 저장 |

### 1-2. 교육 TTS 흐름
```
[상담원 음성/텍스트 입력]
    ↓
WebSocket /ws/edu 수신
    ↓
Whisper STT → {"type": "stt", "text": "..."} 전송
    ↓
is_simulation_active() → handle_agent_message()
    ↓
asyncio.to_thread(process_agent_input)
    ├─ generate_text() → sLLM (Kanana-2.1B) 고객 응답 생성
    ├─ generate_speech() → Qwen3-TTS 음성 파일 생성
    └─ audio_url = "/static/tts_output/{session_id}/response_001.mp3"
    ↓
{"type": "customer_response", "data": {"text": "...", "audio_url": "..."}} 전송
```

### 1-3. WebSocket 메시지 타입

| 타입 | 방향 | 설명 |
|------|------|------|
| `connected` | → 프론트 | WebSocket 연결 확인 + `ws_session_id` |
| `stt` | → 프론트 | STT 음성 인식 결과 텍스트 |
| `rag` | → 프론트 | RAG 검색 결과 (카드 데이터) |
| `customer_response` | → 프론트 | AI 고객 응답 텍스트 + TTS audio_url |
| `simulation_initialized` | → 프론트 | 시뮬레이션 초기화 완료 |
| `init_simulation` | ← 프론트 | 시뮬레이션 세션 초기화 요청 |
| `text_message` | ← 프론트 | 텍스트 입력 (키보드) |

### 2-2. 카드 생성 우선순위
```
1. LLM 카드 (상위 N개 문서 → gpt-4.1-mini로 JSON 카드 생성)
2. 규칙 기반 카드 (나머지 문서 → _doc_to_card_base() + structured JSONB)
3. 보장: card_info는 LLM 2개 + 규칙 2개, 그 외 라우트는 4개까지 규칙 기반 보충
```

```python

    "card_products": "product-spec",
```

## 3. 프론트엔드 검색 레이어 개선

### 3-1. 검색 분기 정리 (`searchSimulator.ts`)

| 상황 | 동작 | 검색 방식 |
|------|------|----------|
| 대기콜 통화 중 | `isCallActive && !isDirectIncoming` | Mock 검색 |
| 대기중 (통화 전) | `!isCallActive` | 실제 RAG API |
| 다이렉트콜 | `isDirectIncoming` | 실제 RAG API |
| Mock 모드 | `USE_MOCK_DATA = true` | Mock 검색 |

### 3-2. RAG API 연동 (`searchWithRAG`)
- `POST /api/v1/rag/` — `{ query, top_k: 4 }`
- 응답: `currentSituation` + `nextStep` 카드 합쳐서 **2개 제한**
- 각 카드에 `relevanceScore`, `documentType` 추가
- 실패 시 Mock fallback

### 3-3. 검색 이력 (`searchLayerHelpers.ts`)
- 검색 결과 localStorage 저장 (최대 20건)
- `SearchHistoryDropdown` 컴포넌트에서 페이징 + 개별 삭제

## 4. STT 키워드 감지 + 컬러 태깅 (프론트엔드)

### 4-1. 키워드 카테고리 (8개)

| 카테고리 | 키워드 예시 |
|----------|-----------|
| 분실/도난 | 카드분실, 분실신고, 재발급, 도난, 긴급정지 |
| 한도 | 한도증액, 한도조회, 신용한도, 증액신청 |
| 결제/승인 | 결제, 승인, 선결제, 승인취소, 결제오류 |
| 이용내역 | 이용내역, 거래내역, 사용내역, 명세서 |
| 수수료/연체 | 연체, 수수료문의, 연회비, 이자, 미납 |
| 포인트/혜택 | 포인트, 마일리지, 캐시백, 적립, 혜택 |
| 정부지원 | 정부지원, 바우처, 등유, 임신, 육아 |
| 기타 | 일반상담, 카드발급, 해외결제, 결제일변경 |

### 4-2. 컬러 태깅 (10종)

| 카테고리 | 배경색 | 텍스트색 |
|----------|--------|---------|
| 카드종류 | `#E3F2FD` | `#1976D2` (블루) |
| 분실도난 | `#FFEBEE` | `#C62828` (레드) |
| 재발급 | `#E8F5E9` | `#2E7D32` (그린) |
| 결제승인 | `#FFF3E0` | `#EF6C00` (오렌지) |
| 포인트마일 | `#FCE4EC` | `#C2185B` (핑크) |
| 수수료연회비 | `#F3E5F5` | `#7B1FA2` (퍼플) |
| 해외사용 | `#E0F2F1` | `#00695C` (틸) |
| 한도관리 | `#E1F5FE` | `#0277BD` (시안) |
| 연체납부 | `#FFF8E1` | `#F57C00` (앰버) |
| 결제일 | `#F1F8E9` | `#558B2F` (라임) |

### 4-3. 동작 흐름
```
[WebSocket] STT 결과 수신
    ↓
handleSttResult(text)
    ├─ 단어 분리 → incomingKeywordsByCase 8개 카테고리 매칭
    ├─ 매칭된 키워드 → displayedKeywords (최대 3개)
    ├─ sttTexts에 { text, isKeyword, speaker } 추가
    └─ sttTranscript에 { speaker: 'agent', message, timestamp } 추가
```

## 5. 교육 모드 프론트엔드 연동

### 5-1. WebSocket 엔드포인트 분기

| 파일 | 변경 |
|------|------|
| `frontend_dev/src/app/hooks/useVoiceRecoders.ts` | `wsEndpoint` 옵션 추가, `onCustomerResponse` 콜백, `onConnected` 콜백 |
| `frontend_dev/src/app/pages/RealTimeConsultationPage.tsx` | 교육 모드: `ws/edu`, 실전 모드: `ws/call` |

```typescript
const wsEndpoint = isSimulationMode
  ? "ws://127.0.0.1:8000/api/v1/ws/edu"
  : "ws://127.0.0.1:8000/api/v1/ws/call";
```

### 5-2. 교육 시뮬레이션 초기화 흐름
```
[시뮬레이션 시작]
    ↓
REST POST /education/simulation/start → simulation_session_id 획득
    ↓
useVoiceRecorder({ wsEndpoint: "ws/edu", onConnected, ... })
    ↓
WebSocket 연결 → {"type": "connected", "ws_session_id": "abc"}
    ↓
onConnected → trySendInitSimulation()
    ↓
sendMessage({ type: "init_simulation", simulation_session_id: "..." })
    ↓
{"type": "simulation_initialized"} 수신
```

### 5-3. AI 고객 응답 처리 (`handleCustomerResponse`)
- 고객 발화를 `sttTexts`에 `speaker: 'customer'`로 추가
- `sttTranscript`에도 추가 (후처리용)
- `audio_url` → `new Audio()` 재생

### 5-4. sendMessage ref 패턴
```typescript
// useVoiceRecorder 반환값의 sendMessage를 onConnected에서 사용하면 순환참조
// → ref 패턴으로 해결
const sendMessageRef = useRef(null);
sendMessageRef.current = sendMessage; // hook 반환 후 업데이트
```

| 파일 | 변경 |

```

  → result.summary (상담 요약: title, category, process, next_step 등)
  → result.evaluation (상담 평가)
```

## 테스트 방법

### 백엔드 준비
```bash
cd backend_dev
uvicorn app.main:app --reload
```

### 프론트엔드 실행
```bash
cd frontend_dev
npm run dev
```

### 테스트 시나리오

1. **대기콜 테스트 (Mock 데이터)**
   - 실시간 상담 → 인입케이스 클릭 → Mock 시나리오 카드 확인
   - 검색 어시스턴트 → Mock 검색 결과 확인

2. **다이렉트 콜 테스트 (실제 RAG)**
   - 다이렉트 콜 클릭 → 마이크 허용
   - 콘솔: `[WebSocket] 연결 성공`, `[STT] 음성 인식 결과`, `[RAG] 결과 수신`
   - 칸반보드에 RAG 카드 4개 표시 확인
   - STT 키워드 컬러 태깅 확인

3. **교육 시뮬레이션 TTS 테스트**
   - 시뮬레이션 페이지 → 시나리오 선택 → 시작
   - 콘솔: `init_simulation 전송`, `simulation_initialized 수신`
   - 음성 입력 → AI 고객 응답 텍스트 표시 + TTS 오디오 재생
   - 콘솔: `[교육] AI 고객 응답:`, `[TTS] 재생`

4. **검색 어시스턴트 테스트**
   - 대기중: 실제 RAG API 호출 확인
   - 대기콜 통화 중: Mock 검색 확인
   - 다이렉트콜: 실제 RAG API 호출 확인

5. **후처리 테스트**
   - 통화 종료 → AfterCallWorkPage 이동
   - STT 전문 표시 확인 (상담사/고객 구분)
   - LLM 화자 분리 결과 반영 확인
