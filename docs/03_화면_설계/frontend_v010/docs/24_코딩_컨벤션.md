## 2. 컴포넌트 작성 규칙

### 2.1 함수형 컴포넌트

**규칙**: `function` 키워드 사용 + `default export`

```tsx
✅ 올바른 예시:
export default function DashboardPage() {
  return <div>...</div>;
}

❌ 잘못된 예시:
const DashboardPage = () => {
  return <div>...</div>;
};
export default DashboardPage;

// 또는
export const DashboardPage: React.FC = () => {
  return <div>...</div>;
};
```

### 2.2 Props 인터페이스

**규칙**: 컴포넌트명 + `Props` 접미사, 컴포넌트 정의 바로 위에 작성

```tsx
✅ 올바른 예시:
interface MainLayoutProps {
  children: ReactNode;
}

export default function MainLayout({ children }: MainLayoutProps) {
  return <div>{children}</div>;
}

❌ 잘못된 예시:
// Props를 inline으로 작성
export default function MainLayout({ children }: { children: ReactNode }) {
  return <div>{children}</div>;
}

// 또는 Props 접미사 없이 작성
interface MainLayout {
  children: ReactNode;
}
```

### 2.4 조건부 렌더링

**규칙**: 간단한 경우 `&&` 사용, 복잡한 경우 삼항 연산자 또는 Early Return

```tsx
✅ 올바른 예시:
// 간단한 경우
{isLoading && <Spinner />}

// 양쪽 모두 렌더링하는 경우
{isAdmin ? <AdminPanel /> : <UserPanel />}

// 복잡한 경우 (Early Return)
if (!data) {
  return <Spinner />;
}

return <Table data={data} />;

❌ 잘못된 예시:
// 불필요한 삼항 연산자
{isLoading ? <Spinner /> : null}

// 중첩된 조건부 렌더링
{isLoading ? (
  <Spinner />
) : isError ? (
  <Error />
) : (
  <Table />
)}
// → Early Return으로 변경 권장
```

## 3. TypeScript 규칙

### 3.1 타입 vs 인터페이스

**규칙**: 
- **Props, 객체 형태**: `interface` 사용
- **Union, Primitive**: `type` 사용

```tsx
✅ 올바른 예시:
// Props는 interface
interface UserCardProps {
  user: User;
  onEdit: (id: string) => void;
}

// Union은 type
type Status = 'active' | 'inactive' | 'pending';

// 객체는 interface
interface User {
  id: string;
  name: string;
  status: Status;
}

❌ 잘못된 예시:
// Props를 type으로
type UserCardProps = {
  user: User;
};

// 객체를 type으로
type User = {
  id: string;
  name: string;
};
```

### 3.2 any 금지

**규칙**: `any` 사용 금지, `unknown` 또는 구체적인 타입 사용

```tsx
✅ 올바른 예시:
// 구체적인 타입
const handleSubmit = (data: FormData) => {
  // ...
};

// unknown (타입 가드와 함께)
const parseData = (data: unknown) => {
  if (typeof data === 'string') {
    return JSON.parse(data);
  }
  return null;
};

❌ 잘못된 예시:
const handleSubmit = (data: any) => {
  // ...
};
```

### 3.3 Optional Chaining 사용

**규칙**: 중첩된 객체 접근 시 `?.` 사용

```tsx
✅ 올바른 예시:
const userName = user?.profile?.name ?? '이름 없음';

❌ 잘못된 예시:
const userName = user && user.profile && user.profile.name 
  ? user.profile.name 
  : '이름 없음';
```

### 3.4 Nullish Coalescing 사용

**규칙**: 기본값 설정 시 `??` 사용 (0, false를 유효한 값으로 처리)

```tsx
✅ 올바른 예시:
const count = userInput ?? 10;  // userInput이 null/undefined일 때만 10
const isActive = user.isActive ?? false;  // 명시적 기본값

❌ 잘못된 예시:
const count = userInput || 10;  // userInput이 0일 때도 10이 됨
```

## 6. 상태 관리 규칙

### 6.1 useState 명명

**규칙**: `[value, setValue]` 형식

```tsx
✅ 올바른 예시:
const [isOpen, setIsOpen] = useState(false);
const [userData, setUserData] = useState<User | null>(null);
const [employees, setEmployees] = useState<Employee[]>([]);

❌ 잘못된 예시:
const [isOpen, setOpen] = useState(false);
const [userData, updateUserData] = useState<User | null>(null);
const [employees, changeEmployees] = useState<Employee[]>([]);
```

### 6.2 LocalStorage 저장

**규칙**: 
- 저장: `JSON.stringify()` 사용
- 읽기: `JSON.parse()` + try-catch

```tsx
✅ 올바른 예시:
// 저장
localStorage.setItem('user', JSON.stringify(user));

// 읽기
const savedUser = localStorage.getItem('user');
let user = null;
if (savedUser) {
  try {
    user = JSON.parse(savedUser);
  } catch (e) {
    console.error('Failed to parse user data', e);
  }
}

// 읽기 (간단한 방법)
const user = JSON.parse(localStorage.getItem('user') || '{}');

❌ 잘못된 예시:
// try-catch 없이 파싱
const user = JSON.parse(localStorage.getItem('user'));
```

### 6.3 useEffect 의존성 배열

**규칙**: 
- 필요한 의존성만 추가
- ESLint 경고 무시하지 않기

```tsx
✅ 올바른 예시:
useEffect(() => {
  fetchData(userId);
}, [userId]); // userId가 변경될 때만 실행

useEffect(() => {
  const interval = setInterval(() => {
    updateTime();
  }, 1000);
  
  return () => clearInterval(interval); // Cleanup
}, []); // 마운트 시 한 번만

❌ 잘못된 예시:
useEffect(() => {
  fetchData(userId);
}, []); // userId 변경을 감지하지 못함

// eslint-disable-next-line react-hooks/exhaustive-deps
useEffect(() => {
  fetchData(userId);
}, []); // ESLint 경고 무시 (권장하지 않음)
```

## 7. 데이터 처리 규칙

### 7.1 배열 처리

**규칙**: Immutable 방식 사용

```tsx
✅ 올바른 예시:
// 추가
setEmployees(prev => [...prev, newEmployee]);

// 수정
setEmployees(prev => prev.map(emp => 
  emp.id === id ? { ...emp, name: newName } : emp
));

// 삭제
setEmployees(prev => prev.filter(emp => emp.id !== id));

// 정렬 (새 배열 생성)
const sorted = [...employees].sort((a, b) => a.rank - b.rank);

❌ 잘못된 예시:
// 직접 수정 (Mutation)
employees.push(newEmployee);
setEmployees(employees);

employees[0].name = newName;
setEmployees(employees);

employees.sort((a, b) => a.rank - b.rank);
setEmployees(employees);
```

### 7.2 객체 처리

**규칙**: Spread 연산자 사용

```tsx
✅ 올바른 예시:
// 복사 및 수정
const updatedUser = { ...user, name: 'New Name' };

// 중첩 객체 수정
const updatedUser = {
  ...user,
  profile: {
    ...user.profile,
    email: 'new@email.com'
  }
};

❌ 잘못된 예시:
// 직접 수정
user.name = 'New Name';

user.profile.email = 'new@email.com';
```

### 7.3 데이터 필터링

**규칙**: 체이닝 사용, 조건 명확하게

```tsx
✅ 올바른 예시:
const filteredEmployees = employees
  .filter(emp => emp.status === 'active')
  .filter(emp => emp.team === selectedTeam)
  .sort((a, b) => a.rank - b.rank)
  .slice(0, 10);

// 또는 한 번에
const filteredEmployees = employees.filter(emp => {
  if (emp.status !== 'active') return false;
  if (selectedTeam && emp.team !== selectedTeam) return false;
  return true;
});

❌ 잘못된 예시:
// 중간 변수 남발
let temp1 = employees.filter(emp => emp.status === 'active');
let temp2 = temp1.filter(emp => emp.team === selectedTeam);
let temp3 = temp2.sort((a, b) => a.rank - b.rank);
const filteredEmployees = temp3.slice(0, 10);
```

### 9.3 Early Return 사용

**규칙**: 가드 조건은 상단에

```tsx
✅ 올바른 예시:
function processData(data: Data | null) {
  if (!data) return null;
  if (data.length === 0) return [];
  if (!data.isValid) return null;
  
  // 실제 로직
  return data.map(item => transform(item));
}

❌ 잘못된 예시:
function processData(data: Data | null) {
  if (data && data.length > 0 && data.isValid) {
    return data.map(item => transform(item));
  } else if (!data) {
    return null;
  } else if (data.length === 0) {
    return [];
  } else {
    return null;
  }
}
```

### 9.4 Console.log 제거

**규칙**: 프로덕션 코드에서 제거 (개발 중에만 사용)

```tsx
✅ 올바른 예시:
// 개발 환경에서만 로그
if (process.env.NODE_ENV === 'development') {
  console.log('Debug:', data);
}

// 또는 제거
// console.log('Debug:', data);

❌ 잘못된 예시:
console.log('User data:', user);
console.log('Clicked!');
```
