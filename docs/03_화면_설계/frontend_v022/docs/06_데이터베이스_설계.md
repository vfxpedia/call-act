## 1. 데이터베이스 개요

### 1.1 데이터베이스 정보

| 항목 | 값 |
|------|-----|
| **DBMS** | PostgreSQL 15+ |
| **확장** | pgvector (벡터 검색) |
| **인코딩** | UTF-8 |
| **타임존** | Asia/Seoul (KST) |
| **포트** | 5432 (기본값) |

### 1.2 데이터베이스 생성

```sql
-- 데이터베이스 생성
CREATE DATABASE callact_db
  WITH ENCODING 'UTF8'
  LC_COLLATE = 'ko_KR.UTF-8'
  LC_CTYPE = 'ko_KR.UTF-8'
  TEMPLATE template0;

-- pgvector 확장 설치
\c callact_db
CREATE EXTENSION IF NOT EXISTS vector;

-- UUID 확장 설치 (선택)
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

### 1.3 스키마 구성

```sql
-- 스키마 생성
CREATE SCHEMA IF NOT EXISTS public;
CREATE SCHEMA IF NOT EXISTS rag;      -- RAG 관련 테이블
CREATE SCHEMA IF NOT EXISTS logs;     -- 로그 테이블

-- 기본 스키마 설정
SET search_path TO public, rag, logs;
```

## 3. 테이블 상세 설계

### 3.1 users (사용자/상담사)

**설명**: 상담사 및 관리자 정보

```sql
CREATE TABLE users (
    -- 기본 정보
    id VARCHAR(20) PRIMARY KEY,                    -- 예: EMP-001
    name VARCHAR(50) NOT NULL,                     -- 이름
    email VARCHAR(100) UNIQUE NOT NULL,            -- 이메일
    password_hash VARCHAR(255) NOT NULL,           -- 비밀번호 해시 (bcrypt)
    
    -- 직원 정보
    team VARCHAR(20),                              -- 팀 (상담1팀, 상담2팀, 상담3팀)
    position VARCHAR(20),                          -- 직급 (사원, 대리, 과장, 차장, 부장)
    phone VARCHAR(20),                             -- 전화번호
    join_date DATE,                                -- 입사일
    
    -- 권한
    role VARCHAR(20) NOT NULL DEFAULT 'agent',     -- 역할: agent, admin, developer
    status VARCHAR(20) DEFAULT 'active',           -- 상태: active, inactive, vacation
    
    -- 성과 지표
    total_consultations INT DEFAULT 0,             -- 총 상담 건수
    fcr_rate DECIMAL(5,2),                        -- FCR 달성률 (%)
    avg_consultation_time INTERVAL,                -- 평균 상담 시간
    
    -- 메타 정보
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login_at TIMESTAMP
);

-- 인덱스
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_team ON users(team);
CREATE INDEX idx_users_status ON users(status);
```

### 3.2 consultations (상담 기록)

**설명**: 각 상담 세션의 메타 정보

```sql
CREATE TABLE consultations (
    -- 기본 정보
    id VARCHAR(30) PRIMARY KEY,                    -- 예: CS-20250105-1432
    user_id VARCHAR(20) NOT NULL,                  -- 상담사 ID (FK)
    
    -- 고객 정보
    customer_name VARCHAR(50),                     -- 고객명
    customer_phone VARCHAR(20),                    -- 고객 전화번호
    customer_card_number VARCHAR(20),              -- 카드 번호 (마스킹)
    
    -- 상담 정보
    category VARCHAR(50),                          -- 카테고리 (카드분실, 해외결제 등)
    scenario_id INT,                               -- 시나리오 ID (FK, nullable)
    
    -- 상담 결과
    status VARCHAR(20) DEFAULT 'in_progress',      -- 상태: in_progress, completed, pending
    summary TEXT,                                  -- AI 자동 요약
    memo TEXT,                                     -- 상담사 메모
    
    -- 성과 지표
    is_fcr BOOLEAN DEFAULT FALSE,                  -- FCR 달성 여부
    is_best_practice BOOLEAN DEFAULT FALSE,        -- 우수 상담 사례
    
    -- 시간 정보
    start_time TIMESTAMP NOT NULL,                 -- 상담 시작 시간
    end_time TIMESTAMP,                            -- 상담 종료 시간
    duration INTERVAL,                             -- 상담 시간 (자동 계산)
    
    -- 메타 정보
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 외래키
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (scenario_id) REFERENCES rag.scenarios(id) ON DELETE SET NULL
);

-- 인덱스
CREATE INDEX idx_consultations_user_id ON consultations(user_id);
CREATE INDEX idx_consultations_category ON consultations(category);
CREATE INDEX idx_consultations_status ON consultations(status);
CREATE INDEX idx_consultations_start_time ON consultations(start_time DESC);
CREATE INDEX idx_consultations_is_fcr ON consultations(is_fcr);

-- 트리거: duration 자동 계산
CREATE OR REPLACE FUNCTION calculate_duration()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.end_time IS NOT NULL THEN
        NEW.duration = NEW.end_time - NEW.start_time;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_calculate_duration
BEFORE INSERT OR UPDATE ON consultations
FOR EACH ROW
EXECUTE FUNCTION calculate_duration();
```

### 3.6 document_embeddings (문서 임베딩)

**설명**: pgvector 기반 벡터 검색을 위한 임베딩

```sql
CREATE TABLE rag.document_embeddings (
    -- 기본 정보
    id SERIAL PRIMARY KEY,
    document_id INT NOT NULL,                      -- 문서 ID (FK)
    
    -- 임베딩 정보
    chunk_text TEXT NOT NULL,                      -- 청크 텍스트 (512 토큰 이내)
    chunk_index INT NOT NULL,                      -- 청크 순서 (0부터 시작)
    embedding vector(1536) NOT NULL,               -- OpenAI Embedding (1536 차원)
    
    -- 메타 정보
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 외래키
    FOREIGN KEY (document_id) REFERENCES rag.documents(id) ON DELETE CASCADE
);

-- 벡터 검색 인덱스 (HNSW - Hierarchical Navigable Small World)
CREATE INDEX idx_embeddings_vector ON rag.document_embeddings 
USING hnsw (embedding vector_cosine_ops);

-- 문서 ID 인덱스
CREATE INDEX idx_embeddings_document_id ON rag.document_embeddings(document_id);

-- 벡터 유사도 검색 예시 함수
CREATE OR REPLACE FUNCTION rag.search_similar_documents(
    query_embedding vector(1536),
    top_k INT DEFAULT 5
)
RETURNS TABLE (
    document_id INT,
    chunk_text TEXT,
    similarity FLOAT
) AS $$
BEGIN
    RETURN QUERY
    SELECT 
        de.document_id,
        de.chunk_text,
        1 - (de.embedding <=> query_embedding) AS similarity
    FROM rag.document_embeddings de
    ORDER BY de.embedding <=> query_embedding
    LIMIT top_k;
END;
$$ LANGUAGE plpgsql;
```

### 3.10 notices (공지사항)

**설명**: 상담사용 공지사항

```sql
CREATE TABLE notices (
    -- 기본 정보
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,                   -- 제목
    content TEXT NOT NULL,                         -- 내용
    
    -- 분류
    tag VARCHAR(20),                               -- 태그 (긴급, 이벤트, 시스템 등)
    
    -- 작성자
    author VARCHAR(50),                            -- 작성자
    author_id VARCHAR(20),                         -- 작성자 ID (FK, nullable)
    
    -- 상태
    is_pinned BOOLEAN DEFAULT FALSE,               -- 상단 고정

    FOREIGN KEY (author_id) REFERENCES users(id) ON DELETE SET NULL
```

## 4. pgvector 벡터 검색

### 4.1 벡터 검색 설정

#### 4.1.1 pgvector 확장 설치

```sql
-- pgvector 확장 설치 (PostgreSQL 서버에서 실행)

```

#### 4.1.2 벡터 차원 설정

```sql
-- OpenAI text-embedding-ada-002: 1536 차원
-- OpenAI text-embedding-3-small: 1536 차원
-- OpenAI text-embedding-3-large: 3072 차원

-- 현재 사용: 1536 차원
CREATE TABLE rag.document_embeddings (
    embedding vector(1536) NOT NULL
);
```

### 4.2 벡터 유사도 연산자

| 연산자 | 의미 | 설명 |
|--------|------|------|
| `<->` | L2 Distance | 유클리드 거리 (작을수록 유사) |
| `<#>` | Inner Product | 내적 (클수록 유사) |
| `<=>` | Cosine Distance | 코사인 거리 (작을수록 유사) |

**권장**: `<=>` (Cosine Distance) 사용

### 4.3 벡터 검색 쿼리

#### 4.3.1 기본 검색

```sql
-- 키워드 "카드분실"의 임베딩과 유사한 문서 검색
SELECT 
    d.id,
    d.title,
    de.chunk_text,
    1 - (de.embedding <=> $1::vector) AS similarity
FROM rag.document_embeddings de
JOIN rag.documents d ON de.document_id = d.id
WHERE d.is_active = TRUE
ORDER BY de.embedding <=> $1::vector
LIMIT 5;

-- $1: 키워드 임베딩 벡터 (1536차원)
```

#### 4.3.2 카테고리 필터링

```sql
-- 특정 카테고리 내에서만 검색
SELECT 
    d.id,
    d.title,
    de.chunk_text,
    1 - (de.embedding <=> $1::vector) AS similarity
FROM rag.document_embeddings de
JOIN rag.documents d ON de.document_id = d.id
WHERE d.is_active = TRUE
  AND d.category = '약관'
ORDER BY de.embedding <=> $1::vector
LIMIT 5;
```

#### 4.3.3 임계값 필터링

```sql
-- 유사도 0.8 이상만 반환
SELECT 
    d.id,
    d.title,
    de.chunk_text,
    1 - (de.embedding <=> $1::vector) AS similarity
FROM rag.document_embeddings de
JOIN rag.documents d ON de.document_id = d.id
WHERE d.is_active = TRUE
  AND 1 - (de.embedding <=> $1::vector) >= 0.8
ORDER BY de.embedding <=> $1::vector
LIMIT 5;
```

### 4.4 벡터 인덱스 전략

#### 4.4.1 HNSW 인덱스

```sql
-- HNSW (Hierarchical Navigable Small World) 인덱스
-- 가장 빠르고 정확함 (권장)
CREATE INDEX idx_embeddings_hnsw ON rag.document_embeddings 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- m: 최대 연결 수 (기본: 16, 높을수록 정확하지만 느림)
-- ef_construction: 인덱스 구축 시 탐색 깊이 (기본: 64)
```

#### 4.4.2 IVFFlat 인덱스 (대용량 데이터)

```sql
-- IVFFlat (Inverted File with Flat compression)
-- 대용량 데이터에 적합 (100만 건 이상)
CREATE INDEX idx_embeddings_ivfflat ON rag.document_embeddings 
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);

-- lists: 클러스터 개수 (데이터 수의 제곱근 권장)
-- 예: 10,000건 → lists = 100
```
