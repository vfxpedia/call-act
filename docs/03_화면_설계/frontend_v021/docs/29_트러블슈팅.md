## 1. 설치 및 실행 문제

### 🔴 문제: `npm install` 실패

**증상**:
```bash
npm ERR! code ERESOLVE
npm ERR! ERESOLVE unable to resolve dependency tree
```

**원인**:
- Node.js 버전이 낮음
- npm 버전이 낮음
- 의존성 충돌

**해결 방법**:

```bash
# 1. Node.js 버전 확인 (18+ 필요)
node -v

# 2. npm 업데이트
npm install -g npm@latest

# 3. 캐시 클리어 후 재설치
npm cache clean --force
rm -rf node_modules package-lock.json
npm install

# 4. legacy-peer-deps 옵션 사용
npm install --legacy-peer-deps

# 5. Yarn 사용 (npm이 안 될 때)
npm install -g yarn
yarn install
```

```bash
src/app/pages/DashboardPage.tsx:45:7 - error TS2322:
```

- Props 인터페이스 오류

```typescript
// ❌ 잘못된 예
const handleChange = (value: string) => {

const handleChange = (value: string) => {

interface CardProps {
  count: number;  // string → number
}
```

### 🔴 문제: `Module not found` 에러

**증상**:
```bash
Module not found: Error: Can't resolve '@/app/components/Button'
```

**원인**:
- Import 경로 오류
- 파일이 존재하지 않음
- alias 설정 누락

**해결 방법**:

```typescript

// ✅ 올바른 경로
import { Button } from '@/app/components/ui/button';

// 2. 파일 존재 확인
// src/app/components/ui/button.tsx 파일이 있는지 확인

// 3. tsconfig.json의 paths 확인
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}

// 4. vite.config.ts의 resolve.alias 확인
import path from 'path';

export default defineConfig({
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src')
    }
  }
});
```

```typescript
// ❌ 잘못된 예
const [employees, setEmployees] = useState();  // undefined

return (
  <div>
    {employees?.map(emp => <div key={emp.id}>{emp.name}</div>)}

// ✅ 올바른 예 3: Early Return
```

### 🔴 문제: `Maximum update depth exceeded`

**증상**:
```bash
Uncaught Error: Maximum update depth exceeded.
This can happen when a component repeatedly calls setState inside componentWillUpdate or componentDidUpdate.
```

**원인**:
- useEffect 무한 루프
- 의존성 배열 누락
- setState를 렌더링 중에 호출

**해결 방법**:

```typescript
// ❌ 잘못된 예 1: 의존성 배열 없음
useEffect(() => {
  setCount(count + 1);  // 무한 루프!
});

// ✅ 올바른 예 1: 의존성 배열 추가
useEffect(() => {
  setCount(count + 1);
}, []);  // 빈 배열: 마운트 시 한 번만

// ❌ 잘못된 예 2: 렌더링 중 setState
const Component = () => {
  const [count, setCount] = useState(0);
  setCount(count + 1);  // 무한 루프!
  return <div>{count}</div>;
};

// ✅ 올바른 예 2: useEffect 내부에서 호출
const Component = () => {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    setCount(count + 1);
  }, []);
  
  return <div>{count}</div>;
};

// ❌ 잘못된 예 3: 객체/배열 의존성
useEffect(() => {
  fetchData(filters);
}, [filters]);  // filters가 매번 새 객체 → 무한 루프

// ✅ 올바른 예 3: 원시값 의존성
useEffect(() => {
  fetchData(filters);
}, [filters.category, filters.status]);  // 원시값만 의존
```

### 🔴 문제: LocalStorage 데이터가 사라짐

**증상**:
- 페이지 새로고침하면 데이터 사라짐
- 로그인 상태 유지 안 됨

- LocalStorage에 저장 안 함
- 시크릿 모드 사용 중
- 브라우저 설정에서 쿠키/스토리지 차단

**해결 방법**:

```typescript
// 1. 저장 확인
const handleLogin = (user: User) => {
  // ✅ LocalStorage에 저장
  localStorage.setItem('user', JSON.stringify(user));
  
  // 저장 확인
  console.log('Saved:', localStorage.getItem('user'));
};

// 2. 읽기 확인
const getUser = () => {
  const savedUser = localStorage.getItem('user');
  
  if (!savedUser) {
    console.log('No user in LocalStorage');
    return null;
  }
  
  try {
    return JSON.parse(savedUser);
  } catch (e) {
    console.error('Failed to parse user', e);
    return null;
  }
};

// 3. 브라우저 확인
// Chrome DevTools > Application > Storage > Local Storage
// - 데이터가 저장되어 있는지 확인
// - 시크릿 모드가 아닌지 확인
```

### 🔴 문제: 애니메이션이 끊김 (Janky Animation)

**증상**:
- 칸반보드 슬라이딩이 부드럽지 않음
- FPS가 낮음 (< 30 FPS)

**원인**:
- layout 속성 애니메이션 (width, height, top, left)
- transform 대신 position 사용
- 하드웨어 가속 미지원

**해결 방법**:

```tsx
// ❌ 잘못된 예: layout 속성 (CPU 연산)
<motion.div
  initial={{ left: '100%' }}
  animate={{ left: 0 }}
>

// ✅ 올바른 예: transform 속성 (GPU 가속)
<motion.div
  initial={{ x: '100%' }}
  animate={{ x: 0 }}
  transition={{ duration: 0.5, ease: 'easeOut' }}
>

// will-change 추가 (성능 힌트)
<motion.div
  style={{ willChange: 'transform' }}
  initial={{ x: '100%' }}
  animate={{ x: 0 }}
>
```

### 🔴 문제: Step 자동 전환이 안 됨

**증상**:
- STT 메시지가 모두 나왔는데 Step 1에 머물러 있음

**해결 방법**:

```typescript
// 1. 현재 Step 키워드 확인
console.log('Step 키워드:', currentStep.keywords.map(k => k.text));

// 2. 태깅된 키워드 확인
console.log('태깅된 키워드:', keywords.map(k => k.text));

// 3. 조건 체크
const stepKeywords = currentStep.keywords.map(k => k.text);
const taggedKeywords = keywords.map(k => k.text);
const allTagged = stepKeywords.every(k => taggedKeywords.includes(k));
```

### 🔴 문제: 메모리 누수 (Memory Leak)

**증상**:
- 시간이 지날수록 페이지가 느려짐
- 브라우저 메모리 사용량 증가
- 탭을 닫아도 메모리 해제 안 됨

**원인**:
- useEffect cleanup 누락
- setInterval/setTimeout cleanup 누락
- 이벤트 리스너 제거 안 함

**해결 방법**:

```typescript
// ❌ 잘못된 예: cleanup 없음
useEffect(() => {
  const interval = setInterval(() => {
    updateTime();
  }, 1000);
  // cleanup 없음!
}, []);

// ✅ 올바른 예: cleanup 있음
useEffect(() => {
  const interval = setInterval(() => {
    updateTime();
  }, 1000);
  
  return () => clearInterval(interval);  // Cleanup!
}, []);

// ✅ 이벤트 리스너 cleanup
useEffect(() => {
  const handleResize = () => { /* ... */ };
  window.addEventListener('resize', handleResize);
  
  return () => window.removeEventListener('resize', handleResize);
}, []);
```

**메모리 프로파일링**:
```bash
# Chrome DevTools
# 1. F12 > Memory 탭
# 2. "Take heap snapshot" 클릭
# 3. 페이지 사용
# 4. 다시 "Take heap snapshot" 클릭
# 5. 두 스냅샷 비교 (Comparison)
```

### 🔴 문제: 배포 후 404 Not Found

**증상**:
- 루트 경로(`/`)는 정상
- 다른 경로(`/dashboard`, `/login`)는 404

**원인**:
- SPA 라우팅 설정 누락
- Vercel rewrites 설정 누락

**해결 방법**:

```json
// vercel.json 파일 생성 (프로젝트 루트)
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/" }
  ]
}

// Git commit 후 push
git add vercel.json
git commit -m "chore: Vercel SPA rewrites 설정"
git push origin main

// Vercel 자동 재배포
```

```typescript
console.log(import.meta.env.VITE_API_URL);  // undefined
```

```bash
# Vercel 대시보드 > Settings > Environment Variables
# Name: VITE_API_URL
# Value: https://api.example.com
# Environment: Production

# 3. 재배포
# Vercel 대시보드 > Deployments > Redeploy

console.log('API URL:', import.meta.env.VITE_API_URL);
```
