## 원인 분석

### 1. 풀 크기 부족 (주요 원인)

**문제점**:
- `MAIN_CATEGORY_POOL_SIZES`가 **50명 기준**으로 설정되어 있었음
- 실제 상담사는 **70명**
- "결제/승인" 카테고리가 **2,327건**으로 예상(1,559건)보다 훨씬 많음
- "결제/승인" 풀에 **10명만** 배정 → 평균 **232.7건/명**

**영향**:
- 상위 상담사들이 "결제/승인" 풀에 포함되면 매우 많은 상담을 받게 됨
- 예: EMP-001이 "결제/승인" 풀에 포함되면 2,327 / 10 = 약 232건만 받아도 이미 평균의 2.5배

### 2. 상담사 중복 배정 (중요 원인)

**문제점**:
- 한 상담사가 **여러 카테고리 풀에 중복 포함**될 수 있음
- 예: EMP-001이 "결제/승인" 풀(10명 중 1명) + "기타" 풀(70명 중 1명) + "이용내역" 풀(7명 중 1명)에 모두 포함
- 결과: EMP-001이 여러 카테고리에서 상담을 받아 **총 상담 건수가 누적됨**

**계산 예시**:
```
EMP-001이 포함된 풀:
  - 결제/승인 (10명): 2,327 / 10 = 232건
  - 기타 (70명): 1,474 / 70 = 21건
  - 이용내역 (7명): 919 / 7 = 131건
  - 한도 (6명): 576 / 6 = 96건
  총합: 약 480건 (실제 830건은 랜덤 10% 포함)
```

### 3. "기타" 카테고리 순차 배분 문제

**문제점**:
- "기타" 카테고리는 **모든 상담사(70명)**가 풀에 포함
- 순차 배분(`pool_index = counter % len(agent_pool)`)이므로 **처음 몇 명이 더 많이** 받을 수 있음
- 1,474건을 70명이 나눠 받으면 평균 21건이지만, 순차 배분으로 인해 불균등 발생

### 4. 실제 상담 건수와 예상 불일치

**문제점**:
- 예상: "결제/승인" 1,559건 → 실제: **2,327건** (약 1.5배)
- 예상: "기타" XXX건 → 실제: **1,474건**
- 풀 크기가 예상 건수 기준으로 설정되어 있어 실제와 불일치

## 해결 방안

### 방안 1: 풀 크기 재조정 (즉시 적용 가능) ⭐

**목표**: 실제 상담 건수에 맞춰 풀 크기 조정

**수정 내용**:
```python
# 대분류별 담당 풀 크기 설정 (70명 기준)
# 실제 상담 건수에 맞춰 조정 (2026-01-13 기준: 총 6,533건)
MAIN_CATEGORY_POOL_SIZES = {
    "분실/도난": 7,      # ~398건 (398/70 ≈ 5.7건/명, 7명이면 약 57건/명)
    "한도": 8,           # ~576건 (576/70 ≈ 8.2건/명, 8명이면 약 72건/명)
    "결제/승인": 25,     # ~2,327건 (2,327/70 ≈ 33.2건/명, 25명이면 약 93건/명) - 최대
    "이용내역": 12,      # ~919건 (919/70 ≈ 13.1건/명, 12명이면 약 77건/명)
    "수수료/연체": 4,    # ~248건 (248/70 ≈ 3.5건/명, 4명이면 약 62건/명)
    "포인트/혜택": 5,    # ~339건 (339/70 ≈ 4.8건/명, 5명이면 약 68건/명)
    "정부지원": 4,       # ~252건 (252/70 ≈ 3.6건/명, 4명이면 약 63건/명)
    "기타": None,        # 순차 분배 (모든 상담사, ~1,474건)
}
```

**예상 효과**:
- "결제/승인" 풀: 10명 → 25명 → 평균 93건/명 (기존 232건 대비 약 60% 감소)
- 전체적으로 더 균등한 배분 기대

**단점**:
- 여전히 중복 배정 문제는 해결되지 않음
- 상담사가 여러 풀에 포함되면 누적 효과 발생

### 방안 2: 상담사별 총 상담 건수 제한 (권장) ⭐⭐

**목표**: 상담사별 총 상담 건수를 추적하고 제한을 두어 균등 배분

**구현 방법**:
```python
# 상담사별 현재 상담 건수 추적
agent_consultation_counts = {}  # {agent_id: count}

for row in consultations_data:
    # ... 기존 로직 ...
    
    # 상담사 배분 (하이브리드: 90% 순차 + 10% 랜덤)
    agent_pool = agent_pools_cache[main_category]
    
    # 상담사별 건수 초기화
    for agent_id in agent_pool:
        if agent_id not in agent_consultation_counts:
            agent_consultation_counts[agent_id] = 0
    
    # 최소 건수를 가진 상담사 우선 선택
    if random.random() < 0.1:  # 10% 랜덤
        # 랜덤이지만 최소 건수 상담사 우선
        min_count = min(agent_consultation_counts[aid] for aid in agent_pool)
        candidates = [aid for aid in agent_pool 
                     if agent_consultation_counts[aid] == min_count]
        agent_id = random.choice(candidates)
    else:  # 90% 순차
        # 최소 건수를 가진 상담사 순차 선택
        min_count = min(agent_consultation_counts[aid] for aid in agent_pool)
        candidates = [aid for aid in agent_pool 
                     if agent_consultation_counts[aid] == min_count]
        pool_index = category_counters[main_category] % len(candidates)
        agent_id = candidates[pool_index]
    
    # 건수 증가
    agent_consultation_counts[agent_id] += 1
```

**예상 효과**:
- 상담사별 총 상담 건수가 균등하게 유지됨
- 변동계수 2.11 → 0.3 이하로 개선 기대

**단점**:
- 구현 복잡도 증가
- 성능 약간 저하 (최소값 계산)

---

### 방안 3: 카테고리별 상담사 완전 분리 (극단적)

**목표**: 각 카테고리별로 상담사를 완전히 분리하여 중복 배정 방지

**구현 방법**:
- 각 카테고리 풀에 서로 다른 상담사만 배정
- 예: "결제/승인" 풀에 EMP-001~EMP-025, "기타" 풀에 EMP-026~EMP-070

**예상 효과**:
- 중복 배정 문제 완전 해결
- 각 상담사가 특정 카테고리만 담당

**단점**:
- 상담사 전문성 제한 (다양한 카테고리 경험 부족)
- 유연성 감소
- 구현 복잡도 높음

## 참고 사항

### 변동계수 (Coefficient of Variation)

- **0.1~0.3**: 매우 균등
- **0.3~0.5**: 균등
- **0.5~1.0**: 약간 불균등 (허용 가능)
- **1.0 이상**: 불균등 (개선 필요)

### 현재 상황

- 변동계수 **2.11**은 매우 높은 수치
- 상위 5명이 하위 5명보다 **약 40배** 많은 상담을 받음
- 즉시 개선 필요
