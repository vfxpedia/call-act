# 테디카드 데이터 DB 적재 실행 가이드

## 작성일: 2026-01-11
## 목적: 테디카드 전처리 데이터를 PostgreSQL 데이터베이스에 적재

---

## 개요

이 가이드는 `data-preprocessing/data/teddycard/` 폴더에 있는 전처리 완료 데이터(임베딩 포함)를 PostgreSQL 데이터베이스에 적재하는 과정을 안내합니다.

### 작업 흐름

```
data-preprocessing/data/teddycard/ (서브모듈, 팀 레포)
  ↓
DB 적재 스크립트 (backend_dev/app/db/scripts/)
  ↓
PostgreSQL 데이터베이스
  ↓
검증
```

## Step 1: DB 적재 스크립트 작성

### 1.1 스크립트 위치

`backend_dev/app/db/scripts/03_load_teddycard_to_db.py`

### 1.2 스크립트 기본 구조

스크립트는 다음 작업을 수행해야 합니다:

1. JSON 파일 읽기 (`data-preprocessing/data/teddycard/`)
2. 데이터베이스 연결
3. 테이블별 데이터 삽입:
   - `card_products` 테이블
   - `service_guide_documents` 테이블
   - `notices` 테이블
4. Foreign Key 관계 처리
5. 에러 처리 및 로깅

**참고**: 하나카드 데이터 적재 스크립트(`03_load_hana_to_db.py`)를 참고하여 작성할 수 있습니다.

### 1.3 주요 고려사항

**1. 경로 설정**:
```python
# 프로젝트 루트 기준
BASE_DIR = Path(__file__).parent.parent.parent.parent.parent
DATA_DIR = BASE_DIR / "data-preprocessing" / "data" / "teddycard"
```

**2. 임베딩 벡터 변환**:
```python
# JSON의 embedding 리스트를 PostgreSQL vector 타입으로 변환
import psycopg2.extras
from pgvector.psycopg2 import register_vector

# 연결 후
register_vector(conn)
```

**3. 배치 삽입**:
- 대량 데이터는 `executemany` 사용
- 트랜잭션 단위로 커밋

**4. 에러 처리**:
- 개별 레코드 에러 시에도 계속 진행
- 에러 로그 기록
- 중복 키 에러 처리 (`ON CONFLICT`)

### 1.4 스크립트 작성 확인

스크립트 작성 후 다음을 확인:

- [ ] JSON 파일 경로가 올바른지 확인
- [ ] DB 연결 정보가 올바른지 확인
- [ ] 테이블 구조와 데이터 매핑이 올바른지 확인

## Step 3: 데이터 검증

### 3.1 레코드 수 확인

**DBeaver에서 실행**:
```sql
-- card_products 테이블 확인
SELECT COUNT(*) as total_count FROM card_products;

-- service_guide_documents 테이블 확인
SELECT COUNT(*) as total_count FROM service_guide_documents;

-- notices 테이블 확인
SELECT COUNT(*) as total_count FROM notices;

-- 임베딩이 있는 문서 수 확인
SELECT 
    COUNT(*) as total_documents,
    COUNT(embedding) as documents_with_embedding
FROM service_guide_documents;
```

**예상 결과**:
- card_products: 약 150건
- service_guide_documents: 약 1,200건 (임베딩 포함)
- notices: 약 50건
- documents_with_embedding: service_guide_documents의 전체 레코드 수와 동일해야 함

### 3.2 데이터 샘플 확인

```sql
-- card_products 샘플
SELECT id, name, card_type, brand, annual_fee_domestic 
FROM card_products 
LIMIT 5;

-- service_guide_documents 샘플
SELECT id, title, category, document_source, 
       CASE WHEN embedding IS NOT NULL THEN 'Yes' ELSE 'No' END as has_embedding
FROM service_guide_documents 
LIMIT 5;

-- notices 샘플
SELECT id, title, category, priority, start_date, end_date
FROM notices 
LIMIT 5;
```

### 3.3 임베딩 벡터 검증

```sql
-- 임베딩 벡터 차원 확인 (1536이어야 함)
SELECT 
    id,
    array_length(embedding::float[], 1) as embedding_dimension
FROM service_guide_documents
WHERE embedding IS NOT NULL
LIMIT 5;
```

**예상 결과**: 모든 embedding_dimension이 1536이어야 합니다.

### 3.4 Foreign Key 관계 확인

```sql
-- notices.created_by가 employees 테이블을 참조하는 경우
SELECT 
    n.id,
    n.title,
    n.created_by,
    e.name as employee_name
FROM notices n
LEFT JOIN employees e ON n.created_by = e.id
WHERE n.created_by IS NOT NULL
LIMIT 5;
```

## Step 4: 에러 처리

### 4.1 일반적인 에러

**에러 1: 연결 실패**
```
psycopg2.OperationalError: could not connect to server
```

**해결**:
1. Docker 컨테이너 실행 확인: `docker ps`
2. DB 연결 정보 확인 (`.env` 파일)
3. 포트 충돌 확인: `netstat -an | findstr 5432`

**에러 2: 테이블 없음**
```
psycopg2.errors.UndefinedTable: relation "card_products" does not exist
```

**해결**:
1. DB 스키마 확인: `02_setup_tedicard_tables.sql` 실행
2. 테이블 목록 확인: DBeaver에서 `\dt` 실행

**에러 3: Enum 타입 에러**
```
psycopg2.errors.InvalidTextRepresentation: invalid input value for enum
```

**해결**:
1. Enum 타입 값 확인: JSON 데이터의 값이 DB Enum과 일치하는지 확인
2. Enum 타입 정의 확인: `02_setup_tedicard_tables.sql` 확인

**에러 4: 임베딩 벡터 차원 불일치**
```
pgvector.exceptions.DimensionMismatch: vector must have 1536 dimensions
```

**해결**:
1. JSON 파일의 embedding 길이 확인
2. 임베딩 모델 확인 (text-embedding-3-small은 1536차원)

### 4.2 부분 실패 처리

일부 레코드만 실패한 경우:

1. **에러 로그 확인**: 스크립트에서 기록한 에러 로그 확인
2. **실패한 레코드 식별**: 에러 로그에서 ID 확인
3. **재실행 또는 수동 삽입**: 필요시 개별 레코드 재삽입
