이 가이드는 테스트 데이터 적재가 성공한 후, 전체 데이터를 DB에 적재하는 방법을 안내합니다.

**⚠️ 중요**: 
- 이 가이드는 **담당자(DB 적재 담당자)용**입니다
- 팀원은 이 과정을 진행할 필요가 없습니다 (담당자가 이미 완료)
- 테스트 데이터 적재가 성공한 경우에만 진행하세요

## 2. 전체 데이터 적재

### 2.1 .env 파일 확인 및 생성

**⚠️ 중요**: Anaconda Prompt는 `cmd.exe`를 사용하므로 환경 변수 설정이 복잡합니다.
**가장 간단한 방법**: `.env` 파일을 사용하세요.

**`.env` 파일 위치**:
- **팀원**: 프로젝트 루트에 `.env` 파일 생성 (`call-act/.env`)
- **개인 개발**: `backend_dev/db_loading/.env` 파일 생성 가능 (우선 사용, 개인 파일)
- 스크립트는 다음 순서로 `.env` 파일을 읽습니다:
  1. `backend_dev/db_loading/.env` (있으면 우선 사용, 개인 파일)
  2. 프로젝트 루트 `.env` (팀원 공용)

**⚠️ 참고**: 
- `backend_dev/db_loading/.env`는 개인 폴더이므로 팀원과 공유하지 않습니다
- 팀원들은 프로젝트 루트 `.env`만 사용합니다
- `DB_HOST_IP`는 사용하지 않습니다 (팀원의 Tailscale IP는 무시)

**`.env` 파일 생성** (프로젝트 루트):

```bash
# Anaconda Prompt에서 (프로젝트 루트)
cd C:\Users\AI-WS01\projects\call-act

# backend/.env.example 참고하여 .env 파일 생성
# 또는 수동으로 생성
```

**`.env` 파일 내용** (프로젝트 루트 `.env`):

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=callact_admin
DB_PASSWORD=callact_pwd1
DB_NAME=callact_db

# OpenAI (임베딩 생성 시 필요, 이미 완료했다면 생략 가능)
OPENAI_API_KEY=your_key_here
```

### 2.3 전체 데이터 적재 실행

**⚠️ 중요**: 
- `.env` 파일이 있으면 환경 변수 설정 불필요
- 전체 데이터 적재는 **10-20분** 소요됩니다
- 중간에 중단되면 재시작 가능합니다 (ON CONFLICT DO UPDATE 사용)

```bash
# .env 파일이 있으면 바로 실행 가능
python load_hana_to_db.py
```

**환경 변수 설정이 필요한 경우** (`.env` 파일이 없을 때, 권장하지 않음):

```bash
# Anaconda Prompt (cmd.exe)에서
set DB_USER=callact_admin
set DB_PASSWORD=callact_pwd1
set DB_NAME=callact_db
set DB_HOST=localhost
set DB_PORT=5432

python load_hana_to_db.py
```

**주의**: 
- `set` 명령어는 공백 없이 사용 (`set 변수명=값`)
- `.env` 파일 사용을 권장합니다


## 4. 중단 및 재시작

### 4.1 중단 시나리오

**중단 원인**:
- 네트워크 오류
- 전원 차단
- Ctrl+C로 수동 중단
- 메모리 부족

**⚠️ 안전한 중단**:
- 스크립트는 `ON CONFLICT DO UPDATE`를 사용하므로 중단 후 재시작 가능
- 이미 적재된 데이터는 업데이트되므로 중복 걱정 불필요

### 4.2 재시작 방법

**중단된 위치에서 재시작**:
```powershell
# 동일한 환경 변수 설정 후 재실행
conda activate final_env
cd C:\Users\[사용자명]\projects\call-act\scripts\db_loading

$env:DB_USER="callact_admin"
$env:DB_PASSWORD="callact_pwd1"
$env:DB_NAME="callact_db"
$env:DB_HOST="localhost"
$env:DB_PORT="5432"

# 전체 데이터 재적재 (중복은 자동으로 업데이트됨)
python load_hana_to_db.py
```

**재시작 시**:
- 이미 적재된 데이터는 `ON CONFLICT DO UPDATE`로 업데이트됨
- 새로운 데이터만 추가됨
- 전체 시간은 동일하게 소요됨

### 4.3 부분 재시작

**특정 테이블만 재적재**:
```powershell
# consultations만 재적재
python load_hana_to_db.py --skip-documents

# consultation_documents만 재적재
python load_hana_to_db.py --skip-consultations
```

## 6. 문제 해결

### 6.1 데이터 개수 불일치

**증상**: Consultations와 Documents 개수가 다름

**확인 사항**:
```sql
-- 고아 문서 확인
SELECT COUNT(*) 
FROM consultation_documents cd
LEFT JOIN consultations c ON cd.consultation_id = c.id
WHERE c.id IS NULL;
```

**해결**: `--skip-consultations` 옵션 없이 다시 실행

### 6.2 임베딩 누락

**증상**: Documents with Embedding이 전체보다 적음

**확인 사항**:
```sql
SELECT COUNT(*) 
FROM consultation_documents 
WHERE embedding IS NULL;
```

**해결**: 임베딩 파일 확인 후 재적재

### 6.3 성능 문제

**증상**: 적재 속도가 너무 느림 (< 5건/초)

**해결**:
1. Docker 컨테이너 리소스 확인
2. 디스크 I/O 확인
3. 배치 크기 조정 (환경 변수 `DB_LOAD_BATCH_SIZE`)
