```powershell

conda activate final_env

# 2. 작업 디렉토리 이동
cd C:\Users\AI-WS01\projects\call-act\scripts\db_loading

# 3. 환경 변수 설정 (PowerShell)

$env:DB_PASSWORD="callact_pwd1"

$env:DB_HOST="localhost"
```

## DBeaver에서 `call_act_db` 생성 원인 분석

### 원인 추정

1. **이전 Docker 설정**:
   - 초기 `docker-compose.yml`에서 `POSTGRES_DB: call_act_db`로 설정되어 있었을 가능성
   - Docker 컨테이너가 해당 이름으로 생성됨

2. **문서 참고**:
   - 이전 문서에 `call_act_db` 예시가 많았음
   - 문서를 보고 수동으로 생성했을 가능성

3. **DBeaver 자동 감지**:
   - 연결 시 PostgreSQL의 데이터베이스 목록을 자동 스캔
   - `call_act_db`가 존재하면 목록에 표시

### 해결 방법

**이미 해결됨**:
- ✅ Docker 컨테이너 재생성 (`callact_db`로)
- ✅ 모든 문서 수정 완료
- ✅ 코드 파일 수정 완료

**DBeaver 정리**:
- 기존 `call_act_db` 연결 삭제
- 새 연결 생성 (`callact_db`)

**확인 방법**:
```powershell
# Docker 컨테이너 내부에서 확인
docker exec callact_db_container psql -U callact_admin -d postgres -l

# 출력에서 callact_db만 보이면 정상
# call_act_db가 보이면 재생성 필요
```

## 보안 처리

### ✅ 완료된 보안 처리

1. **`.env.example` 파일 생성**:
   - 실제 비밀번호 없이 템플릿만 제공
   - Git에 커밋됨

2. **`.env` 파일 Git 제외**:
   - `backend/.gitignore`에 `.env` 추가
   - 실제 비밀번호는 `.env`에 저장 (Git에 커밋되지 않음)

3. **문서에서 비밀번호 제거**:
   - `backend/docs/SETUP.md`에서 비밀번호 제거
   - `.env.example` 참조하도록 수정

### 팀원 공유 시

**비밀번호는 안전한 방법으로 공유**:
- 채팅 앱 1:1 메시지
- 비밀번호 관리 도구 공유
- 문서에는 템플릿만 제공

**로컬 개발 vs 팀 Docker 서버**:
- 로컬: `localhost` 사용
- 팀 Docker 서버: 팀장 IP 주소 사용 (`.env`에서 `DB_HOST` 변경)
