## 1. 환경 설정 오류

### 1.1 `conda activate final_env` 작동 안 함

**증상**:
```
PowerShell에서:
conda activate final_env
# 아무 반응 없음 또는 에러 발생
```

**원인**: PowerShell에서 conda 초기화가 안 되어 있음

**해결 방법**:

#### 방법 1: Anaconda Prompt 사용 (권장) ⭐

1. Windows 검색에서 "Anaconda Prompt" 실행
2. `conda activate final_env` 실행
3. 모든 작업을 Anaconda Prompt에서 진행

#### 방법 2: conda init 실행

```powershell
# PowerShell에서 실행
conda init powershell

# PowerShell 재시작 (또는 새 터미널 열기)
conda activate final_env
```

#### 방법 3: 절대 경로 사용

```powershell
# PowerShell에서 직접 Python 실행
C:\Users\[사용자명]\anaconda3\envs\final_env\python.exe 스크립트경로
```

#### 방법 4: conda run 사용

```powershell
conda run -n final_env python 스크립트경로
```

---

### 1.2 Python 버전이 3.13.x로 나옴

**증상**:
```powershell
python --version
# 출력: Python 3.13.9 (base 환경)
```

**원인**: `final_env` 환경이 활성화되지 않음

**확인**:
```powershell
conda env list
# * 표시가 base에 있으면 final_env가 비활성화 상태
```

**해결**:
```powershell
# Anaconda Prompt 사용 권장
conda activate final_env
python --version
# 출력: Python 3.11.14 (정상)

# 또는 절대 경로 사용
C:\Users\[사용자명]\anaconda3\envs\final_env\python.exe --version
```

---

### 1.3 `ModuleNotFoundError: psycopg2`

**증상**:
```
ModuleNotFoundError: No module named 'psycopg2'
```

**원인**: 필요한 패키지가 설치되지 않음

**해결**:
```powershell
# final_env 환경 활성화
conda activate final_env

# 패키지 설치
pip install -r backend/requirements.txt

# 설치 확인
pip list | Select-String "psycopg2"
# psycopg2-binary가 보이면 정상
```

---

### 1.4 `AttributeError: module 'psycopg2' has no attribute 'connection'`

**증상**:
```
AttributeError: module 'psycopg2' has no attribute 'connection'
```

**원인**: 타입 힌팅 오류 (코드 문제)

**해결**: 최신 코드가 반영되었는지 확인

**확인**:
```python
# backend/scripts/load_hana_to_db.py 파일 확인
# 다음 import가 있어야 함:
from psycopg2.extensions import connection as psycopg2_connection
```

**이미 해결됨**: 최신 코드에 반영되어 있음

## 2. Docker 관련 오류

### 2.1 `docker ps` 결과에 `callact_db_container` 없음

**증상**:
```powershell
docker ps
# callact_db_container가 보이지 않음
```

**원인**: Docker 컨테이너가 실행되지 않음

**해결**:
```powershell
# Docker Desktop 실행 확인
# 시스템 트레이에서 Docker 아이콘이 녹색이어야 함

# 컨테이너 실행
cd C:\Users\[사용자명]\projects\call-act\backend
docker-compose up -d

# 실행 확인
docker ps
# callact_db_container가 "healthy" 상태로 보이면 정상
```

---

### 2.2 컨테이너가 "unhealthy" 상태

**증상**:
```powershell
docker ps
# callact_db_container가 "unhealthy" 상태
```

**원인**: PostgreSQL이 제대로 시작되지 않음

**해결**:
```powershell
# 컨테이너 로그 확인
docker logs callact_db_container

# 컨테이너 재시작
docker-compose restart

# 또는 완전히 재생성
docker-compose down
docker-compose up -d

# 몇 초 후 확인
docker ps
# "healthy" 상태가 되면 정상
```

---

### 2.3 포트 5432가 이미 사용 중

**증상**:
```
Error: bind: address already in use
```

**원인**: 다른 PostgreSQL 인스턴스가 실행 중

**해결**:
```powershell
# 포트 사용 확인
netstat -ano | findstr :5432

# 해당 프로세스 종료 (PID 확인 후)
taskkill /PID [PID번호] /F

# 또는 docker-compose.yml에서 포트 변경
# ports:
#   - "5433:5432"  # 5433으로 변경
```

## 3. DB 연결 오류

### 3.1 `FATAL: password authentication failed for user "postgres"`

**증상**:
```
psycopg2.OperationalError: FATAL: password authentication failed for user "postgres"
```

**원인**: 
1. 환경 변수가 설정되지 않음
2. 잘못된 사용자 이름 사용 (`postgres` 대신 `callact_admin` 사용해야 함)

**해결**:
```powershell
# 환경 변수 설정 확인
$env:DB_USER
# 출력: callact_admin 이어야 함

# 환경 변수 설정
$env:DB_USER="callact_admin"
$env:DB_PASSWORD="callact_pwd1"
$env:DB_NAME="callact_db"
$env:DB_HOST="localhost"
$env:DB_PORT="5432"

# 다시 실행
python setup_db.py
```

---

### 3.2 `FATAL: database "callact_db" does not exist`

**증상**:
```
psycopg2.OperationalError: FATAL: database "callact_db" does not exist
```

**원인**: 데이터베이스가 아직 생성되지 않음

**해결**:
```powershell
# 컨테이너 내부에서 데이터베이스 생성
docker exec callact_db_container psql -U callact_admin -d postgres -c "CREATE DATABASE callact_db;"

# 생성 확인
docker exec callact_db_container psql -U callact_admin -l
# callact_db가 목록에 보이면 정상

# 다시 실행
python setup_db.py
```

**또는**: docker-compose.yml이 올바르게 설정되었는지 확인:
```yaml
POSTGRES_DB: callact_db  # call_act_db가 아님!
```

---

### 3.3 `FATAL: database "call_act_db" does not exist` (잘못된 이름)

**증상**: 
- DBeaver에서 `call_act_db`로 연결 시도
- 에러 발생

**원인**: 데이터베이스 이름이 `callact_db`인데 `call_act_db`로 연결 시도

**해결**:
1. **DBeaver에서 기존 연결 삭제**:
   - 좌측 패널에서 `call_act_db` 연결 우클릭
   - "연결 삭제" 선택

2. **새 연결 생성**:
   - Database: **`callact_db`** ⚠️ (언더스코어 없음)

3. **또는 기존 연결 수정**:
   - 우클릭 → "연결 편집"
   - Database를 `callact_db`로 변경

---

### 3.4 DBeaver에서 `call_act_db`가 보임

**증상**: DBeaver 좌측 패널에 `call_act_db` 연결이 있음

**원인**: 이전에 생성한 연결이 남아있음

**해결**:
```powershell
# 1. 기존 연결 삭제
# DBeaver 좌측 패널에서 call_act_db 우클릭 → "연결 삭제"

# 2. 새 연결 생성
# Database: callact_db (언더스코어 없음)

# 또는
# 3. 기존 연결 수정
# 우클릭 → "연결 편집" → Database: callact_db
```

## 4. 데이터 적재 오류

### 4.1 `FileNotFoundError: hana_vectordb_with_embeddings.json`

**증상**:
```
FileNotFoundError: [Errno 2] No such file or directory: '...\hana_vectordb_with_embeddings.json'
```

**원인**: 임베딩 파일이 생성되지 않음

**해결**:
1. **파일 존재 확인**:
```powershell
Test-Path "data-preprocessing\data\hana\hana_vectordb_with_embeddings.json"
# False면 파일 없음
```

2. **임베딩 생성 스크립트 실행**:
```powershell
conda activate final_env
cd scripts\db_loading

# 임베딩 생성 (테스트용 200개)
python generate_embeddings_hana.py --limit 200

# 또는 전체 데이터
python generate_embeddings_hana.py
```

**참고**: `docs/04_dev/02_db/03_임베딩_데이터_저장_위치.md` 참조

---

### 4.2 `Foreign Key constraint violation`

**증상**:
```
psycopg2.IntegrityError: insert or update on table "consultation_documents" violates foreign key constraint
```

**원인**: `consultations` 테이블을 먼저 적재하지 않음

**해결**:
```powershell
# consultations를 먼저 적재
python load_hana_to_db.py --skip-documents

# 그 다음 documents 적재
python load_hana_to_db.py --skip-consultations

# 또는 전체 다시 적재 (권장)
python load_hana_to_db.py
```

**주의**: `--skip-consultations` 옵션을 사용하면 안 됨

---

### 4.3 데이터 개수 불일치

**증상**: 
- Consultations: 10건
- Consultation Documents: 5건

**원인**: 일부 데이터 적재 실패

**확인**:
```sql
-- DBeaver에서 실행
SELECT COUNT(*) FROM consultations;
SELECT COUNT(*) FROM consultation_documents;

-- 고아 문서 확인
SELECT COUNT(*) 
FROM consultation_documents cd
LEFT JOIN consultations c ON cd.consultation_id = c.id
WHERE c.id IS NULL;
```

**해결**:
```powershell
# 전체 다시 적재 (중복은 자동으로 업데이트됨)
python load_hana_to_db.py
```

## 5. 검증 오류

### 5.1 `Orphaned Documents: X건`

**증상**:
```
[WARNING] Found X documents without matching consultation
```

**원인**: Foreign Key 관계 문제

**해결**:
```sql
-- 고아 문서 확인
SELECT cd.id, cd.title, cd.consultation_id
FROM consultation_documents cd
LEFT JOIN consultations c ON cd.consultation_id = c.id
WHERE c.id IS NULL;

-- consultations 재적재
python load_hana_to_db.py --skip-documents
python load_hana_to_db.py --skip-consultations
```

---

### 5.2 `Documents without Embedding: X건`

**증상**:
```
Documents without Embedding: X건 (0건이어야 함)
```

**원인**: 임베딩 파일에 일부 데이터가 없음

**확인**:
```sql
-- 임베딩이 없는 문서 확인
SELECT id, title, category
FROM consultation_documents
WHERE embedding IS NULL
LIMIT 10;
```

**해결**:
1. 임베딩 파일 확인
2. 누락된 데이터에 대해 임베딩 재생성
3. 해당 문서만 재적재

---

### 5.3 `Valid Dimensions (1536): X/Y` (일부 실패)

**증상**:
```
Valid Dimensions (1536): 5000/5371
```

**원인**: 일부 임베딩 벡터 차원이 잘못됨

**확인**:
```sql
-- 차원이 잘못된 문서 확인
SELECT id, title,
    array_length(string_to_array(embedding::text, ','), 1) as dimension
FROM consultation_documents
WHERE embedding IS NOT NULL
AND array_length(string_to_array(embedding::text, ','), 1) != 1536;
```

**해결**: 해당 문서의 임베딩 재생성 후 재적재

## 6. 기타 오류

### 6.1 인코딩 오류 (`cp949 codec can't encode`)

**증상**:
```
UnicodeEncodeError: 'cp949' codec can't encode character '\u2705' in position 24
```

**원인**: Windows PowerShell의 인코딩 문제 (출력 문제)

**해결**:
- 이 오류는 출력 문제일 뿐, 실제 작업에는 영향 없음
- Anaconda Prompt 사용 권장
- 또는 출력 무시하고 계속 진행

---

### 6.2 `Connection refused` 또는 `Connection timeout`

**증상**:
```
psycopg2.OperationalError: connection to server at "localhost" (::1), port 5432 failed
```

**원인**: Docker 컨테이너가 실행되지 않음

**해결**:
```powershell
# Docker 컨테이너 확인
docker ps
# callact_db_container가 보이지 않으면 실행 필요

# 컨테이너 실행
cd scripts\docker
docker-compose up -d

# 몇 초 후 확인
docker ps
```

---

### 6.3 메모리 부족 오류

**증상**:
```
MemoryError: Unable to allocate array
```

**원인**: 데이터가 너무 커서 메모리 부족

**해결**:
```powershell
# 배치 크기 줄이기
$env:DB_LOAD_BATCH_SIZE="50"  # 기본값: 100

# 또는 limit 옵션 사용
python load_hana_to_db.py --limit 1000  # 점진적으로 증가
```

## 7. 문제 해결 순서

**오류 발생 시 체크리스트**:

1. ✅ **환경 확인**
   - [ ] `conda activate final_env` 성공
   - [ ] Python 3.11.14 확인
   - [ ] 필요한 패키지 설치 확인

2. ✅ **Docker 확인**
   - [ ] Docker Desktop 실행 중
   - [ ] `docker ps`에서 `callact_db_container` 확인
   - [ ] 컨테이너 상태가 "healthy"

3. ✅ **DB 연결 확인**
   - [ ] 환경 변수 설정 확인
   - [ ] Database 이름: `callact_db` (언더스코어 없음)
   - [ ] 사용자: `callact_admin` (postgres 아님)

4. ✅ **파일 확인**
   - [ ] 임베딩 파일 존재 확인
   - [ ] RDB 메타데이터 파일 존재 확인

5. ✅ **검증 실행**
   - [ ] 검증 스크립트 실행
   - [ ] 오류 메시지 확인
   - [ ] 위 가이드에서 해당 오류 찾기
