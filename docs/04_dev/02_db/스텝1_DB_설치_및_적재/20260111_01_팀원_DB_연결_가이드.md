## 목적

팀원이 이미 적재된 데이터베이스에 DBeaver로 연결하는 방법을 안내합니다.
**⚠️ 중요**: 이 가이드는 DB 적재 과정이 이미 완료된 경우를 위한 것입니다.
DB 적재가 필요하면 [01_스텝1_팀원_시작_가이드.md](./20260111_02_스텝1_팀원_시작_가이드.md)를 참조하세요.

## 배경

- DB 적재는 담당자가 이미 완료
- 팀원은 데이터베이스 연결만 하면 됨
- DBeaver를 사용하여 PostgreSQL에 연결

## 내용

### 1. 사전 준비

#### 1.1 DBeaver 설치

- DBeaver가 설치되어 있지 않으면 설치 필요
- https://dbeaver.io/download/

#### 1.2 연결 정보 받기

담당자 또는 DB 호스트로부터 다음 정보를 받으세요:

- **Host**: `[Tailscale IP 주소]` (예: `100.64.1.2`) ⚠️ **Tailscale 사용**
- **Port**: `5432`
- **Database**: `callact_db` ⚠️ **주의**: 언더스코어 없음 (`call_act_db` 아님)
- **Username**: `callact_admin`
- **Password**: `callact_pwd1` (또는 담당자가 공유한 비밀번호)

**⚠️ 중요**: 
- 이 프로젝트는 **Tailscale VPN**을 사용합니다
- Tailscale 설치 및 설정이 필요합니다
- 상세 가이드: [Tailscale DB 연결 가이드](./20260111_05_Tailscale_DB_연결_가이드.md) 참조

### 2. Tailscale 설치 (필수)

**⚠️ 중요**: 이 프로젝트는 Tailscale VPN을 사용합니다. 먼저 Tailscale을 설치하고 설정해야 합니다.

**Tailscale 설치 및 설정**:
1. [Tailscale DB 연결 가이드](./20260111_05_Tailscale_DB_연결_가이드.md) 참조
2. Tailscale 설치 및 로그인
3. 담당자의 Tailscale 네트워크에 접속 확인

### 3. DBeaver 연결 생성

#### 3.1 새 연결 생성

1. **DBeaver 실행**
2. **새 연결 생성**:
   - 좌측 상단 "+" 버튼 클릭
   - 또는 메뉴: Database → New Database Connection
3. **데이터베이스 선택**: **PostgreSQL** 선택 → Next

#### 3.2 연결 정보 입력

**Main 탭**:
- **Host**: Tailscale IP 주소 (예: `100.64.1.2`) ⚠️ **Tailscale IP 사용**
- **Port**: `5432`
- **Database**: `callact_db` ⚠️ **중요**: 언더스코어 없음
- **Username**: `callact_admin`
- **Password**: `callact_pwd1` (또는 담당자가 공유한 비밀번호)
- **Save password**: 체크 (선택사항)

#### 3.3 연결 테스트

1. **"Test Connection" 버튼 클릭**
2. **드라이버 다운로드 안내가 나오면**: "Download" 클릭하여 자동 설치
3. **성공 메시지 확인**: ✅ "Connected" 또는 "연결이 성공적으로 완료되었습니다"

#### 3.4 연결 완료

1. **"Finish" 버튼 클릭**
2. **좌측 패널에서 연결 확인**: `callact_db` 연결이 보임
3. **확장하여 테이블 확인**:
   - `callact_db` → `Schemas` → `public` → `Tables`
   - 다음 테이블 3개가 보여야 함:
     - `employees`
     - `consultations`
     - `consultation_documents`

### 4. 데이터 확인

#### 3.1 테이블 데이터 확인

```sql
-- DBeaver에서 SQL 편집기 열기 (Ctrl+Shift+Enter)

-- 전체 데이터 개수 확인
SELECT 
    (SELECT COUNT(*) FROM consultations) as consultations_count,
    (SELECT COUNT(*) FROM consultation_documents) as documents_count,
    (SELECT COUNT(*) FROM employees) as employees_count;

-- 상담 데이터 샘플 확인
SELECT id, category, title, call_date 
FROM consultations 
LIMIT 10;

-- 문서 데이터 샘플 확인
SELECT id, category, title, created_at 
FROM consultation_documents 
LIMIT 10;
```

#### 3.2 기본 상담사 확인

```sql
-- 기본 상담사 확인
SELECT id, name, email, role, department 
FROM employees 
WHERE id = 'EMP-TEDI-DEFAULT';

-- 결과 예시:
-- EMP-TEDI-DEFAULT | 테디카드 기본 상담사 | default@tedicard.com | 상담사 | 테디카드 상담팀
```

### 5. 문제 해결

#### 5.1 Tailscale 연결 문제

**증상**: Tailscale이 연결되지 않거나 "Disconnected" 상태

**해결**:
1. [Tailscale DB 연결 가이드 - 문제 해결](./20260111_05_Tailscale_DB_연결_가이드.md#4-문제-해결) 참조
2. Tailscale 재시작
3. 담당자에게 네트워크 초대 확인 요청

#### 5.2 연결 실패: `FATAL: password authentication failed`

**원인**: 비밀번호가 잘못됨

**해결**:
- 담당자에게 정확한 비밀번호 확인
- Password 필드 다시 입력

#### 5.3 연결 실패: `Connection refused` 또는 `Connection timeout`

**원인**: 
- Tailscale이 연결되지 않음
- 담당자의 Docker 컨테이너가 실행되지 않음
- Tailscale IP 주소가 잘못됨

**해결**:
1. **Tailscale 연결 상태 확인**:
   ```bash
   tailscale status
   ```

2. 담당자에게 Docker 컨테이너 실행 확인 요청:
   ```bash
   docker ps
   # callact_db_container가 보여야 함
   ```

3. Tailscale IP 확인 (담당자에게 요청)

4. Ping 테스트:
   ```bash
   ping [Tailscale IP]
   ```

#### 5.4 `FATAL: database "callact_db" does not exist`

**원인**: 데이터베이스 이름이 잘못됨

**해결**:
- Database 필드 확인: `callact_db` (언더스코어 없음)
- `call_act_db`로 입력하지 않았는지 확인

#### 5.5 이전 연결(`call_act_db`)이 보임

**원인**: 이전에 잘못된 이름으로 연결 생성

**해결**:
1. 좌측 패널에서 `call_act_db` 연결 우클릭
2. "연결 삭제" 선택
3. 위 가이드대로 새 연결 생성 (`callact_db`)

**더 많은 문제 해결**: [Tailscale DB 연결 가이드 - 문제 해결](./20260111_05_Tailscale_DB_연결_가이드.md#4-문제-해결) 참조

### 6. Backend 코드에서 사용

#### 5.1 .env 파일 설정

프로젝트를 받은 후 `.env` 파일을 생성하세요:

```bash
# backend/.env.example을 복사
Copy-Item backend\.env.example backend\.env
```

#### 5.2 .env 파일 수정

```env
# backend/.env
DB_HOST=[팀원 IP 주소]  # localhost가 아님!
DB_PORT=5432
DB_USER=callact_admin
DB_PASSWORD=callact_pwd1  # 담당자가 공유한 비밀번호
DB_NAME=callact_db
```

#### 5.3 Backend 코드에서 자동 사용

`backend/app/core/config.py`가 환경 변수를 자동으로 읽어옵니다:

```python
# backend/app/core/config.py는 이미 환경 변수를 사용하도록 설정됨
DB_HOST = os.getenv("DB_HOST", "localhost")
DB_NAME = os.getenv("DB_NAME", "callact_db")
# ...
```
