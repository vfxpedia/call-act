## 1. 페르소나 5타입 (팀원 LLM 분류 기준)

### 1.1 타입 정의

| 코드 | 이름 | 카테고리 | 설명 |
|------|------|----------|------|
| N1 | 일반형 | normal | 큰 특징 없이 바로 문의사항을 말함 |
| N2 | 수다형 | normal | 사적인 이야기나 본인 상황을 길게 설명함 |
| S1 | 급한성격형 | special | 빠른 처리를 선호함 |
| S2 | 디지털미아형 | special | 기술적 조작에 서툴고 앱 사용을 어려워함 |
| S3 | 불만형 | special | 분노, 짜증을 드러냄 |

### 1.2 LLM Guidance

```
N1: 표준 응대 매뉴얼대로 진행하세요. 고객이 원하는 바를 파악하여 신속하게 처리하면 됩니다.

N2: 고객의 이야기를 충분히 들어주세요. 공감 표현을 자주 사용하고, 적절한 타이밍에 본론으로 유도하세요. "네, 그러셨군요"와 같은 리액션이 효과적입니다.

S1: 시간을 최소화하세요. 인사말은 짧게, 즉시 해결 가능한 방법을 먼저 제시하세요. 불필요한 설명은 생략하고 핵심만 전달하세요.

S2: 천천히 단계별로 안내하세요. 전문 용어를 피하고 "화면 왼쪽 위", "빨간색 버튼"처럼 시각적으로 설명하세요. 각 단계마다 "여기까지 되셨나요?"로 확인하세요.

S3: 먼저 진심으로 사과하고 고객의 감정을 인정하세요. "불편을 드려 정말 죄송합니다"로 시작하고, 즉각적인 해결책을 제시하세요. 절대 감정적으로 대응하지 마세요.
```

### 1.3 Personality Tags

| 코드 | Tags |
|------|------|
| N1 | `['normal', 'direct', 'straightforward']` |
| N2 | `['talkative', 'personal', 'expressive']` |
| S1 | `['impatient', 'urgent', 'time_sensitive']` |
| S2 | `['tech_challenged', 'needs_guidance', 'patient_required']` |
| S3 | `['angry', 'frustrated', 'demanding']` |

### 1.4 Communication Style

| 코드 | Speed | Tone |
|------|-------|------|
| N1 | moderate | neutral |
| N2 | moderate | warm |
| S1 | fast | concise |
| S2 | slow | patient |
| S3 | moderate | calm_professional |

## 2. customers 테이블 변경

### 2.1 삭제된 컬럼

| 컬럼명 | 이유 |
|--------|------|
| `llm_guidance` | persona_types 테이블에서 JOIN으로 조회 |
| `personality_tags` | persona_types 테이블에서 JOIN으로 조회 |
| `communication_style` | persona_types 테이블에서 JOIN으로 조회 |
| `customer_type_codes` | 고객당 1개 페르소나만 (current_type_code 사용) |

### 2.2 FK 제약조건 추가

```sql
ALTER TABLE customers
ADD CONSTRAINT fk_customers_persona_type
FOREIGN KEY (current_type_code) REFERENCES persona_types(code);
```

### 2.3 조회 방법 변경

**변경 전**: `SELECT * FROM customers WHERE id = ?`

**변경 후**: `SELECT * FROM v_customer_with_persona WHERE id = ?`

뷰에서 제공하는 추가 필드:
- `age` (birth_date에서 계산)
- `fcr_rate` (FCR 비율)
- `persona_name`, `persona_description`
- `personality_tags`, `communication_style`, `llm_guidance`

## 4. 자동 통계 트리거

### 4.1 고객 통계 자동 업데이트

```sql
-- 상담 INSERT 시 자동 실행
CREATE TRIGGER trg_consultation_insert_update_customer
AFTER INSERT ON consultations
FOR EACH ROW
EXECUTE FUNCTION fn_update_customer_stats_on_consultation();
```

업데이트 항목:
- `total_consultations` +1
- `last_consultation_date` 갱신

### 4.2 FCR 자동 계산

```sql
-- 상담 INSERT 시 자동 실행
CREATE TRIGGER trg_consultation_insert_check_fcr
AFTER INSERT ON consultations
FOR EACH ROW
EXECUTE FUNCTION fn_update_fcr_on_consultation();
```

로직:
1. 같은 고객, 같은 카테고리, 7일 이내 이전 상담이 있으면 → 이전 상담의 FCR = FALSE
2. 새 상담은 FCR = TRUE로 설정
3. `customers.resolved_first_call` 재계산

## 5. 적용 방법

```bash

python 01_setup_callact_db.py
```

- 기존 `current_type_code` 값 중 N1, N2, S1, S2, S3 외의 값은 NULL로 변경됨

## 결론

v4.0 스키마는 Frontend 요구사항과 팀원의 LLM 분류 결과를 반영한 통합 버전이다.

핵심 변경:
1. **단순화**: 12타입 → 5타입
2. **정규화**: 페르소나 정보는 persona_types 테이블에만 저장
3. **확장**: consultations에 피드백, 녹취, 후속조치 필드 추가
4. **자동화**: 트리거로 통계 자동 업데이트
