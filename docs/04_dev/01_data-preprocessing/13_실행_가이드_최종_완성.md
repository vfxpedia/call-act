### Step 1: 데이터 변환 (01~05 스크립트)

**목적**: 원본 데이터를 표준 형식으로 변환하고 텍스트 치환 (신한→테디 등)

**실행 순서**:

```bash
# 작업 디렉토리로 이동
cd data-preprocessing_dev/preprocessing/tedicard

# 1. 신한 카드 정보 변환
python 01_convert_shinhan_cards.py

# 2. 현대 가이드 변환 (merge 포함)
python 02_convert_hyundai_guides.py

# 3. 삼성 가이드 변환 + 공지사항 (merge 포함)
python 03_convert_samsung_guides.py

# 4. 신한 약관 변환 (merge 미적용)
python 04_convert_shinhan_terms.py

# 5. 스페셜 카드 변환 (merge 미적용)
python 05_convert_special_cards.py
```

**출력 파일** (각 스크립트 실행 후 생성):
- `output/teddycard_card_products.json` (01번)
- `output/teddycard_service_guides_hyundai.json` (02번)
- `output/teddycard_service_guides_samsung.json` (03번)
- `output/teddycard_notices.json` (03번)
- `output/teddycard_service_guides_shinhan.json` (04번)
- `output/teddycard_service_guides_special.json` (05번)

**확인 사항**:
- [ ] 모든 출력 파일이 생성되었는지 확인
- [ ] 파일 크기가 0이 아닌지 확인
- [ ] 에러 메시지가 없는지 확인

**확인 사항**:

- [ ] 파일 크기가 0이 아닌지 확인
- [ ] 연회비, 브랜드 등이 올바르게 파싱되었는지 확인 (샘플 확인)

### Step 3: 키워드 추출 (08_extract_keywords.py)

**목적**: enriched 파일에 keywords 필드 추가 (STT 키워드 추출 및 RAG 검색 활용)

**현재 방식**: 수동 작성된 `keywords_dict.json` 사용

**향후 개선**: hana 데이터에서 키워드 사전 자동 생성 (참고: `11_키워드_사전_개선_방안.md`)

**중요**: 이 단계는 **enriched 파일**에 keywords를 추가합니다. 원본 파일은 수정하지 않습니다.

```bash
# 단어사전만 사용 (빠름, 권장)
python 08_extract_keywords.py

# 또는 LLM 보완 포함 (더 정확하지만 느림)
python 08_extract_keywords.py --use-llm
```

**처리 파일** (enriched 파일 우선):
- `output/teddycard_service_guides_enriched.json`
- `output/teddycard_card_products_enriched.json`
- `output/teddycard_notices_enriched.json`

**출력**: enriched JSON 파일에 `keywords` 필드가 추가됨 (파일이 업데이트됨)

**확인 사항**:
- [ ] 모든 enriched 파일에 `keywords` 필드가 추가되었는지 확인
- [ ] 키워드가 빈 배열이 아닌 문서가 있는지 확인 (샘플 확인)
- [ ] 원본 파일은 수정되지 않았는지 확인

## 3. 문서 번호 정보 점검

### 3.1 현재 데이터 구조 확인

**약관 문서** (`teddycard_service_guides_shinhan.json`):
- `title`: "제1조(목적)", "제2조(용어의 정의)" 등 조 번호 포함
- `metadata.original_title`: 원본 제목 보존
- `id`: 문서 ID (예: `sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001`)

**카드 정보 문서** (`teddycard_card_products.json`):
- `id`: 카드 ID (예: `CARD-SHINHAN-{card_name}`)
- `name`: 카드명 (테디카드로 치환됨)

**서비스 가이드 문서** (`teddycard_service_guides_*.json`):
- `id`: 문서 ID (원본 ID 보존)
- `title`: 문서 제목

### 3.2 프론트엔드 활용 방안

**STT 키워드 → VectorDB 검색 → 화면 표시 시나리오**:

1. **STT 키워드 추출**: 실시간 음성 인식에서 키워드 추출
2. **VectorDB 검색**: 키워드 기반 유사도 검색
3. **문서 정보 표시**:
   - 문서 제목 (`title`)
   - 문서 ID (`id`)
   - 원본 출처 (`metadata.original_source`)
   - 약관 조 번호 (`title`에서 추출 또는 별도 필드)

**데이터 구조 점검 결과**:
- ✅ `title` 필드에 약관 조 번호 포함 (예: "제1조(목적)")
- ✅ `id` 필드에 문서 식별자 포함
- ✅ `metadata.original_title`에 원본 제목 보존
- ✅ `metadata.original_source`에 데이터 출처 포함

**프론트엔드 표시 예시**:
```
[검색 결과]
제목: 제1조(목적)
출처: 신한 약관
문서 ID: sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001
```

```python
import json
from pathlib import Path

# 예시: service_guides 파일 확인
file_path = Path("output/teddycard_service_guides_enriched.json")
with open(file_path, 'r', encoding='utf-8') as f:
    data = json.load(f)

# 첫 번째 문서 확인
if data:
    first_doc = data[0]
    print(f"ID: {first_doc.get('id')}")
    print(f"Title: {first_doc.get('title')}")
    print(f"Keywords: {first_doc.get('keywords', [])}")

embedding_file = Path("output/teddycard_service_guides_with_embeddings.json")

        embedding_data = json.load(f)

        first_embedding = embedding_data[0]
        print(f"임베딩 포함: {'embedding' in first_embedding}")

            print(f"임베딩 차원: {len(first_embedding['embedding'])}")
```

## 7. 문제 해결

### 파일을 찾을 수 없음

**증상**: `FileNotFoundError` 또는 파일 경로 오류

**해결**:
1. 작업 디렉토리 확인: `cd data-preprocessing_dev/preprocessing/tedicard`
2. 파일 존재 확인: `ls output/*.json` 또는 `Get-ChildItem output/*.json`
3. 파일명 확인: `teddycard_`로 시작하는지 확인

### API 키 오류

**증상**: `OPENAI_API_KEY not found`

**해결**:
1. `.env` 파일 확인: 프로젝트 루트(`call-act/`)에 존재하는지 확인
2. 환경 변수 확인: `echo $env:OPENAI_API_KEY` (PowerShell)

### 모듈 없음 오류

**증상**: `ModuleNotFoundError: No module named 'openai'`

**해결**:
```bash
conda activate final_env
pip install openai python-dotenv tqdm
```

## 11. 문서 번호 정보 점검 및 활용 방안

### 11.1 현재 데이터 구조 확인

**약관 문서** (`teddycard_service_guides_shinhan.json`):
- `title`: "제1조(목적)", "제2조(용어의 정의)" 등 조 번호 포함
- `metadata.original_title`: 원본 제목 보존 ("제1조(목적)")
- `id`: 문서 식별자 (예: `sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001`)
- `metadata.original_source`: 데이터 출처 ("shinhan")

**서비스 가이드 문서**:
- `title`: 문서 제목
- `id`: 문서 식별자
- `metadata.original_source`: 데이터 출처 (hyundai, samsung, shinhan, special_card)

**카드 정보 문서**:
- `id`: 카드 ID (예: `CARD-SHINHAN-{card_name}`)
- `name`: 카드명 (테디카드로 치환됨)

### 11.2 데이터 점검 결과

**점검 항목**:
- ✅ 문서 번호 정보 존재: `title` 필드에 포함 (약관 조 번호: "제1조", "제2조" 등)
- ✅ 문서 식별자 존재: `id` 필드
- ✅ 출처 정보 존재: `metadata.original_source`
- ✅ 원본 제목 보존: `metadata.original_title`
- ✅ 원본 ID 보존: `metadata.original_id`

**실제 데이터 예시**:
```json
{
  "id": "sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001",
  "title": "제1조(목적)",
  "metadata": {
    "original_source": "shinhan",
    "original_id": "sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001",
    "original_title": "제1조(목적)"
  }
}
```

### 11.3 프론트엔드 활용 방안

**STT 키워드 → VectorDB 검색 → 화면 표시 시나리오**:

1. **STT 키워드 추출**: 실시간 음성 인식에서 키워드 추출
2. **VectorDB 검색**: 키워드 기반 유사도 검색 (RAG)
3. **문서 정보 표시**:
   - 문서 제목 (`title`)
   - 문서 번호 (약관 조 번호: `title`에서 정규식으로 추출, 예: `제\d+조`)
   - 문서 식별자 (`id`)
   - 원본 출처 (`metadata.original_source`)
   - 카테고리 (`category`)

**프론트엔드 표시 예시**:
```
[검색 결과 1]
제목: 제1조(목적)
내용: 이 약관은 "테디카드 주식회사"가...
출처: 신한 약관
문서 ID: sinhan_terms_loan__대환_대출_비교_서비스_이용약관_001
카테고리: 대출/여신

[검색 결과 2]
제목: Apple Pay 이용처 안내
내용: 위 마크가 있는 곳이라면...
출처: 현대 가이드
문서 ID: hyundai_applepay_0000
카테고리: 이용처 안내
```

**구현 방안**:
1. VectorDB 검색 결과에서 다음 필드 추출:
   - `title`: 문서 제목 (약관 조 번호 포함)
   - `id`: 문서 식별자
   - `metadata.original_source`: 데이터 출처
   - `category`: 카테고리
   - `content`: 문서 내용 (요약 또는 일부)

2. 약관 문서인 경우 조 번호 추출:
   - 정규식: `제\d+조` → "제1조", "제2조" 등
   - `document_type`이 "terms"인 경우 조 번호 강조 표시

3. 프론트엔드 컴포넌트 구성:
   - 제목 (조 번호 강조)
   - 내용 (일부 또는 요약)
   - 출처 뱃지
   - 카테고리 태그
   - 문서 ID (상세 정보 보기용)

### 11.4 결론

- ✅ **문서 번호 정보 존재**: `title` 필드에 약관 조 번호 포함
- ✅ **문서 식별자 존재**: `id` 필드로 고유 식별 가능
- ✅ **출처 정보 존재**: `metadata.original_source`로 데이터 출처 추적 가능
- ✅ **원본 정보 보존**: `metadata.original_*` 필드들로 원본 정보 추적 가능

**최종 결론**: 현재 데이터 구조로 프론트엔드에서 문서 번호 정보를 표시하고, STT 키워드 기반 VectorDB 검색 결과를 사용자에게 명확하게 제시할 수 있습니다.
