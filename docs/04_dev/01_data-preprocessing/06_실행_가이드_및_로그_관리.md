# 실행 가이드 및 로그 관리

## 1. 실행 순서

### 1.1 전체 워크플로우

```
1. 원본 데이터 수집
   ↓
2. 텍스트 치환 (신한→테디 등)
   ↓
3. JSON 형식 변환 (01~05 스크립트)
   ↓
4. 데이터 보강 (07_enrich_for_db.py) ← 현재 단계
   ↓
5. 임베딩 생성 (06_generate_embeddings.py) ← 다음 단계
   ↓
6. DB 적재 (backend_dev/app/db/scripts/)
```

### 1.2 실행 명령어

```bash
# 작업 디렉토리로 이동
cd data-preprocessing_dev/preprocessing/tedicard

# 1. 데이터 보강
python 07_enrich_for_db.py

# 2. 임베딩 생성 (처음 실행)
python 06_generate_embeddings.py

# 3. 임베딩 생성 (중단 후 재시작)
python 06_generate_embeddings.py --resume
```

---

## 2. 로그 관리

### 2.1 로그 파일 위치

- **임베딩 생성 로그**: `data-preprocessing_dev/preprocessing/output/embedding_generation.log`
- **체크포인트 파일**: `data-preprocessing_dev/preprocessing/output/embedding_checkpoint.json`
- **에러 로그**: `data-preprocessing_dev/preprocessing/output/embedding_errors.json` (에러 발생 시)

### 2.2 로그 내용

**임베딩 생성 로그** (`embedding_generation.log`):
- 타임스탬프가 포함된 모든 로그 메시지
- 진행 상황 (처리된 문서 수, 에러 수)
- 체크포인트 저장 시점
- API 호출 실패 및 재시도 정보

**체크포인트 파일** (`embedding_checkpoint.json`):
```json
{
  "processed_ids": ["doc_1", "doc_2", ...],
  "last_index": 150,
  "timestamp": "2026-01-11 15:30:00",
  "total_documents": 1000,
  "processed_count": 150,
  "error_count": 2,
  "completed": false
}
```

## 3. 재시작 기능

### 3.1 체크포인트 기반 재시작

임베딩 생성 중 중단되면 `--resume` 옵션으로 재시작 가능:

```bash
# 중단된 작업 재시작
python 06_generate_embeddings.py --resume
```

**동작 방식**:
1. `embedding_checkpoint.json` 파일에서 이미 처리된 문서 ID 목록 로드
2. 해당 문서들은 제외하고 나머지만 처리
3. 50개마다 체크포인트 저장 (중단 시 손실 최소화)

### 3.2 체크포인트 저장 주기

- **기본**: 50개 문서마다 자동 저장
- **최종**: 모든 문서 처리 완료 시 저장
- **에러 발생 시**: 즉시 저장

### 3.3 재시작 시 주의사항

1. **체크포인트 파일 확인**: `embedding_checkpoint.json` 파일이 존재하는지 확인
2. **로그 확인**: `embedding_generation.log`에서 마지막 처리 상태 확인
3. **에러 로그 확인**: `embedding_errors.json`에서 실패한 문서 ID 확인

## 4. 에러 처리

### 4.1 API 호출 실패

**재시도 로직**:
- 최대 3회 재시도
- 재시도 간격: 5초 × 시도 횟수 (5초, 10초, 15초)
- 모든 재시도 실패 시 에러 로그에 기록

**에러 로그 예시**:
```json
{
  "errors": ["doc_123", "doc_456"],
  "timestamp": "2026-01-11T15:30:00"
}
```

### 4.2 네트워크 중단

- 체크포인트가 저장되어 있으면 `--resume`으로 재시작
- 처리 중이던 문서는 다시 처리됨 (중복 방지: processed_ids 체크)

### 4.3 메모리 부족

- 대량 데이터 처리 시 배치 크기 조정 필요
- 현재는 문서 단위로 순차 처리 (메모리 효율적)

## 5. 진행 상황 모니터링

### 5.1 콘솔 출력

- `tqdm` 진행률 표시줄
- 실시간 처리 상태 (처리된 문서 수, 에러 수)

### 5.2 로그 파일 모니터링

```bash
# 실시간 로그 확인 (PowerShell)
Get-Content embedding_generation.log -Wait -Tail 50

# 또는 tail 명령어 (Git Bash)
tail -f embedding_generation.log
```

### 5.3 체크포인트 확인

```python
import json
from pathlib import Path

checkpoint_file = Path("output/embedding_checkpoint.json")
if checkpoint_file.exists():
    with open(checkpoint_file, 'r', encoding='utf-8') as f:
        checkpoint = json.load(f)
    
    print(f"처리 완료: {checkpoint.get('processed_count', 0)}/{checkpoint.get('total_documents', 0)}")
    print(f"에러 수: {checkpoint.get('error_count', 0)}")
    print(f"완료 여부: {checkpoint.get('completed', False)}")
```

## 7. 문제 해결

### 7.1 파일을 찾을 수 없음

**증상**: `FileNotFoundError` 또는 파일 경로 오류

**해결**:
1. 작업 디렉토리 확인: `cd data-preprocessing_dev/preprocessing/tedicard`
2. 파일 존재 확인: `ls output/*.json`
3. BASE_DIR 경로 확인: 스크립트 내 `BASE_DIR` 설정 확인

### 7.2 API 키 오류

**증상**: `OPENAI_API_KEY not found`

**해결**:
1. `.env` 파일 확인: 프로젝트 루트 또는 스크립트 디렉토리
2. 환경 변수 확인: `echo $env:OPENAI_API_KEY` (PowerShell)
3. 스크립트 내 환경 변수 로드 확인

### 7.3 체크포인트 파일 손상

**증상**: JSON 파싱 오류

**해결**:
1. 체크포인트 파일 백업
2. 수동으로 JSON 형식 확인 및 수정
3. 또는 체크포인트 파일 삭제 후 처음부터 재실행
