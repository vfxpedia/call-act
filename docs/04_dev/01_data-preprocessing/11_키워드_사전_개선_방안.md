## 1. 현재 상황

### 1.1 현재 키워드 추출 방식

**현재 구현** (`08_extract_keywords.py`):
- 수동 작성된 `keywords_dict.json` 사용
- 14개 카테고리, 약 100+ 키워드
- 단어사전 기반 키워드 매칭 (빠름)
- LLM 보완 옵션 (선택적)

**문제점**:
- 수동 작성된 키워드 사전이 실제 상담 데이터를 반영하지 못할 수 있음
- 실제 사용되는 키워드를 놓칠 가능성

### 1.2 사용 가능한 실제 데이터

**Hana 카드 상담 데이터**:
- 총 6,533건의 실제 상담 사례
- 이미 `metadata.keywords` 필드에 키워드가 추출되어 있음
- 카테고리별로 분류되어 있음 (57개 카테고리)

**현재 hana 데이터 키워드 통계**:
- 총 고유 키워드: 약 76개
- 상위 키워드:
  - 카드: 6,014건
  - 결제: 5,267건
  - 이용: 2,357건
  - 신청: 1,282건
  - 해지: 1,144건
  - 신용카드: 951건
  - 등등...

## 2. 개선 방안

### 2.1 하이브리드 접근법 (권장)

**아이디어**: 
- 실제 상담 데이터(hana)에서 키워드를 추출하여 사전 구축
- 수동 사전은 핵심 키워드 보완용으로 사용
- STT 실시간 추출을 위한 빠른 매칭용으로 활용

**장점**:
1. 실제 사용되는 키워드 중심으로 구축
2. 6,533건을 모두 LLM으로 처리할 필요 없음 (이미 키워드가 추출되어 있음)
3. 이미 정리된 문서를 활용 (효율적)
4. 카테고리별 키워드 분포 확인 가능

**단점**:
- hana 데이터에 없는 새로운 키워드는 누락될 수 있음
- → 수동 사전으로 보완

### 2.2 구체적 구현 방안

#### 방법 1: hana 데이터에서 키워드 사전 자동 생성 (권장)

**스크립트**: `10_generate_keywords_dict_from_hana.py` (신규 작성)

**로직**:
1. `hana_vectordb.json` 로드
2. 모든 문서의 `metadata.keywords` 수집
3. 카테고리별 키워드 통계 분석
4. 빈도순으로 정렬하여 키워드 사전 생성
5. 수동 사전과 병합 (중복 제거)

**출력**: 
- `keywords_dict_from_hana.json` (자동 생성)
- 기존 `keywords_dict.json`과 병합하여 사용

**예시 출력 구조**:
```json
{
  "카드종류": ["신용카드", "체크카드", "법인카드", ...],
  "결제": ["결제", "승인", "취소", "환불", "거절", "한도", ...],
  "포인트": ["포인트", "마일리지", "캐시백", "적립", "사용", ...],
  ...
}
```

#### 방법 2: hana 데이터 + 수동 사전 병합

**순서**:
1. hana 데이터에서 키워드 사전 자동 생성
2. 기존 수동 사전(`keywords_dict.json`) 로드
3. 두 사전 병합 (hana 우선, 수동 사전은 보완)
4. 최종 키워드 사전 저장

**병합 전략**:
- hana 키워드가 우선 (실제 사용 빈도 기반)
- 수동 사전은 hana에 없는 키워드 추가
- 중복 제거

## 3. 실행 계획

### Phase 1: hana 데이터 분석

1. hana 데이터 키워드 통계 분석
2. 카테고리별 키워드 분포 확인
3. 빈도 기반 키워드 우선순위 결정

### Phase 2: 키워드 사전 자동 생성 스크립트 작성

1. `10_generate_keywords_dict_from_hana.py` 작성
2. hana 데이터에서 키워드 추출
3. 카테고리별로 그룹화
4. 빈도순 정렬

### Phase 3: 키워드 사전 병합

1. hana 기반 사전 생성
2. 기존 수동 사전과 병합
3. 최종 키워드 사전 저장

### Phase 4: 키워드 추출 스크립트 업데이트

1. `08_extract_keywords.py` 업데이트
2. 병합된 키워드 사전 사용
3. 테스트 및 검증

## 4. 예상 효과

### 4.1 키워드 커버리지 향상

- **현재**: 수동 사전 약 100개 키워드
- **개선 후**: hana 데이터 기반 + 수동 사전 보완
- **예상**: 실제 사용되는 키워드 커버리지 대폭 향상

### 4.2 STT 키워드 추출 정밀도 향상

- 실제 상담에서 사용되는 키워드 중심
- 카테고리별 키워드 매핑 정확도 향상
- 실시간 키워드 추출 속도 유지 (사전 기반 매칭)

### 4.3 RAG 검색 품질 향상

- 키워드 기반 필터링 정확도 향상
- 카테고리별 검색 정밀도 향상

## 5. 주의사항

### 5.1 hana 데이터 한계

- hana 데이터는 하나카드 상담 데이터
- 테디카드 통합 후에는 다른 카드사 키워드도 필요
- → 수동 사전으로 보완 필요

### 5.2 키워드 동의어 처리

- "카드" vs "신용카드" vs "체크카드"
- "결제" vs "승인" vs "거래"
- 동의어 매핑 필요 (향후 개선)

### 5.3 카테고리 매핑

- hana 카테고리와 테디카드 카테고리 매핑 필요
- 예: "도난/분실 신청/해제" → "분실도난" 카테고리
