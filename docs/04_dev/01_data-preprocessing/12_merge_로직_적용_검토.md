## 1. merge 로직 개요

**merge_by_category2 함수**:
- 같은 `metadata.original_category2` 값을 가진 문서들을 하나로 통합
- 통합된 문서의 제목은 category2 값 사용
- 통합된 문서의 내용은 모든 문서의 내용을 `\n\n`으로 연결
- 원본 문서 ID 목록을 `metadata.merged_from`에 저장

---

## 2. 각 데이터 소스별 merge 적용 여부

### 2.1 삼성 데이터 ✅ merge 적용

**현재 상태**: `03_convert_samsung_guides.py`에 merge 로직 적용됨

**이유**:
- 원본 데이터가 카테고리별로 과도하게 분할되어 있음
- 예: "신용도 관리방법"이 10개 문서로 분할
- merge 후: 1개 통합 문서로 생성 (RAG 검색에 유리)

**결과**:
- 개별 문서 → 통합 문서
- `metadata.merged_from`에 원본 ID 목록 보존

---

### 2.2 현대 데이터 ✅ merge 적용 (최근 추가)

**현재 상태**: `02_convert_hyundai_guides.py`에 merge 로직 추가 완료

**merge 효과**:
- 총 문서 수: 128건 → 60건 (68건 감소)
- merge 그룹: 21개
- 예: "Apple Pay 이용처" 관련 21개 문서 → 1개로 통합

**이유**:
- 관련 문서들을 통합하여 RAG 검색 품질 향상
- 불필요한 분할 제거

---

### 2.3 신한 약관 데이터 ❌ merge 미적용 (비권장)

**현재 상태**: `04_convert_shinhan_terms.py`에 merge 로직 없음

**merge 대상 확인 결과**:
- 총 문서 수: 988건
- merge 후 예상: 37건 (951건 감소)
- 문제: "본문" 카테고리가 634건 (대부분)

**merge 비권장 이유**:
1. **약관 특성**: 약관 문서는 조(條) 단위로 분할되어 있음
2. **검색 정확도**: 조 단위 검색이 더 정확함
   - 예: "제1조(목적)"과 "제2조(용어의 정의)"를 통합하면 검색 정확도 하락
3. **문서 구조**: 각 조가 독립적인 의미 단위
4. **RAG 검색**: 조 단위로 검색하는 것이 사용자 의도와 일치

**결론**: 신한 약관 데이터는 merge 적용하지 않음 (현재 상태 유지)

---

### 2.4 스페셜 카드 데이터 ❌ merge 미적용 (검토 필요)

**현재 상태**: `05_convert_special_cards.py`에 merge 로직 없음

**데이터 구조**:
- 원본 데이터: 단일 `category` 필드 (category1/category2 구조 없음)
- `metadata.original_category`: 단일 카테고리
- `metadata.original_card_name`: 카드명 (예: "국민행복카드", "K패스")

**merge 적용 가능 여부**:
- category2 구조가 없어서 merge 기준이 부족함
- 같은 카테고리를 가진 문서들을 통합할 수는 있지만, 효과가 미미할 가능성

**검토 필요 사항**:
1. 같은 카테고리를 가진 문서 수 확인
2. 통합 시 검색 품질 향상 여부 확인
3. 원본 데이터 구조 유지 여부 판단

**결론**: 
- 현재는 merge 적용하지 않음
- 향후 필요 시 category 기반 merge 고려 (category2가 없으므로)

---

## 3. merge 적용 기준

### 3.1 merge 적용 권장 조건

1. **원본 데이터가 과도하게 분할된 경우**
   - 예: 삼성 "신용도 관리방법" 10개 문서
   - 예: 현대 "Apple Pay 이용처" 21개 문서

2. **category2 기준으로 그룹화 가능한 경우**
   - 같은 category2를 가진 문서가 2개 이상
   - category2가 의미 있는 구분 기준

3. **통합 시 RAG 검색 품질 향상**
   - 관련 정보를 한 번에 검색 가능
   - 컨텍스트가 풍부해짐

### 3.2 merge 적용 비권장 조건

1. **문서가 독립적인 의미 단위인 경우**
   - 예: 약관의 조(條) 단위
   - 예: FAQ의 개별 질문

2. **category2 구조가 없는 경우**
   - merge 기준이 불명확
   - 예: 스페셜 카드 (단일 category)

3. **통합 시 검색 정확도 하락 우려**
   - 예: 신한 약관 조 단위 검색

---

## 4. 최종 정리

| 데이터 소스 | merge 적용 | 이유 |
|-----------|-----------|------|
| 삼성 | ✅ 적용 | 카테고리별 과도한 분할, merge 효과 큼 |
| 현대 | ✅ 적용 | 관련 문서 통합으로 검색 품질 향상 |
| 신한 약관 | ❌ 미적용 | 조 단위 독립성, 검색 정확도 유지 |
| 스페셜 카드 | ❌ 미적용 | category2 구조 없음, 효과 미미 |

## 5. 향후 개선 사항

### 5.1 스페셜 카드 merge 검토

**방안**:
1. 같은 카테고리를 가진 문서 수 확인
2. 통합 효과 시뮬레이션
3. 필요 시 category 기반 merge 적용

**현재**: merge 미적용 유지

### 5.2 merge 기준 세분화

**현재**: category2 기준 통합

**향후 개선 가능성**:
- 문서 길이 고려
- 문서 유사도 고려
- 사용자 검색 패턴 분석
