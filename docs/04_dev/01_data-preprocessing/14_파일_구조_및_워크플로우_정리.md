# 파일 구조 및 워크플로우 정리

## 작성일: 2026-01-11
## 목적: 파일 일관성 및 워크플로우 명확화

---

## 문제점

현재 출력 디렉토리에 다음 파일들이 혼재되어 있어 어떤 파일이 최종 버전인지 불명확함:

### 현재 파일 구조

```
output/
├── teddycard_card_products.json              # 원본 (Step 1)
├── teddycard_card_products_enriched.json     # Enriched (Step 2)
├── teddycard_notices.json                    # 원본 (Step 1)
├── teddycard_notices_enriched.json           # Enriched (Step 2)
├── teddycard_service_guides_samsung.json     # 원본 (Step 1)
├── teddycard_service_guides_hyundai.json     # 원본 (Step 1)
├── teddycard_service_guides_shinhan.json     # 원본 (Step 1)
├── teddycard_service_guides_special.json     # 원본 (Step 1)
└── teddycard_service_guides_enriched.json    # Enriched 통합 (Step 2)
```

### 문제점

1. **일관성 부족**: 
   - `card_products`, `notices`는 원본 + enriched 파일이 있음
   - `service_guides`는 원본 4개 + enriched 통합 1개가 있음
   - 어떤 파일이 최종 버전인지 명확하지 않음

2. **워크플로우 혼란**:
   - Step 3 (키워드 추출)가 어떤 파일을 수정해야 하는지 불명확
   - Step 4 (임베딩 생성)가 어떤 파일을 사용해야 하는지 명확하지 않음

---

## 올바른 워크플로우

### 파일 분류

#### 중간 파일 (Step 1 출력)
- 원본 데이터를 표준 형식으로 변환한 파일
- 용도: Step 2의 입력으로만 사용
- 최종 버전 아님

#### 최종 파일 (Step 2+ 출력)
- `_enriched.json` 접미사를 가진 파일
- Step 2 (데이터 보강) → Step 3 (키워드 추가) → Step 4 (임베딩 생성)
- DB 적재 및 RAG 검색에 사용되는 최종 버전

### 워크플로우

```
Step 1: 원본 데이터 변환 (01~05 스크립트)
  ↓
  중간 파일 생성:
  - teddycard_card_products.json
  - teddycard_service_guides_*.json (4개)
  - teddycard_notices.json
  ↓
Step 2: 데이터 보강 (07_enrich_for_db.py)
  ↓
  최종 파일 생성 (최종 버전의 기반):
  - teddycard_card_products_enriched.json
  - teddycard_service_guides_enriched.json (통합)
  - teddycard_notices_enriched.json
  ↓
Step 3: 키워드 추출 (08_extract_keywords.py)
  ↓
  최종 파일에 keywords 필드 추가:
  - teddycard_card_products_enriched.json (업데이트)
  - teddycard_service_guides_enriched.json (업데이트)
  - teddycard_notices_enriched.json (업데이트)
  ↓
Step 4: 임베딩 생성 (06_generate_embeddings.py)
  ↓
  최종 파일에 embedding 필드 추가:
  - teddycard_card_products_with_embeddings.json
  - teddycard_service_guides_with_embeddings.json
  - teddycard_notices_with_embeddings.json
```

---

## 명명 규칙

### 파일명 규칙

1. **중간 파일** (Step 1 출력):
   - `teddycard_<type>.json`
   - 예: `teddycard_card_products.json`

2. **최종 파일** (Step 2+ 출력):
   - `teddycard_<type>_enriched.json` (Step 2)
   - `teddycard_<type>_enriched.json` (Step 3에서 keywords 추가)
   - `teddycard_<type>_with_embeddings.json` (Step 4)

3. **service_guides 특수 사항**:
   - Step 1: 개별 파일 4개 (`samsung`, `hyundai`, `shinhan`, `special`)
   - Step 2: 통합 파일 1개 (`teddycard_service_guides_enriched.json`)

### 최종 버전 파일

**Step 4 완료 후 최종 버전:**
- `teddycard_card_products_with_embeddings.json`
- `teddycard_service_guides_with_embeddings.json`
- `teddycard_notices_with_embeddings.json`

**DB 적재 및 RAG 검색에 사용되는 파일**

## 해결 방안

### 방안 1: 명확한 파일 사용 규칙 (권장)

**원칙:**
- Step 2 이후: `_enriched.json` 파일만 사용
- Step 3: `_enriched.json` 파일에 keywords 추가
- Step 4: `_enriched.json` 파일에서 임베딩 생성
- 중간 파일 (원본): 참고용으로만 보관

**스크립트 수정:**
- `08_extract_keywords.py`: enriched 파일만 처리 (이미 수정 완료)
- `06_generate_embeddings.py`: enriched 파일만 사용 (이미 구현됨)

### 방안 2: 중간 파일 정리 (선택사항)

**옵션 A: 중간 파일 보관**
- 원본 파일들은 보관 (재실행 시 참고)
- 명확히 중간 파일임을 표시 (폴더 분리 또는 README)

**옵션 B: 중간 파일 제거**
- Step 2 이후 원본 파일 삭제
- 재실행 시 Step 1부터 다시 실행

**권장: 옵션 A (중간 파일 보관)**
- 재실행 시 시간 절약
- 디버깅 시 유용

## 현재 상황 및 다음 단계

### 현재 상태

1. ✅ Step 1 완료: 원본 파일 생성
2. ✅ Step 2 완료: enriched 파일 생성
3. ⚠️ Step 3: enriched 파일에 keywords 추가 필요 (수정된 스크립트 재실행)
4. ⏳ Step 4: 임베딩 생성 (대기 중)

### 다음 단계

1. **수정된 `08_extract_keywords.py` 실행**:
   ```bash
   python 08_extract_keywords.py --use-llm
   ```
   - enriched 파일들에 keywords 추가
   - 원본 파일은 수정하지 않음 (이미 수정된 코드)

2. **Step 4 실행**: 임베딩 생성
   ```bash
   python 06_generate_embeddings.py
   ```
