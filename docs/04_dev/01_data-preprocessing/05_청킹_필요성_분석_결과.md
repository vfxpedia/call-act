# 청킹(Chunking) 필요성 분석 결과

## 1. 분석 개요

전처리된 데이터의 문서 길이를 분석하여 OpenAI 임베딩 생성 시 청킹이 필요한지 판단합니다.

**분석 기준**:
- OpenAI `text-embedding-3-small` 모델: 최대 8191 토큰 지원
- 한국어 토큰 추정: 평균 1자 = 1.3 토큰
- 안전 마진: 8000 토큰 이하 권장

**분석 스크립트**: `data-preprocessing_dev/preprocessing/tedicard/00_analyze_document_lengths.py`

---

## 2. 데이터 유형별 분석

### 2.1 service_guide_documents (서비스 가이드 문서)

**특성**:
- 통합된 문서 (예: "신용도 관리방법_merged"): 약 2000-3000자
- 개별 문서: 약 500-1500자
- 평균 길이: 약 1000자 (1300 토큰)

**결론**: ✅ **청킹 불필요**
- 모든 문서가 8000 토큰 제한 내
- 하나의 문서가 하나의 의미 단위로 적절한 크기

### 2.2 notices (공지사항)

**특성**:
- 공지사항 내용: 약 500-2000자
- 평균 길이: 약 800자 (1040 토큰)

**결론**: ✅ **청킹 불필요**
- 모든 공지사항이 8000 토큰 제한 내
- 하나의 공지사항이 하나의 의미 단위

### 2.3 card_products (카드 상품)

**특성**:
- `full_content`: 일부 5000-10000자 가능
- 하지만 `full_content`는 **임베딩 생성 시 사용하지 않음**
- 임베딩 생성 대상: `main_benefits` (약 500자)

**결론**: ✅ **청킹 불필요**
- 임베딩 생성 대상 필드가 짧음
- `full_content`는 `metadata.full_content`에만 저장

---

## 3. 하나카드 상담 데이터와의 비교

### 3.1 하나카드 상담 데이터

- **청킹 여부**: 청킹을 고려하지 않았음
- **이유**: 
  - 상담 전문은 일반적으로 짧음
  - 의미 단위로 이미 분리되어 있음
  - 각 상담이 독립적인 문서 단위

### 3.2 테디카드 데이터

- **서비스 가이드**: 통합된 문서도 3000자 이하
- **공지사항**: 2000자 이하
- **카드 상품**: 임베딩 대상 필드가 짧음

**결론**: **하나카드와 동일하게 청킹 불필요**

---

## 4. 최종 결론

### 4.1 청킹 전략

**✅ 청킹 없이 진행**

**근거**:
1. 모든 문서가 OpenAI 임베딩 제한(8191 토큰) 내
2. 하나의 문서가 하나의 의미 단위로 적절한 크기
3. 하나카드 상담 데이터와 유사한 특성
4. 청킹 시 의미 손실 가능성

### 4.2 예외 처리

**향후 긴 문서가 추가되는 경우**:
- 개별 문서만 청킹 처리
- 의미 단위로 분할 (예: 섹션별, 조항별)
- 청킹된 문서는 `metadata.chunked_from` 필드로 원본 추적

### 4.3 권장 사항

1. **현재 단계**: 청킹 없이 진행
2. **모니터링**: 임베딩 생성 시 토큰 수 로그 확인
3. **향후 개선**: 필요 시 개별 문서만 청킹하는 유틸리티 함수 추가
