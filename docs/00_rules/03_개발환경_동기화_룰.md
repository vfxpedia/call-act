# 개발 환경 동기화 규칙 (Dev/Prod Sync Rules)

**작성일**: 2026-01-13  
**대상**: 프로젝트 개발자 및 LLM  
**목적**: `*_dev` 폴더에서 `*` 폴더로 동기화 시 발생할 수 있는 경로 오류 방지

---

## ⚠️ 중요: 문제 발생 원인

### 발생했던 문제

1. **경로 참조 오류**: `backend_dev`에서 `backend`로 복사 시 `backend_dev` 경로가 그대로 남아있음
2. **설정 파일 기본값 오류**: `config.py`의 `ENV_TYPE` 기본값이 `'dev'`로 설정되어 팀 레포에 들어감
3. **문서 경로 하드코딩**: README 등 문서에 `backend_dev` 경로가 하드코딩되어 있음
4. **스크립트 출력 경로 오류**: `data-preprocessing_dev` 경로가 프로덕션 스크립트에 그대로 남아있음

### 근본 원인

- `*_dev` → `*` 동기화 시 경로 참조 수정 절차가 명확하지 않았음
- 동기화 체크리스트가 없어서 누락 발생
- LLM이 동기화 시 경로를 자동으로 수정하지 못함

---

## 1. 기본 원칙

### 1.1 개발 환경 구조

```
call-act/ (메인 레포 - 개인 Git)
├── data-preprocessing/ (서브모듈 - 팀 레포) ⭐ 프로덕션
├── backend/ (서브모듈 - 팀 레포) ⭐ 프로덕션
├── frontend/ (서브모듈 - 팀 레포) ⭐ 프로덕션
├── data-preprocessing_dev/ (개인 개발) 🔧 개발
├── backend_dev/ (개인 개발) 🔧 개발
└── frontend_dev/ (개인 개발) 🔧 개발
```

### 1.2 핵심 원칙

1. **모든 개발은 `*_dev` 폴더에서만 진행**
2. **테스트 완료 후 `*` 폴더로 복사하여 팀과 공유**
3. **동기화 시 반드시 경로 참조를 프로덕션 경로로 수정**
4. **동기화 후 반드시 체크리스트 확인**

---

## 2. 동기화 전 체크리스트

### 2.1 필수 확인 사항

- [ ] `*_dev` 폴더에서 테스트 완료
- [ ] 모든 기능이 정상 동작하는지 확인
- [ ] 파일 목록 확인 (복사할 파일들)

### 2.2 경로 참조 확인 사항

동기화 전 `*_dev` 폴더에서 다음을 확인:

- [ ] 하드코딩된 경로 확인
  - `backend_dev` → `backend`로 변경 예정
  - `data-preprocessing_dev` → `data-preprocessing`으로 변경 예정
  - `preprocessing` → `preprocess` (폴더 구조에 맞춰)
- [ ] `config.py` 파일 확인
  - `ENV_TYPE` 기본값: `'dev'` (개발 환경)
  - 프로덕션에서는 `'prod'`로 변경 필요
- [ ] 문서 파일 확인
  - README, 가이드 문서의 경로 예시 확인
  - `backend_dev` → `backend`로 변경 필요
  - `data-preprocessing_dev` → `data-preprocessing`으로 변경 필요

## 3. 동기화 절차

### 3.1 파일 복사

1. **파일 복사**:
   ```bash
   # 예시: backend_dev → backend
   cp -r backend_dev/app/db/scripts/*.py backend/app/db/scripts/
   cp -r backend_dev/docker/* backend/docker/
   ```

2. **문서 복사**:
   ```bash
   cp -r backend_dev/docs/*.md backend/docs/
   ```

### 3.2 경로 수정 (필수)

**⚠️ 중요**: 가급적으로 경로를 하드코딩하지 말고 `config.py`를 사용하여 환경 변수로 관리하는 것을 권장합니다.

#### 3.2.1 Python 스크립트 경로 수정

**권장 방법: config.py 사용** (환경 변수로 경로 전환):

```python
# ✅ 권장: config.py 사용
from config import OUTPUT_DIR, DATA_DIR

# config.py에서 ENV_TYPE에 따라 자동으로 경로 설정
# 프로덕션: ENV_TYPE='prod' → data-preprocessing/data/teddycard
# 개발: ENV_TYPE='dev' → data-preprocessing_dev/data/teddycard
```

**config.py 예시**:
```python
# data-preprocessing/preprocess/teddycard/config.py
import os
from pathlib import Path
from typing import Literal

# 환경 타입: 환경 변수 또는 기본값
ENV_TYPE: Literal['dev', 'prod'] = os.getenv('PREPROCESSING_ENV', 'prod').lower()

PROJECT_ROOT = Path(__file__).resolve().parents[3]  # call-act

# 환경 타입에 따라 경로 자동 설정
if ENV_TYPE == 'dev':
    DATA_DIR = PROJECT_ROOT / "data-preprocessing_dev"
    OUTPUT_DIR = DATA_DIR / "data" / "teddycard"
else:  # prod
    DATA_DIR = PROJECT_ROOT / "data-preprocessing"
    OUTPUT_DIR = DATA_DIR / "data" / "teddycard"
```

**하드코딩된 경로 수정** (config.py 사용 불가능한 경우):
```python
# ❌ 잘못된 예시 (개발 환경)
BASE_DIR = Path(__file__).parent.parent.parent.parent
OUTPUT_DIR = BASE_DIR / "data-preprocessing_dev" / "data" / "teddycard"

# ✅ 올바른 예시 (프로덕션 환경)
BASE_DIR = Path(__file__).parent.parent.parent.parent
OUTPUT_DIR = BASE_DIR / "data-preprocessing" / "data" / "teddycard"
```

**config.py 기본값 수정**:
```python
# ❌ 잘못된 예시 (개발 환경)
ENV_TYPE: Literal['dev', 'prod'] = os.getenv('PREPROCESSING_ENV', 'dev').lower()

# ✅ 올바른 예시 (프로덕션 환경)
ENV_TYPE: Literal['dev', 'prod'] = os.getenv('PREPROCESSING_ENV', 'prod').lower()
```

#### 3.2.2 문서 경로 수정

**README, 가이드 문서 수정**:
```markdown
<!-- ❌ 잘못된 예시 -->
```bash
cd backend_dev/app/db/scripts
python 02_generate_embeddings_hana.py
```

<!-- ✅ 올바른 예시 -->
```bash
cd backend/app/db/scripts
python 02_generate_embeddings_hana.py
```
```

**파일 구조 예시 수정**:
```markdown
<!-- ❌ 잘못된 예시 -->
```
backend_dev/app/db/scripts/
├── 01_setup_db.py
└── 02_generate_embeddings_hana.py
```

<!-- ✅ 올바른 예시 -->
```
backend/app/db/scripts/
├── 01_setup_db.py
└── 02_generate_embeddings_hana.py
```
```

#### 3.2.3 주석 설명 수정

**개발 환경 언급은 유지하되, 프로덕션 경로로 수정**:
```python
# ✅ 올바른 예시
# 환경 변수 로드
# 1. 로컬 .env 파일 우선 (backend/app/db/scripts/.env)
# 2. 프로젝트 루트 .env 파일 (override=False로 이미 로드된 값은 유지)
# 참고: 개인 개발 환경(backend_dev)에서는 backend_dev/app/db/scripts/.env가 우선 사용됨
```

## 4. 동기화 후 체크리스트

**⚠️ 중요**: "점검 완료"라고 말하기 전에 3단계 검증을 모두 완료해야 합니다.  
**상세 가이드**: [점검 프로세스 분석](./04_점검_프로세스_분석.md) 참조

### 4.1 1단계: 표면적 검증

**경로 문자열 확인**:
- [ ] **grep으로 경로 확인**:
  ```bash
  # backend 폴더에서
  grep -r "backend_dev" backend/
  grep -r "data-preprocessing_dev" backend/
  
  # data-preprocessing 폴더에서
  grep -r "data-preprocessing_dev" data-preprocessing/preprocess/
  grep -r "preprocessing/output" data-preprocessing/  # 이전 구조 확인
  ```

- [ ] **config.py 기본값 확인**:
  ```python
  # data-preprocessing/preprocess/teddycard/config.py
  ENV_TYPE: Literal['dev', 'prod'] = os.getenv('PREPROCESSING_ENV', 'prod').lower()
  #                                                                   ^^^^^ 프로덕션은 'prod'
  ```

- [ ] **문서 경로 문자열 확인**:
  ```bash
  grep -r "backend_dev" backend/docs/
  grep -r "data-preprocessing_dev" data-preprocessing/docs/
  ```

### 4.2 2단계: 실제 검증 (필수)

**⚠️ 1단계만으로는 불충분합니다. 반드시 2단계를 수행해야 합니다.**

- [ ] **문서 경로 정확성 확인**:
  ```bash
  # 문서 내 상대 경로가 실제로 작동하는지 확인
  # 예: backend/docs/통합_DB_설정_가이드.md에서
  # ../../../docs/00_git/ → 실제 파일 존재 여부 확인
  ls docs/00_git/Git_LFS_설치_및_사용_가이드.md
  ```

- [ ] **README 내용 검증**:
  ```bash
  # README 내용이 실제 상황과 일치하는지 확인
  # 예: 임베딩 파일이 이미 있으면 → 선택 사항으로 표시되어야 함
  ls data-preprocessing/data/hana/hana_vectordb_with_embeddings.json
  # 파일이 있으면 README에서 임베딩 생성 단계는 선택 사항이어야 함
  ```

- [ ] **파일 필요성 검증**:
  ```bash
  # 각 파일이 프로덕션 환경에 필요한지 확인
  # 불필요한 파일: *.log, *_checkpoint.json, *.bat (개발 도구)
  # .gitignore에 포함되어 있는지 확인
  cat backend/.gitignore
  ```

- [ ] **config.py 규칙 명시 확인**:
  ```bash
  # 개발 룰 문서에 config.py 사용 규칙이 명시되어 있는지 확인
  grep -i "config.py\|우선\|권장" docs/00_rules/03_개발환경_동기화_룰.md
  ```

### 4.2 정상 동작 확인

- [ ] 경로 참조가 모두 프로덕션 경로로 수정되었는지 확인
- [ ] `config.py` 기본값이 `'prod'`로 설정되었는지 확인
- [ ] 문서의 경로 예시가 프로덕션 경로로 수정되었는지 확인
- [ ] 주석에 개발 환경 설명이 포함되어 있는지 확인 (참고용)

## 5. 경로 참조 규칙

### 5.0 기본 원칙: config.py 우선 사용

**가급적으로 경로를 하드코딩하지 말고 `config.py`를 사용하여 환경 변수로 관리합니다.**

**이유**:
- 동기화 시 경로 수정 불필요
- 환경 변수(`PREPROCESSING_ENV`)로 쉽게 전환 가능
- 하드코딩 경로 오류 방지

**사용 방법**:
```python
# ✅ 권장: config.py 사용
from config import OUTPUT_DIR, DATA_DIR

# ❌ 지양: 하드코딩
OUTPUT_DIR = BASE_DIR / "data-preprocessing" / "data" / "teddycard"
```

**예외**: 양방향 지원 스크립트(프로덕션 경로 우선, 개발 경로 대체)는 하드코딩 허용

### 5.1 허용되는 경로 참조

**프로덕션 환경 (`*` 폴더)**:
- ✅ `backend/app/db/scripts/` (절대 경로)
- ✅ `data-preprocessing/data/teddycard/` (절대 경로)
- ✅ `BASE_DIR / "data-preprocessing" / "data" / "teddycard"` (Python Path 객체)
- ✅ `ENV_TYPE='prod'` (config.py 기본값)

**개발 환경 (`*_dev` 폴더)**:
- ✅ `backend_dev/app/db/scripts/` (절대 경로)
- ✅ `data-preprocessing_dev/data/teddycard/` (절대 경로)
- ✅ `BASE_DIR / "data-preprocessing_dev" / "data" / "teddycard"` (Python Path 객체)
- ✅ `ENV_TYPE='dev'` (config.py 기본값)

### 5.2 금지되는 경로 참조

**프로덕션 환경에서 절대 사용 금지**:
- ❌ `backend_dev/` (개발 환경 경로)
- ❌ `data-preprocessing_dev/` (개발 환경 경로)
- ❌ `preprocessing/output/` (이전 폴더 구조)
- ❌ `ENV_TYPE='dev'` (프로덕션 기본값)

### 5.3 개발 환경 경로를 참조해야 하는 경우

**프로덕션 스크립트에서 개발 환경 경로를 참조해야 하는 경우**:

1. **양방향 지원 스크립트** (예: `backend/app/db/scripts/01_setup_callact_db.py`):
   ```python
   # ✅ 올바른 예시: 프로덕션 우선, 개발 환경 대체
   DATA_DIR_PROD = BASE_DIR / "data-preprocessing" / "data" / "teddycard"
   DATA_DIR_DEV = BASE_DIR / "data-preprocessing_dev" / "data" / "teddycard"
   
   # 프로덕션 경로 우선 확인
   if DATA_DIR_PROD.exists():
       DATA_DIR = DATA_DIR_PROD
   else:
       DATA_DIR = DATA_DIR_DEV  # 개발 환경 대체
   ```

2. **문서에서 개발 환경 설명**:
   ```markdown
   **참고**: 개인 개발 환경(`backend_dev`)에서는 `backend_dev/app/db/scripts/.env`가 우선 사용됩니다.
   ```

## 6. LLM 동기화 작업 시 규칙

### 6.1 필수 작업 순서

LLM이 `*_dev` → `*` 동기화 작업을 수행할 때:

1. **파일 복사 전**:
   - `*_dev` 폴더에서 경로 참조 확인
   - 수정해야 할 경로 목록 작성

2. **파일 복사**:
   - 필요한 파일만 선택적으로 복사
   - 전체 폴더 복사는 지양 (불필요한 파일 포함 방지)

3. **경로 수정**:
   - 하드코딩된 경로 수정
   - `config.py` 기본값 수정
   - 문서 경로 예시 수정

4. **검증**:
   - grep으로 경로 확인
   - 체크리스트 확인

### 6.2 자동 검증 명령어

동기화 후 다음 명령어로 자동 검증:

```bash
# backend 폴더 확인
cd backend
grep -r "backend_dev" --include="*.py" --include="*.md" . || echo "✅ backend_dev 경로 없음"
grep -r "data-preprocessing_dev" --include="*.py" --include="*.md" . | grep -v "DATA_DIR_DEV\|KEYWORDS_DICT_DIR_DEV" || echo "✅ 하드코딩된 data-preprocessing_dev 경로 없음"

# data-preprocessing 폴더 확인
cd ../data-preprocessing
grep -r "data-preprocessing_dev" --include="*.py" --include="*.md" preprocess/ | grep -v "DATA_DIR\|ENV_TYPE\|개인 개발\|참고" || echo "✅ 하드코딩된 data-preprocessing_dev 경로 없음"

# config.py 기본값 확인
python -c "import sys; sys.path.insert(0, 'preprocess/teddycard'); from config import ENV_TYPE; print(f'✅ ENV_TYPE 기본값: {ENV_TYPE}' if ENV_TYPE == 'prod' else f'❌ ENV_TYPE 기본값이 {ENV_TYPE}입니다. prod여야 합니다.')"
```

## 8. 트러블슈팅

### 8.1 문제: 동기화 후 경로 오류 발생

**증상**: 프로덕션 환경에서 스크립트 실행 시 경로 오류

**해결**:
1. grep으로 오류 경로 확인
2. 프로덕션 경로로 수정
3. 다시 검증

### 8.2 문제: config.py 기본값이 'dev'로 되어 있음

**증상**: 프로덕션 환경에서 `ENV_TYPE` 기본값이 `'dev'`

**해결**:
1. `config.py` 확인
2. `ENV_TYPE` 기본값을 `'prod'`로 수정
3. 다시 검증

### 8.3 문제: 문서에 잘못된 경로가 있음

**증상**: 문서 예시가 `backend_dev` 경로를 사용

**해결**:
1. 문서 내 경로 검색
2. 프로덕션 경로로 수정
3. 개발 환경 설명은 주석으로 유지
