## 목적
CALL-ACT의 핵심 차별화 기능인 **통화 중 고객 감정 분석 및 상담 후 시각화** 기능 구현을 위한 감정 분석 모델, API, 데이터셋 조사 및 기술 실현 가능성 검증

## 배경
- **핵심 차별점**: 통화 중 백그라운드로 고객 감정을 분석하여 상담 종료 후 시각화
- **목표**: 상담사 보호, 객관적 평가 근거 제공, 악성 민원 대응
- **요구사항**:
  - 통화 중 실시간 분석 (백그라운드)
  - 음성 톤 + 텍스트 기반 멀티모달 분석
  - 한국어 특화 감정 인식
  - 분노, 평온, 대기, 만족 등 다중 감정 분류

## 1. 감정 분석 접근 방식

### 1.1 두 가지 분석 방법

| 방식 | 입력 데이터 | 장점 | 단점 | 적합성 |
|------|-----------|------|------|--------|
| **음성 기반 (Speech Emotion Recognition, SER)** | 음성 파형, 톤, 피치, 에너지 | 비언어적 감정 포착 (화남, 흥분 등) | 모델 복잡도 높음, 한국어 데이터 부족 | ⭐⭐⭐⭐ |
| **텍스트 기반 (Text Emotion Recognition)** | STT 변환된 텍스트 | 모델 성숙도 높음, 한국어 BERT 활용 가능 | 비언어적 감정 놓칠 수 있음 | ⭐⭐⭐⭐⭐ |
| **멀티모달 (Multimodal)** | 음성 + 텍스트 결합 | 최고 정확도 | 구현 복잡도 매우 높음 | ⭐⭐⭐ |

**권장 방식**: **텍스트 기반 우선 구현 + 음성 기반 추가** (단계적 접근)

## 2. 한국어 감정 분석 모델 및 API 조사

### 2.1 상용 API 서비스

#### 2.1.1 네이버 CLOVA Sentiment API
- **URL**: https://www.ncloud.com/product/aiService/clovaSentiment
- **제공 기능**:
  - 한국어 텍스트 감정 분석
  - Positive / Negative / Neutral 3단계 분류
  - 신뢰도 점수 제공
- **장점**:
  - ✅ 한국어 특화
  - ✅ 네이버 빅데이터 학습
  - ✅ 안정적인 서비스
- **단점**:
  - ⚠️ 3단계 분류만 제공 (분노, 평온 등 세부 감정 불가)
  - ⚠️ 음성 톤 분석 불가 (텍스트만)
- **비용**: API 호출당 과금 (약 0.01원/건)
- **적합성**: ⭐⭐⭐ (세부 감정 분류 부족)

#### 2.1.2 AWS Comprehend (한국어 지원)
- **URL**: https://aws.amazon.com/comprehend/
- **제공 기능**:
  - 감정 분석 (Positive, Negative, Neutral, Mixed)
  - 한국어 포함 다국어 지원
- **장점**:
  - ✅ AWS 생태계 통합 용이
  - ✅ 대규모 처리 가능
- **단점**:
  - ⚠️ 한국어 정확도 네이버 대비 낮음
  - ⚠️ 4단계 분류만 제공
- **비용**: 100자당 $0.0001
- **적합성**: ⭐⭐

#### 2.1.3 구글 Cloud Natural Language API
- **URL**: https://cloud.google.com/natural-language
- **제공 기능**:
  - Sentiment Analysis (점수: -1.0 ~ +1.0)
  - 한국어 지원
- **장점**:
  - ✅ Google의 강력한 NLP 기술
  - ✅ 연속적인 감정 점수 제공
- **단점**:
  - ⚠️ 한국어 콜센터 도메인 특화 부족
  - ⚠️ 세부 감정 카테고리 없음
- **비용**: 1,000 units당 $1.00
- **적합성**: ⭐⭐⭐

### 2.2 오픈소스 모델

#### 2.2.1 KoBERT (SKT Brain)
- **URL**: https://github.com/SKTBrain/KoBERT
- **제공 기능**:
  - 한국어 BERT 사전학습 모델
  - 감정 분류 Fine-tuning 가능
- **장점**:
  - ✅ 한국어 특화
  - ✅ 무료 오픈소스
  - ✅ 커스터마이징 가능 (분노, 평온, 대기, 만족 등 원하는 카테고리)
- **단점**:
  - ⚠️ 직접 학습 데이터 필요
  - ⚠️ 모델 학습 및 튜닝 필요
- **적합성**: ⭐⭐⭐⭐⭐ (가장 유연)

#### 2.2.2 KcELECTRA (Beomi)
- **URL**: https://github.com/Beomi/KcELECTRA
- **제공 기능**:
  - 한국어 ELECTRA 모델
  - 감정 분류 태스크 Fine-tuning 가능
- **장점**:
  - ✅ KoBERT보다 경량화
  - ✅ 빠른 추론 속도
- **단점**:
  - ⚠️ 학습 데이터 필요
- **적합성**: ⭐⭐⭐⭐⭐

#### 2.2.3 koGPT2 / polyglot-ko (EleutherAI)
- **URL**: https://github.com/EleutherAI/polyglot
- **제공 기능**:
  - 한국어 생성형 LLM
  - Few-shot / Zero-shot 감정 분류 가능
- **장점**:
  - ✅ 학습 데이터 없이도 사용 가능 (프롬프트 엔지니어링)
  - ✅ 유연한 감정 카테고리 정의
- **단점**:
  - ⚠️ 추론 속도 느림
  - ⚠️ 정확도 BERT 대비 낮을 수 있음
- **적합성**: ⭐⭐⭐

## 4. 구현 전략 및 로드맵

### 4.1 단계적 구현 계획

#### **Phase 1: 텍스트 기반 감정 분석 (MVP)**
**기간**: 2주
**목표**: 상담 종료 후 STT 텍스트 기반 감정 분석

| 항목 | 세부 내용 |
|------|-----------|
| 모델 | KoBERT Fine-tuning |
| 데이터셋 | AI Hub 감정 대화 데이터셋 (38,000건) |
| 감정 카테고리 | 분노, 평온, 대기, 만족, 불만, 중립 (6가지) |
| 정확도 목표 | F1-Score > 0.75 |
| 통합 방식 | STT 출력 → 감정 분석 모델 → 감정 라벨 저장 |

**구현 단계**:
1. AI Hub 데이터셋 다운로드 및 전처리
2. KoBERT 모델 Fine-tuning (Google Colab / AWS)
3. 6가지 감정 카테고리 분류 학습
4. FastAPI로 감정 분석 API 구축
5. STT 출력과 연동 테스트

---

#### **Phase 2: 음성 톤 기반 감정 분석 추가**
**기간**: 2주
**목표**: 음성 특징 (톤, 피치, 에너지) 기반 감정 분석 추가

| 항목 | 세부 내용 |
|------|-----------|
| 도구 | openSMILE + Wav2Vec2 |
| 데이터셋 | AI Hub 감정 음성 데이터셋 (50,000건) |
| 특징 추출 | MFCC, 피치, 에너지, 발화 속도 |
| 정확도 목표 | F1-Score > 0.70 |

**구현 단계**:
1. openSMILE로 음성 특징 추출
2. Wav2Vec2 Fine-tuning
3. 감정 분류 헤드 추가
4. 텍스트 기반 결과와 앙상블

---

#### **Phase 3: 멀티모달 감정 분석 (최종)**
**기간**: 1주
**목표**: 텍스트 + 음성 결합하여 최고 정확도 달성

| 항목 | 세부 내용 |
|------|-----------|
| 방식 | Weighted Ensemble (텍스트 70% + 음성 30%) |
| 정확도 목표 | F1-Score > 0.85 |

---

## 5. 감정 카테고리 정의 (카드사 콜센터 특화)

### 5.1 6가지 감정 카테고리

| 감정 | 설명 | 탐지 키워드 예시 | UI 색상 |
