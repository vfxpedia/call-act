## 목적
CALL-ACT RAG 시스템 구축을 위한 카드사 공개 문서 데이터 조사 및 수집 가능성 검증

## 배경
- RAG 시스템은 충분한 양의 고품질 문서 데이터 필요
- 카드사 약관, FAQ, 상품 설명서 등 공개 데이터 활용
- 법적 문제 없이 크롤링/수집 가능한 데이터 소스 확인 필요

## 1. 공개 데이터 소스 조사

### 1.1 금융감독원 전자공시시스템 (DART)
- **URL**: https://dart.fss.or.kr
- **제공 데이터**:
  - 카드사 사업보고서
  - 공시 정보
  - 약관 변경 공시
- **접근 방법**: Open API 제공
- **데이터 형식**: XML, JSON
- **수집 가능성**: ✅ 공개 API, 법적 문제 없음
- **예상 데이터량**: 대형 카드사 기준 약 100~200 페이지 분량
- **업데이트 주기**: 분기별/반기별

### 1.2 여신금융협회 (CREFIA)
- **URL**: https://www.crefia.or.kr
- **제공 데이터**:
  - 카드 상품 정보
  - 금융 소비자 보호 안내
  - 카드 이용 가이드
- **접근 방법**: 웹 크롤링
- **데이터 형식**: HTML
- **수집 가능성**: ⚠️ robots.txt 확인 필요
- **예상 데이터량**: 약 50~100 페이지

## 3. 데이터 수집 방법론

### 3.1 크롤링 도구
- **Python Selenium**: 동적 웹페이지 크롤링
- **BeautifulSoup**: HTML 파싱
- **Scrapy**: 대규모 크롤링 프레임워크

### 3.2 법적 검토 사항
- ✅ **공개 API 사용**: DART 등 공식 API는 법적 문제 없음
- ⚠️ **웹 크롤링**: robots.txt 준수 필수
- ⚠️ **저작권**: 금융사 저작권 확인 필요
- ✅ **교육/연구 목적**: 비상업적 연구 목적 명시

### 3.3 데이터 전처리 계획
1. **PDF 텍스트 추출**: PyPDF2, pdfplumber
2. **HTML → 텍스트 변환**: BeautifulSoup
3. **텍스트 정제**:
   - 특수문자 제거
   - 불필요한 공백 제거
   - 섹션 구분 태깅
4. **구조화**:
   - 카드명, 혜택, 수수료, 약관 등 카테고리 분류
   - 메타데이터 추가 (출처, 수집일, 카드사명)

## 4. 예상 데이터량 및 벡터 DB 구성

### 4.1 수집 목표
- **카드 상품 정보**: 500개 이상
- **FAQ 항목**: 2,000개 이상
- **약관 문서**: 50개 이상
- **총 텍스트량**: 약 10MB ~ 50MB (압축 전)

### 4.2 Vector DB 설계 (예상)
- **Embedding 모델**: OpenAI text-embedding-3-large
- **Vector 차원**: 3072
- **청크 크기**: 500 토큰 (약 300~400 한글 글자)
- **오버랩**: 50 토큰
- **예상 벡터 수**: 20,000 ~ 50,000개

2. **주요 5개 카드사 크롤링** (robots.txt 준수)
3. **법적 검토 병행** (저작권, 이용약관)
4. **2주 내 샘플 데이터 수집 완료** 목표
