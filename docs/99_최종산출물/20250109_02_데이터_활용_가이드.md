## 1. 목적 및 개요

### 1.1 문서 목적

본 문서는 CALL-ACT 시스템의 데이터베이스와 애플리케이션 간 연동 방법을 상세히 안내합니다. 백엔드 및 프론트엔드 개발자가 화면별로 필요한 데이터를 효율적으로 조회하고 활용할 수 있도록 다음 내용을 제공합니다:

- **화면별 데이터 활용 방식**: 각 화면에서 필요한 데이터와 쿼리 예시
- **API 엔드포인트 명세**: 요청/응답 구조 및 데이터 흐름
- **전처리 데이터 스키마**: 신한카드 약관 및 특화카드 데이터 구조
- **외부 시스템 연동**: CRM, OpenAI, STT 시스템 연동 방법
- **성능 최적화 전략**: 캐싱, 쿼리 최적화, 벡터 검색 튜닝

### 1.2 대상 독자

- 백엔드 개발자 (FastAPI, PostgreSQL, pgvector)
- 프론트엔드 개발자 (React, TypeScript)
- 시스템 아키텍트
- 데이터 엔지니어

### 1.3 시스템 구성 요약

CALL-ACT 시스템은 **3개의 논리적 데이터베이스**를 활용하여 상담사를 지원합니다:

| DB 이름 | 주요 내용 | 활용 화면 |
|---------|----------|----------|
| **카드 정보 DB** | 카드 상품, 혜택, 수수료, 포인트 정책 | CSU, 대시보드 |
| **카드사 이용 안내 DB** | 공지사항, FAQ, 신용카드 사용 가이드, 소비자 주의 경보 | CSU, 대시보드 |
| **상담 사례 DB** | 과거 상담 데이터, 교육 시나리오, 우수 사례 | CSU, ACW, EDU, 대시보드 |

각 DB는 **RDB(PostgreSQL) + VectorDB(pgvector)** 하이브리드 구조로 설계되어, 구조화된 데이터 조회와 AI 기반 유사도 검색을 모두 지원합니다.

## 2. 화면별 데이터 활용 방식

### 2.1 실시간 상담 페이지 (CSU)

#### 2.1.1 페이지 개요

실시간 상담 페이지는 상담사가 고객과 전화 통화를 진행하는 동안 필요한 정보를 실시간으로 제공하는 핵심 화면입니다. STT(Speech-to-Text) 기반 키워드 추출과 RAG(Retrieval-Augmented Generation) 검색을 통해 관련 문서를 자동으로 칸반보드에 표시합니다.

#### 2.1.2 필요한 데이터

| 데이터 종류 | 데이터 소스 | 용도 |
|-----------|-----------|------|
| 고객 정보 | 외부 CRM API | 좌측 사이드바에 고객 기본 정보 표시 |
| 최근 상담 내역 | `consultations` 테이블 | 좌측 사이드바에 최근 5건 상담 이력 표시 |
| STT 키워드 | STT 시스템 → `stt_keywords` 테이블 | 실시간 음성 인식 결과 |
| 현재 상황 칸반보드 | `service_guide_documents`, `consultation_documents` VectorDB | STT 키워드 기반 관련 문서 표시 |
| 다음 단계 칸반보드 | `service_guide_documents`, `consultation_documents` VectorDB | 예상되는 다음 단계 정보 선제적 표시 |
| AI 검색 어시스턴트 | OpenAI GPT-4 + RAG 검색 | 상담사의 질문에 즉시 답변 |
| 상담 메모 | 상담 진행 중 입력 (실시간 저장) | 후처리 페이지로 자동 전달 |

#### 2.1.3 데이터 흐름

```
1. 고객 전화 인입
   ↓
2. CRM API 호출: 고객 정보 조회
   ↓
3. STT 시스템: 음성 → 텍스트 변환 (실시간)
   ↓
4. 키워드 추출: ["카드분실", "해외결제", "수수료문의"]
   ↓
5. VectorDB 검색: 키워드 기반 유사 문서 검색 (3개 DB 모두)
   ↓
6. 칸반보드 표시:
   - 현재 상황: Top 2 관련 문서
   - 다음 단계: Top 2 예상 문서
   ↓
7. 상담사가 칸반보드 참고하여 상담 진행
   ↓
8. 상담 메모 실시간 저장 (consultation_summaries.memo)
```

##### STT 키워드 기반 VectorDB 검색

```sql
-- pgvector를 사용한 유사도 검색
-- 1. 키워드를 임베딩 벡터로 변환 (OpenAI API)
-- 2. VectorDB에서 코사인 유사도 검색

-- 서비스 가이드 문서 검색
SELECT
    id,
    title,
    content,
    metadata,
    1 - (embedding <=> '[임베딩 벡터]') AS similarity_score
FROM service_guide_documents
WHERE metadata->>'source_type' IN ('sinhan_terms', 'special_card')
ORDER BY embedding <=> '[임베딩 벡터]'
LIMIT 5;

-- 상담 사례 문서 검색
SELECT
    cd.id,
    cd.title,
    cd.content,
    cd.metadata,
    c.consultation_category,
    c.quality_score,
    1 - (cd.embedding <=> '[임베딩 벡터]') AS similarity_score
FROM consultation_documents cd
JOIN consultations c ON cd.consultation_id = c.id
WHERE cd.is_best_practice = true
ORDER BY cd.embedding <=> '[임베딩 벡터]'
LIMIT 5;
```

**벡터 검색 파라미터**:
- 임베딩 모델: OpenAI `text-embedding-3-small` (1536차원)
- 유사도 측정: 코사인 유사도 (Cosine Similarity)
- Top-K: 각 DB당 5개 문서, 전체 10개 문서 중 상위 4개 표시

#### 2.1.6 프론트엔드 데이터 구조

**TypeScript Interfaces**:

```typescript
// 고객 정보
interface CustomerInfo {
  customerId: string;
  name: string;
  phone: string;
  birthdate: string;
  address: string;
}

// 최근 상담 내역
interface RecentConsultation {
  id: string;
  title: string;
  date: string;
  time: string;
  category: 'card_loss' | 'overseas_payment' | 'fee_inquiry' | 'other';
  status: 'completed' | 'in_progress' | 'incomplete';
}

// 칸반보드 카드
interface KanbanCard {
  id: string;
  title: string;
  keywords: string[];
  content: string;
  relevanceScore: number;
  sourceType: 'sinhan_terms' | 'past_consultation' | 'best_practice' | 'special_card';
  category?: string;
}

// RAG 검색 응답
interface RAGSearchResponse {
  currentSituation: KanbanCard[];
  nextStep: KanbanCard[];
  guidanceScript: string;
}

// AI 어시스턴트 메시지
interface ChatMessage {
  type: 'user' | 'ai';
  text: string;
  timestamp: string;
  references?: {
    documentId: string;
    title: string;
    snippet: string;
  }[];
}
```

### 2.2 상담 후처리 페이지 (ACW)

#### 2.2.1 페이지 개요

상담 후처리 페이지(After Call Work)는 상담사가 통화 종료 후 상담 내용을 정리하고 후속 조치를 기록하는 화면입니다. AI가 생성한 상담 요약본을 검토하고, 유사한 과거 사례를 참고하여 효율적으로 후처리를 완료할 수 있습니다.

#### 2.2.2 필요한 데이터

| 데이터 종류 | 데이터 소스 | 용도 |
|-----------|-----------|------|
| 상담 전문 | `consultation_transcripts` 테이블 | 좌측에 채팅 형태로 통화 내용 표시 |
| 감정 분석 | `consultation_feedback` 테이블 | 상담 중 고객 감정 변화 그래프 표시 |
| 품질 피드백 | `consultation_feedback` 테이블 | 상담 품질 레이더 차트 표시 |
| 현재 상담 케이스 | `consultations`, AI 생성 요약 | 현재 상담의 요약 정보 |
| 유사 사례 참고 | `consultation_documents` VectorDB | 과거 유사 사례 검색하여 후처리 방법 참고 |
| AI 상담 요약본 | GPT-4 생성 → `consultation_summaries.ai_summary` | 자동 생성된 상담 요약 (편집 가능) |
| 상담 메모 | CSU에서 자동 전달 | 상담 중 작성한 메모 |

#### 2.2.3 데이터 흐름

```
1. 상담 종료
   ↓
2. 상담 전문(Transcript) RDB 저장
   ↓
3. GPT-4가 전문 분석 → AI 요약 생성
   ↓
4. 감정 분석 결과 저장 (consultation_feedback)
   ↓
5. VectorDB 검색: 유사 사례 검색
   ↓
6. 유사 사례 후처리 방법 표시 (우측 상단 카드)
   ↓
7. 상담사가 AI 생성 문서 검토 및 수정
   ↓
8. 후속 일정, 이관 부서 정보 입력
   ↓
9. 후처리 완료 및 저장
   ↓
10. RDB 저장 + VectorDB 임베딩 생성
```

### 2.3 교육 시뮬레이션 페이지 (EDU)

#### 2.3.1 페이지 개요

교육 시뮬레이션 페이지는 신입 및 기존 상담사가 실제 상담 환경에서 연습할 수 있도록 AI 기반 페르소나를 제공하는 화면입니다. 실제 우수 사례를 기반으로 한 시나리오와 LLM이 생성한 난이도별 시나리오를 통해 체계적인 교육을 받을 수 있습니다.

#### 2.3.2 필요한 데이터

| 데이터 종류 | 데이터 소스 | 용도 |
|-----------|-----------|------|
| 시나리오 목록 | `training_scenarios` 테이블 | 카테고리별 시나리오 선택 화면 |
| 시나리오 스크립트 | `scenario_scripts` 테이블 | 시뮬레이션 진행 중 AI 고객 대사 |
| 평가 기준 | `scenario_evaluation_criteria` 테이블 | 시뮬레이션 평가 기준 |
| 시도 기록 | `scenario_attempts` 테이블 | 과거 시뮬레이션 점수 및 피드백 |
| AI 페르소나 | LLM 동적 생성 | 시뮬레이션용 가상 고객 특성 |
| 시뮬레이션 평가 | GPT-4 평가 + 키워드 분석 | 대화 품질, 후처리 완성도 평가 |

#### 2.3.3 데이터 흐름

```
1. 상담사가 시나리오 선택
   ↓
2. 시나리오 상세 정보 조회 (training_scenarios)
   ↓
3. 시나리오 스크립트 조회 (scenario_scripts)
   ↓
4. AI 페르소나 생성 (LLM)
   ↓
5. /consultation/live 페이지로 이동 (시뮬레이션 모드)
   ↓
6. 시나리오 스크립트에 따라 AI 고객 대화 진행
   ↓
7. 상담사가 응답 입력
   ↓
8. 실시간 평가: 필수 키워드 포함 여부 확인
   ↓
9. 상담 종료 → /acw 페이지로 이동
   ↓
10. 후처리 작성 (실제 환경과 동일)
   ↓
11. 평가 기준에 따라 점수 산출
   ↓
12. 점수 및 피드백 표시
   ↓
13. 시도 기록 저장 (scenario_attempts)
```

### 2.4 대시보드

#### 2.4.1 페이지 개요

대시보드는 상담사가 로그인 후 가장 먼저 보는 메인 화면으로, 오늘의 상담 통계, 최근 상담 내역, 공지사항, 자주 찾는 문의(FAQ), 우수 사례집 등을 한눈에 확인할 수 있습니다.

#### 2.4.2 필요한 데이터

| 데이터 종류 | 데이터 소스 | 용도 |
|-----------|-----------|------|
| 상담 통계 | `consultations` 테이블 집계 | 오늘의 총 상담 건수, 완료, 진행중, 미완료 |
| 상담 내역 | `consultations` 테이블 | 최근 10건 상담 리스트 |
| 이관 내역 | `consultation_summaries` 테이블 | 타 부서로 이관한 상담 내역 |
| 공지사항 | `notices` 테이블 | 상단 고정 공지 및 최근 공지 5건 |
| 자주 찾는 문의 (FAQ) | `frequent_inquiries` 테이블 | 조회수 기준 Top 5 |
| 우수 사례집 | `best_practices` 테이블 | 최근 우수 사례 3건 |
| 금주의 이슈 | RDB 집계 + AI 트렌드 분석 | 이번 주 주요 문의 카테고리 및 트렌드 |

#### 2.4.3 데이터 흐름

```
1. 대시보드 접속
   ↓
2. 상담 통계 조회 (오늘 날짜 기준)
   ↓
3. 최근 상담 내역 조회 (최근 10건)
   ↓
4. 이관 내역 조회 (최근 5건)
   ↓
```

#### 2.4.4 쿼리 예시

##### 상담 통계 조회

```sql
-- 특정 상담사의 오늘 상담 통계
SELECT
    COUNT(*) FILTER (WHERE consultation_status = 'completed') AS completed,
    COUNT(*) FILTER (WHERE consultation_status = 'in_progress') AS in_progress,
    COUNT(*) FILTER (WHERE consultation_status = 'incomplete') AS incomplete,
    COUNT(*) AS total
FROM consultations
WHERE employee_id = 'EMP-001'
  AND call_date = CURRENT_DATE;
```

**응답 예시**:
```json
{
  "total": 127,
  "completed": 95,
  "in_progress": 12,
  "incomplete": 20
}
```

##### 최근 상담 내역 조회

```sql
-- 특정 상담사의 최근 10건 상담 내역
SELECT
    id,
    title,
    consultation_status,
    consultation_category,
    customer_id,
    call_date,
    call_time,
    fcr_achieved
FROM consultations
WHERE employee_id = 'EMP-001'
ORDER BY call_date DESC, call_time DESC
LIMIT 10;
```

##### 자주 찾는 문의 조회

```sql
-- 조회수 기준 Top 5 FAQ
SELECT
    id,
    inquiry_category,
    question,
    answer,
    view_count
FROM frequent_inquiries
WHERE is_active = true
ORDER BY view_count DESC
LIMIT 5;
```

**응답 예시**:
```json
[
  {
    "id": 1,
    "inquiry_category": "fee_inquiry",
    "question": "연회비는 언제 청구되나요?",
    "answer": "카드 발급일 기준 1년 후 청구됩니다...",
    "view_count": 1542
  }
]
```

##### 공지사항 조회

```sql
-- 상단 고정 공지 + 최근 5건 공지사항
SELECT
    id,
    title,
    content,
    notice_category,
    priority,
    is_pinned,
    start_date,
    end_date,
    created_at
FROM notices
WHERE notice_status = 'active'
  AND CURRENT_DATE BETWEEN start_date AND end_date
ORDER BY is_pinned DESC, created_at DESC
LIMIT 6;
```

##### 우수 사례집 조회

```sql
-- 최근 우수 사례 3건
SELECT
    bp.id,
    bp.title,
    bp.best_practice_category,
    bp.key_takeaway,
    bp.views,
    c.id AS consultation_id,
    c.quality_score,
    e.name AS employee_name
FROM best_practices bp
JOIN consultations c ON bp.consultation_id = c.id
JOIN employees e ON c.employee_id = e.id
ORDER BY bp.created_at DESC
LIMIT 3;
```

##### 금주의 이슈 조회

```sql
-- 이번 주 주요 문의 카테고리 집계
SELECT
    consultation_category,
    COUNT(*) AS count
FROM consultations
WHERE call_date >= DATE_TRUNC('week', CURRENT_DATE)
  AND call_date < DATE_TRUNC('week', CURRENT_DATE) + INTERVAL '1 week'
GROUP BY consultation_category
ORDER BY count DESC
LIMIT 5;
```

## 4. 전처리 데이터 스키마

### 4.1 전처리 데이터 개요

CALL-ACT 시스템은 사전에 전처리된 **신한카드 약관 데이터**와 **특화카드 데이터**를 VectorDB에 저장하여 RAG 검색에 활용합니다. 전처리 데이터는 RDB용 JSON과 VectorDB용 JSON으로 분리되어 있으며, 각각 다른 목적으로 사용됩니다.

### 4.2 신한카드 약관 데이터

#### 4.2.1 데이터 개요

- **원본 데이터**: 86개 TXT 파일 (신한카드 공식 약관)
- **전처리 결과**: 988개 청크 (Chunk)
- **적재 위치**:

#### 4.5.2 데이터 검증

```python
import hashlib

def validate_data(data):
    """
    전처리 데이터 검증
    """
    seen_ids = set()
    seen_hashes = set()

    for item in data:
        # ID 중복 검증
        if item['id'] in seen_ids:
            raise ValueError(f"Duplicate ID: {item['id']}")
        seen_ids.add(item['id'])

        # 내용 중복 검증
        content_hash = hashlib.md5(item['content'].encode()).hexdigest()
        if content_hash in seen_hashes:
            print(f"Warning: Duplicate content for ID: {item['id']}")
        seen_hashes.add(content_hash)

        # 필수 필드 검증
        required_fields = ['id', 'title', 'content', 'metadata', 'source_type']
        for field in required_fields:
            if field not in item or not item[field]:
                raise ValueError(f"Missing required field '{field}' for ID: {item['id']}")

    return True
```

```python
def generate_consultation_summary(transcript: list) -> str:
    """
    상담 전문을 분석하여 AI 요약 생성
    """
    # 전문을 텍스트로 변환
    transcript_text = "\n".join([
        f"{msg['speaker']}: {msg['message']}"
        for msg in transcript
    ])

    prompt = f"""
    다음은 카드사 상담 전문입니다. 이를 분석하여 다음 형식으로 요약해주세요:

    문의사항: [고객의 주요 문의 내용]

    처리 결과: [상담사가 처리한 내용 및 고객에게 안내한 사항]

    상담 전문:
    {transcript_text}
    """

    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": "당신은 카드사 상담 전문가입니다. 상담 전문을 간결하고 명확하게 요약하는 역할을 합니다."},
            {"role": "user", "content": prompt}
        ],
        temperature=0.3,
        max_tokens=500
    )

    return response.choices[0].message.content
```

```python
def get_ai_assistant_response(user_message: str, context_documents: list, chat_history: list) -> str:
    """
    상담사의 질문에 대한 AI 답변 생성
    """
    # 컨텍스트 문서를 텍스트로 변환
    context = "\n\n".join([
        f"[문서 {i+1}] {doc['title']}\n{doc['content'][:500]}"
        for i, doc in enumerate(context_documents)

    # 채팅 히스토리를 메시지 배열로 변환

참고 문서:
{context}
"""}
    ]

    # 이전 대화 추가
    for msg in chat_history:
        messages.append({
            "role": "user" if msg['type'] == 'user' else "assistant",
```

### 5.3 STT 시스템

#### 5.3.1 개요

CALL-ACT 시스템은 실시간 음성 인식을 위해 STT(Speech-to-Text) 시스템과 연동합니다. STT 시스템은 음성을 텍스트로 변환하고, 키워드를 추출하여 RAG 검색에 활용합니다.

#### 5.3.2 처리 흐름

```
1. 고객/상담사 음성 인입
   ↓
2. STT 시스템: 음성 스트림 → 텍스트 변환 (실시간)
   ↓
3. 텍스트 → consultation_transcripts 테이블에 저장
   ↓
4. 키워드 추출 (NLP 기반)
   ↓
5. 키워드 → stt_keywords 테이블에 저장
   ↓
6. 키워드 → RAG 검색 트리거
```

#### 5.3.4 키워드 추출 알고리즘

```python
from typing import List, Dict

def extract_keywords(text: str) -> List[Dict[str, any]]:
    """
    텍스트에서 키워드 추출
    (실제로는 NLP 라이브러리 또는 별도 키워드 추출 API 사용)
    """
    # 예시: 간단한 키워드 매칭
    keyword_map = {
        "카드분실": ["카드", "분실", "잃어버렸", "없어졌"],
        "해외결제": ["해외", "외국", "외화", "달러", "엔화"],
        "수수료문의": ["수수료", "비용", "요금", "청구"],
        "연회비": ["연회비", "회비", "annual fee"],
        "재발급": ["재발급", "다시", "새로", "발급"]
    }

    extracted = []
    for keyword, synonyms in keyword_map.items():
        for synonym in synonyms:
            if synonym in text:
                extracted.append({
                    "keyword": keyword,
                    "confidence": 0.9  # 실제로는 NLP 모델이 계산
                })
                break

    return extracted
```

#### 5.4.3 API 요청 제한 (Rate Limiting)

```python
from redis import Redis
from datetime import timedelta

redis_client = Redis(host='localhost', port=6379, db=0)

def check_rate_limit(api_key: str, limit: int = 100, window: int = 60) -> bool:
    """
    API 요청 제한 확인 (Redis 기반)
    """
    key = f"rate_limit:{api_key}"
    count = redis_client.get(key)

    if count is None:
        redis_client.setex(key, window, 1)
        return True
    elif int(count) < limit:
        redis_client.incr(key)
        return True
    else:
        return False
```

## 6. 성능 최적화 전략

### 6.1 캐싱 전략

#### 6.1.1 Redis 캐싱

**캐싱 대상**:
- 자주 조회되는 FAQ
- 공지사항
- 카드 상품 정보
- OpenAI Embedding 결과 (동일 텍스트)

**캐시 TTL (Time-To-Live)**:

| 데이터 종류 | TTL | 이유 |
|-----------|-----|------|
| FAQ | 24시간 | 자주 변경되지 않음 |
| 공지사항 | 1시간 | 실시간 업데이트 필요 |
| 카드 상품 정보 | 12시간 | 일 1-2회 업데이트 |
| Embedding 결과 | 7일 | 재사용 가능성 높음 |

**구현 예시**:

```python
import redis
import json
from typing import Optional

redis_client = redis.Redis(host='localhost', port=6379, db=0)

def get_cached_faq(faq_id: int) -> Optional[dict]:
    """
    캐시에서 FAQ 조회
    """
    key = f"faq:{faq_id}"
    cached = redis_client.get(key)
    if cached:
        return json.loads(cached)
    return None

def set_cached_faq(faq_id: int, data: dict, ttl: int = 86400):
    """
    FAQ를 캐시에 저장 (TTL: 24시간)
    """
    key = f"faq:{faq_id}"
    redis_client.setex(key, ttl, json.dumps(data))

def get_or_fetch_faq(faq_id: int) -> dict:
    """
    캐시 우선 조회, 없으면 DB 조회 후 캐싱
    """
    cached = get_cached_faq(faq_id)
    if cached:
        return cached

    # DB 조회
    faq = fetch_faq_from_db(faq_id)

    # 캐시 저장
    set_cached_faq(faq_id, faq)

    return faq
```

#### 6.1.2 캐시 무효화 전략

- **Write-Through**: 데이터 업데이트 시 캐시도 동시 업데이트
- **Cache Invalidation**: 데이터 변경 시 관련 캐시 즉시 삭제

```python
def update_faq(faq_id: int, new_data: dict):
    """
    FAQ 업데이트 + 캐시 무효화
    """
    # DB 업데이트
    update_faq_in_db(faq_id, new_data)

    # 캐시 삭제
    redis_client.delete(f"faq:{faq_id}")
```

### 6.3 벡터 검색 최적화

#### 6.3.1 IVFFlat vs HNSW 인덱스

**IVFFlat** (Inverted File with Flat Compression):
- 빠른 근사 검색
- 중소 규모 데이터셋에 적합 (~100만 벡터)
- 메모리 사용량 낮음

```sql
CREATE INDEX idx_service_guide_embedding ON service_guide_documents
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);
```

**HNSW** (Hierarchical Navigable Small World):
- 높은 정확도
- 대규모 데이터셋에 적합 (100만+ 벡터)
- 메모리 사용량 높음

```sql
CREATE INDEX idx_consultation_embedding_hnsw ON consultation_documents
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

#### 6.3.2 벡터 검색 파라미터 튜닝

**IVFFlat 파라미터**:

| 파라미터 | 권장값 | 설명 |
|---------|-------|------|
| `lists` | `sqrt(총 벡터 수)` | 클러스터 수 (100-1000) |
| `probes` | `lists / 10` | 검색할 클러스터 수 (10-50) |

```sql
-- 검색 시 probes 설정
SET ivfflat.probes = 10;

SELECT *
FROM service_guide_documents
ORDER BY embedding <=> '[쿼리 벡터]'
LIMIT 10;
```

**HNSW 파라미터**:

| 파라미터 | 권장값 | 설명 |
|---------|-------|------|
| `m` | 16 | 그래프 연결 수 |
| `ef_construction` | 64 | 인덱스 생성 시 탐색 범위 |
| `ef_search` | 40 | 검색 시 탐색 범위 |

```sql
-- 검색 시 ef_search 설정
SET hnsw.ef_search = 40;

SELECT *
FROM consultation_documents
ORDER BY embedding <=> '[쿼리 벡터]'
LIMIT 10;
```

#### 6.3.3 벡터 검색 벤치마크

**테스트 조건**:
- 데이터셋: 10,000 벡터
- 차원: 1536 (OpenAI text-embedding-3-small)
- 쿼리: Top-10 유사도 검색

| 인덱스 | 검색 시간 | Recall@10 | 메모리 사용 |
|-------|---------|-----------|-----------|
| No Index | 1200ms | 100% | - |
| IVFFlat (lists=100) | 15ms | 95% | 50MB |
| HNSW (m=16) | 8ms | 98% | 150MB |

### 6.5 비동기 처리

#### 6.5.1 백그라운드 작업

**Celery를 사용한 비동기 임베딩 생성**:

```python
from celery import Celery

celery_app = Celery('call_act', broker='redis://localhost:6379/0')

@celery_app.task
def generate_embedding_async(consultation_id: str, text: str):
    """
    상담 요약본 임베딩 생성 (백그라운드)
    """
    # OpenAI Embedding API 호출
    embedding = get_embedding(text)

    # DB 업데이트
    db = SessionLocal()
    db.execute("""
        UPDATE consultation_documents
        SET embedding = :embedding
        WHERE consultation_id = :consultation_id
    """, {"embedding": embedding, "consultation_id": consultation_id})
    db.commit()
    db.close()
```
