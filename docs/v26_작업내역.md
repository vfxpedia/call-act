## 핵심 변경 요약

v26은 **검색 품질 고도화** (실제 유사도 점수, 백엔드 searchTime), **문서 타입 DB↔화면 매핑**, **TTS 문장 단위 스트리밍**을 중심으로 한 운영 품질 개선 버전입니다.

| 영역 | 주요 변경 |
|------|----------|
| 검색 점수 | 백엔드 실제 score → relevanceScore (0~100) 프론트 전달 |
| 검색 속도 | 백엔드 searchTime (ms) API 응답 추가 |
| 문서 타입 | DB document_type → 화면 5종 매핑 (`terms`, `product-spec`, `guide`, `general`, `analysis-report`) |
| TTS 스트리밍 | 문장 분할 순차 TTS → WebSocket audio_chunk 전송 → 프론트 큐 재생 |

## 1. 검색 유사도 점수 + searchTime

### 1-1. 백엔드 변경

| 파일 | 변경 |
|------|------|
| `backend_dev/app/rag/pipeline/card_pipeline.py` | 각 카드에 원본 doc `score` → `_score` 필드 첨부 |
| `backend_dev/app/api/v1/endpoints/rag_frontend.py` | `relevanceScore`, `searchTime` API 응답 추가 |

#### card_pipeline.py — `_score` 첨부
```python
# 각 카드에 원본 doc score 첨부 (프론트엔드 relevanceScore용)
for idx, card in enumerate(cards):
    if idx < len(docs):
        raw_score = docs[idx].get("score")
        card["_score"] = float(raw_score) if isinstance(raw_score, (int, float)) else 0.0
    else:
        card["_score"] = 0.0
```

#### rag_frontend.py — API 응답
```python
# _to_front_card()에 추가
"relevanceScore": min(100, round(float(card.get("_score") or 0) * 100, 1)),

# 엔드포인트 응답에 추가
"searchTime": search_time_ms,  # 전체 RAG 파이프라인 소요 시간 (ms)
```

### 1-2. 프론트엔드 변경

| 파일 | 변경 |
|------|------|
| `frontend_dev/src/utils/searchSimulator.ts` | 백엔드 `relevanceScore` 사용 (하드코딩 제거), `searchTime` 백엔드 우선 |
| `frontend_dev/src/app/components/consultation/SearchHistoryDropdown.tsx` | 결과 건수 표시, 점수 `.toFixed(1)점` 표시 |

#### searchSimulator.ts 변경 전후
```typescript

// v26 (백엔드 실제 점수)

#### SearchHistoryDropdown 변경
```
v25: "검색 이력 3건"           → v26: "검색 이력 3건 (2개 문서)"

```

### 1-3. 점수 흐름
```
[DB 검색] → doc.score (float, 0.0~1.0+)
    ↓
[card_pipeline] → card._score (float)
    ↓
[rag_frontend] → relevanceScore: min(100, score * 100) (0~100)
    ↓
[searchSimulator] → card.relevanceScore (프론트에서 표시)
    ↓
[SearchHistoryDropdown] → "유사도 85.3점"

## 3. TTS 문장 단위 스트리밍

### 3-1. 배경: Qwen3-TTS 스트리밍 조사 결과

| 방식 | TTFB | 청크 간격 | 비고 |
|------|------|----------|------|
| 현재 (전체 파일) | 5~15초 | N/A | 동기 1회 호출 |
| **문장 분할 (채택)** | **2~4초** | **2~4초/문장** | 서버 변경 불필요 |
| CloudWells KV-cache | ~3초 | ~0.6초 | RunPod 서버 수정 필요 |
| DashScope API | ~97ms | 실시간 | 외부 API, 비용 발생 |

**채택 사유**: 문장 분할 방식은 기존 RunPod TTS 서버 변경 없이 즉시 적용 가능. 첫 문장 오디오가 준비되면 즉시 재생 시작.

### 3-2. 백엔드 구현

| 파일 | 변경 |
|------|------|
| `backend_dev/app/llm/education/tts_speaker.py` | `_split_sentences()`, `process_agent_input_streaming()` 추가 |
| `backend_dev/app/llm/education/edu_handler.py` | 스트리밍 호출 + WebSocket 청크 전송 |

#### tts_speaker.py — 스트리밍 함수
```python
def process_agent_input_streaming(session_id, agent_message, input_mode="text"):
    """
    Generator 함수: 문장 단위 TTS 스트리밍

    Yields:
        {"type": "text", "customer_response": str, "turn_number": int}
        {"type": "audio_chunk", "audio_url": str, "chunk_index": int, "total_chunks": int}
        {"type": "audio_done"}

```

#### 문장 분할
```python
def _split_sentences(text):
    # 한국어 문장 종결 부호(.!?。) 기준 분할
    parts = re.split(r'(?<=[.!?。])\s*', text.strip())
    return [s.strip() for s in parts if s.strip()]
```

#### edu_handler.py — WebSocket 전송 흐름
```python
# 1. 스레드 풀에서 스트리밍 generator 실행
chunks = await asyncio.to_thread(_run_streaming)

# 2. 순차 WebSocket 전송
for chunk in chunks:
    if chunk["type"] == "text":
        # 텍스트 즉시 전송 (프론트 화면 표시)
        await websocket.send_json({"type": "customer_response", ...})
    elif chunk["type"] == "audio_chunk":
        # 오디오 청크 전송 (프론트 큐에 추가)
        await websocket.send_json({"type": "audio_chunk", ...})
    elif chunk["type"] == "audio_done":
        await websocket.send_json({"type": "audio_done"})
```

### 3-3. 프론트엔드 구현

| 파일 | 변경 |
|------|------|
| `frontend_dev/src/app/hooks/useVoiceRecoders.ts` | `AudioChunkData` 타입, `onAudioChunk`/`onAudioDone` 콜백 |
| `frontend_dev/src/app/pages/RealTimeConsultationPage.tsx` | 오디오 큐 + `playNextChunk()` 순차 재생 |

#### 새로운 WebSocket 메시지 타입

| 타입 | 방향 | 설명 |
|------|------|------|
| `audio_chunk` | → 프론트 | 문장 단위 TTS 오디오 URL + chunk_index/total_chunks |
| `audio_done` | → 프론트 | 전체 TTS 스트리밍 완료 |

#### 오디오 큐 순차 재생
```typescript
// 큐에 오디오 URL 추가
const handleAudioChunk = (data: AudioChunkData) => {
    audioQueueRef.current.push(data.audio_url);
    playNextChunk(); // 재생 중 아니면 즉시 시작
};

// 순차 재생: 현재 청크 끝나면 다음 청크 자동 시작
const playNextChunk = () => {
    if (isPlayingChunkRef.current || audioQueueRef.current.length === 0) return;
    const nextUrl = audioQueueRef.current.shift();
    const audio = new Audio(`http://127.0.0.1:8000${nextUrl}`);
    audio.onended = () => { isPlayingChunkRef.current = false; playNextChunk(); };
    audio.play();
};
```

### 3-4. TTS 스트리밍 전체 흐름
```
[상담원 발화]
    ↓
WebSocket → STT → handle_agent_message()
    ↓
process_agent_input_streaming()
    ├─ sLLM 고객 응답 생성: "네, 알겠습니다. 카드 분실 접수 도와드리겠습니다. 본인 확인 부탁드립니다."
    ├─ yield {"type": "text", ...}     ← 프론트: 텍스트 즉시 표시
    ├─ 문장 분할: ["네, 알겠습니다.", "카드 분실 접수 도와드리겠습니다.", "본인 확인 부탁드립니다."]
    ├─ TTS("네, 알겠습니다.") → yield {"type": "audio_chunk", chunk_index: 0}    ← 프론트: 즉시 재생 시작
    ├─ TTS("카드 분실 접수...") → yield {"type": "audio_chunk", chunk_index: 1}  ← 프론트: 큐에 추가
    ├─ TTS("본인 확인...") → yield {"type": "audio_chunk", chunk_index: 2}       ← 프론트: 큐에 추가
    └─ yield {"type": "audio_done"}    ← 프론트: 스트리밍 종료 로그
```

## 테스트 방법

### 1. 검색 유사도 점수 테스트
- 검색 어시스턴트에서 검색 실행
- 검색 이력 드롭다운 → 문서별 "유사도 XX.X점" 확인
- 브라우저 Network 탭 → `/api/v1/rag/` 응답에서 `relevanceScore`, `searchTime` 확인

### 2. 문서 타입 테스트
- 검색 결과 카드 → `documentType` 필드 확인
- card_products 문서 → `product-spec`
- service_guide terms → `terms`
- service_guide guide → `guide`

### 3. TTS 스트리밍 테스트
- 교육 시뮬레이션 시작
- 음성/텍스트 입력 → 콘솔 확인:
  - `[교육] AI 고객 응답:` (텍스트 즉시)
  - `[TTS] 오디오 청크 수신: 1/3`
  - `[TTS] 오디오 청크 수신: 2/3`
  - `[TTS] 오디오 청크 수신: 3/3`
  - `[TTS] 스트리밍 완료`
- 첫 문장 오디오가 나머지 생성 전에 재생 시작되는지 확인
