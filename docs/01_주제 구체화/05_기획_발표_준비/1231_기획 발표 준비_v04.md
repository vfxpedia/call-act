## 1. 프로젝트 개요

### 1.1 팀 소개

**팀명**: (가제)1팀

**서비스명**: **CALL-ACT**

**슬로건**: "CALL-ACT는 카드 상담사가 흩어진 약관과 정책을 한눈에 확인하고 즉시 정확한 처리를 할 수 있도록 돕는 상담 지원 서비스입니다."

### 1.2 프로젝트 소개

카드사 상담사의 업무 효율성 향상을 위한 **AI 기반 실시간 문서 검색 및 감정 분석 지원 시스템**

### 1.3 프로젝트 배경

#### 1.3.1 카드사 상담 환경의 복잡성

카드사 상담사는 다음과 같은 복잡한 업무 환경에서 근무합니다:

- **방대한 정보량**: 수십 종의 카드 상품, 각각의 약관, 혜택, 이벤트 정보를 실시간으로 파악해야 함
- **빈번한 정보 변경**: 카드 혜택, 이벤트, 정책이 매월 변경되어 지속적인 학습 필요
- **다중 시스템 참조**: 상담 중 KMS, 약관 문서, FAQ, 정책 자료 등 여러 시스템을 동시에 검색해야 함
- **높은 정확성 요구**: 금융 규제 및 준법 준수 요구로 인해 오답/과장 안내 시 법적 리스크 발생

#### 1.3.2 상담사의 업무 부담

**1차 멘토링 회의(2025.12.22)에서 확인된 핵심 문제점**:

- **정보 과부하**: 고객의 질문에 답하기 위해 다수 문서/시스템에서 정보를 동시에 탐색해야 하는 부담
- **긴 교육 기간**: 입사 후 교육 30일 이상(38%), 단독 상담까지 30일 이상(41.4%) 소요
- **감정 노동**: 감정이 격앙된 고객을 응대하면서 과도한 스트레스와 심리적 소진 경험
- **후처리 부담**: 상담 종료 후 요약, 분류, 기록 업무로 실질적인 AHT/ACW 증가

#### 1.3.3 기존 AI 시스템의 한계

- **고객 대면 AI 챗봇의 한계**: 고객들은 여전히 인간 상담원을 선호(64.6%)하며, AI 챗봇 만족도는 21.6%에 불과
- **상담사 지원 부족**: 기존 시스템은 고객 대체에 집중하고 상담사의 실시간 업무 지원은 미흡

## 2. 문제 정의 및 사용자 요구 분석

### 2.1 카드사 및 콜센터 현황

#### 2.1.1 AI 도입의 역설적 문제

카드사와 고객센터에 AI 상담 시스템이 도입되면서, 상담 효율을 높이려는 취지와 달리 **고객 불편과 상담사 스트레스가 동시에 증가**하는 문제 발생:

- 고객은 반복적인 ARS 절차와 긴 대기 시간으로 인해 상담 전부터 불만 누적
- 상담사는 이미 감정이 격앙된 고객을 응대하며 과도한 감정 노동에 노출됨
- AI 도입의 기대 대비 실효성 부족
  - ⇒ 상담 품질 저하와 상담사 이탈
  - ⇒ 기업의 고객 신뢰를 약화시키는 악순환

**참고 자료**:
- https://www.kpinews.kr/newsView/1065593029467679
- https://kbthink.com/investment/deepdive/research/251013-2.html

#### 2.1.2 PLCC 확장에 따른 복잡성 증가

PLCC(Private Label Credit Card)의 무분별한 확장으로 인해 사용 범위와 혜택이 제각각인 카드들을 사용자가 숙지하기 어려움:

- 카드사에서 직원 대상 교육이 복잡해지면서 피로 유발
- 상담사는 수십 개의 상품·약관·혜택 정보를 실시간으로 조회·응답해야 함

**참고 자료**:
- https://stripe.com/resources/more/what-are-private-label-credit-cards-heres-what-businesses-should-know-about-white-label-cards

### 2.2 상담원 업무 부담의 구조적 요인

#### 2.2.1 고용 형태에 따른 정보 접근 제한

아르바이트나 간접고용 형태의 상담사들은 내부 시스템에 접근이 제한되어 상담원 본인이 정보를 몰라 상담이 막힘:

- 관리자의 지나친 통화 감청 및 모니터링과, 상담원이 답변할 수 없는 케이스에 대한 부정적 피드백으로 인해 부당함을 느끼는 경우 존재

**참고 자료**:
- https://www.humanrights.go.kr/base/board/read?boardManagementNo=17&boardNo=7608231 (국가인권위원회 콜센터 노동자 실태조사)

#### 2.2.2 방대한 정보량과 전문성

**콜센터 노동 실태 설문 조사 결과**:

| 항목 | 세부 내용 | 비율 |
|------|-----------|------|
| 입사 후 교육 기간 | 30일 이상 | 38% |
| 관리자 동석 교육 | 30일 | 25% |
| 단독 상담까지 교육 기간 | 30일 이상 | 41.4% |
| 상담원이 다루는 정보의 범위 | 넓다 | 70% |
| 상담원이 다루는 정보의 전문성 | 전문적이다 | 60% |

**핵심 문제**:
- 정보를 다루는 범위가 넓고 전문적이다 → 모든 정보를 기억하는 것이 아닌 **상황에 따라 필요한 정보를 검색하여 고객에게 응답**
- **상담 중 카드 약관, 혜택, 정책을 여러 시스템/문서에서 동시에 찾아야 함**
- **상담 종료 후 요약, 분류, 후처리 업무로 실질적인 업무 부담 증가**

**참고 자료**:
- https://kossda.snu.ac.kr/handle/20.500.12236/30741
- https://www.laborplus.co.kr/news/articleView.html?idxno=32034

#### 2.2.3 정보 과부하 및 KPI 부담 (내부 조사 요약)

**상담사 업무의 본질**:
- 상담사 업무는 단순 대화 응대가 아니라 **다수 정보 소스 동시에 조회/활용**이 필요함
- 스크립트/약관/정책/예외 규정/지원 케이스 등 여러 데이터 소스 교차 실시간 의사결정
- 고객 문제마다 참조 문서가 다르며, 즉각적 해답을 찾기 어려움
- 고객 대기 시간 증가 → 상담사 스트레스 가중

**핵심 KPI와 부담**:
- **AHT (Average Handle Time)**: 상담 1건을 마무리하는 데 걸리는 총 시간 (상담 내용 숙지 + 문서 검색 + 응답 + 후속 처리)
- **FCR (First Contact Resolution)**: 첫 통화에서 문제를 해결하는 비율
- 불완전 정보/불충분 문서 검색으로 FCR 낮아짐 → 재통화 증가 → 상담사 부담 증가

**참고**: [내부 문서: 현재 시스템의 문제점 파악](./내부 문서/현재 시스템의 문제점 파악.md)

### 2.3 신입 상담원의 추가 어려움

- 실제 상담 경험이 부족해 매뉴얼을 외워도 응용이 어려움
- 고객의 말투, 감정에 따라 대응 방식을 조절하기 어려움
- 실수에 대한 부담으로 상담 중 긴장도 높음

### 2.4 사용자 요구 분석

#### 2.4.1 카드사 입장

**1) 고객 만족도 향상 및 신뢰도 회복**

금융사들이 AI를 고도화하고 있지만 **금융소비자들은 여전히 인간 상담원을 더 선호**함:

- 금융회사 콜센터에 더 필요한 것이 무엇인지를 묻는 말(복수 응답)에 **'인간 상담원 상담까지 소요 시간 단축'이라고 답한 응답자가 전체의 64.6%**로 가장 많음

**참고 자료**:
- https://www.asiae.co.kr/article/2024081208172521711
- https://kbthink.com/investment/deepdive/research/251013-2.html

**2) 정량적·객관적 평가 지표 필요**

콜센터에서는 통화 시간, 발화 횟수, 감정 점수 등 정량적 지표 중심의 직원 평가가 이루어지지만:

- 직원 스트레스를 증가시키고 직무만족을 저하시킬 뿐 아니라 성과 향상에는 기여하지 못함
- **'측정 가능한 지표 중심 평가'가 기업이 기대하는 성과, 효율, 안정성을 구조적으로 달성하지 못함**
- 단순 감시, 정량 점수 중심 평가가 아닌 **맥락, 질, 정서, 지원 요소를 반영한 올바른 평가 재정리 필요**

**3) 생산성 향상을 통한 운영 효율 개선**

상담원의 정보시스템 검색 능력이 성과에 영향을 미침:

- 상담원 개개인의 경력/정보력 편차로 인해 상담 품질의 표준화가 어려우며, 이는 단순 인원 확충으로 해결되지 않는 문제

**참고 자료**:
- https://www.dbpia.co.kr/journal/articleDetail?nodeId=NODE07214954
- https://www.outsourcing.co.kr/news/articleView.html?idxno=201080

**4) 신입 상담원의 빠른 실무 적응을 통한 교육 비용 절감**

- 교육 기간이 길어질 경우 비용이 불어나고, 만약 그 안에 신입 상담원이 퇴사하면 또 신입을 채용해 다시 교육해야 하는 비효율의 악순환
- 교육 기간이 짧아질 경우 신입 상담원이 미흡한 상태로 현장에 투입되어 어려움 호소

**참고 자료**:
- https://www.newsprime.co.kr/news/article/?no=593085

#### 2.4.2 상담원 입장

**1) 숙지해야 하는 정보가 많은 것에서 오는 부담 해소**

고객의 목적이 무엇인지 모르는 상태에서, 어떤 지식을 접목시켜야 할지 몰라 불확실함과 불안감을 경험:

- 다양한 정보들 중에서 고객에게 무엇을 제공해야 하는지 모르는 상황이 상담원의 업무 부적응 초래

**참고 자료**:
- https://www.dbpia.co.kr/journal/articleDetail?nodeId=NODE11580071

**2) 상담 맥락에 맞는 핵심 정보 요약 제공**

상담 중 단순 키워드 검색이 아닌 **상담 맥락에 맞는 핵심 정보만 요약된 형태로 제공**되길 원함:

- 국내 사용자 참여 디자인 워크숍 기반 연구에서 상담원들은 상담 중 핵심 정보 요약, 자동 기록과 같은 지원 기능이 업무 효율과 스트레스 경감에 도움이 된다는 피드백 제공

**참고**: [참고자료/AI기반_콜센터_감정노동_지원_서비스_디자인_연구_성신여대_2025.pdf](./참고자료/AI기반_콜센터_감정노동_지원_서비스_디자인_연구_성신여대_2025.pdf)

**3) 반복적인 후처리 업무 부담 감소**

- 반복적인 상담 내용 기록, 요약, 분류, 후처리 업무 부담 감소
- 객관적인 피드백 희망

#### 2.4.3 신입 상담원 입장

- 실제 상담 사례를 기반으로 한 연습 환경 필요

### 3.1 참고 서비스 분석

#### 3.1.1 AI 상담 챗봇

**대표 사례**: 신한카드 AI-SOLa(아이쏠라), KB국민카드 모두의 카드생활 메이트

![AI상담사 설명](./내부 문서/image_AI상담사.png)

**신한카드 AI-SOLa 개요** (2025년 1월 출시):
- 생성형 AI가 탑재된 상담 지원 시스템
- **STT + sLLM + RAG** 기반 실시간 상담 지원
- 10만 건 이상의 내부 상담 정보를 RAG 구조로 정비
- 1만 3,000여 건의 고객 상담 데이터 반복 학습
- 상담원에게 최적 답변 실시간 제공 + 표준 스크립트 + 후속 업무 자동화

**한계**:
- 감정적 문제나 복잡한 상담에서는 인간 대응이 부족
- 고객들은 여전히 인간 상담원을 더 선호
- 디지털 취약 계층에게는 이용 장벽으로 작용하여 고객의 신뢰도 하락

**참고 자료**:
- https://www.businessplus.kr/news/articleView.html?idxno=89288

**금융권 AI 챗봇 고객 만족도 현황**:

### 3.2 차별점

#### 3.2.1 핵심 차별화 전략

**1) 고객을 대체하는 AI가 아닌 상담사를 지원하는 보조형 AI**

- 고객이 선호하는 건 여전히 인간 상담원
- AI가 직접 고객을 응대하지 않고 **상담사가 더 빠르고 정확하게 대응할 수 있도록 실시간으로 지원**
- 상담 효율, 품질, 상담사 만족도를 동시에 개선하는 **사람 중심 AI 접근**

**2) 단순 키워드 검색을 넘어서는 STT + RAG 기반 문서 검색**

- 상담 내용을 음성(STT)으로 자동 인식하여 상담사가 직접 키워드를 입력하지 않아도 필요한 정보를 즉시 제공
- 검색 부담을 줄여 응답 시간 단축 및 상담 집중도 향상

**3) 실시간 고객 감정 분석 및 시각화 시스템** ⭐ 최대 차별점

CALL-ACT의 가장 큰 차별점은 고객 감정을 실시간으로 분석하고 시각화하여 상담사를 보호하고 지원하는 것입니다:

- **실시간 감정 모니터링**: 통화 중 고객 감정(분노, 평온, 대기, 만족 등)을 실시간으로 분석하여 상담사 화면에 표시
- **감정 변화 그래프**: 시간에 따른 고객 감정 변화를 직관적인 그래프로 시각화
- **상담사 보호**: 악성 민원이나 과도한 감정 격양 상황을 객관적 데이터로 기록하여 상담사의 합리적 대응 입증
- **객관적 평가 근거**: 감정 분석 데이터를 바탕으로 상담사의 성과를 공정하게 평가
- **매뉴얼 개선**: 감정 패턴 분석을 통해 상담 가이드라인 및 교육 자료 개선

이는 기존 시스템에서는 제공하지 않는 CALL-ACT만의 핵심 기능입니다.

**4) 매뉴얼 중심 교육을 넘어서는 실제 상담 사례 기반 시뮬레이션**

- 이론적 매뉴얼 제공이 아닌 실제 응대했던 고객 사례를 바탕으로 한 현실적인 페르소나 제공

**5) 카드 상품뿐만 아니라 다양한 정부 정책 데이터를 함께 제공**

- 공공 데이터와 금융 데이터가 결합된 고차원 상담 지원

## 4. 기대효과

### 4.1 운영 효율성 극대화

**1) 상담 시간 단축**

- 실시간 문서 검색 지원으로 상담원의 정보 탐색 시간을 획기적으로 줄여, 전체 평균 상담 처리 시간을 단축

**2) 비용 절감**

- 상담 후처리 자동화를 통해 불필요한 행정 업무 시간을 줄임으로써, 동일 인원 대비 더 많은 콜 처리가 가능해져 운영 비용 절감

- 상담원 개인의 경력이나 정보력 편차에 의존하지 않고, AI가 제공하는 표준화된 가이드라인(약관, 정부 정책 등)을 통해 균일한 고품질 상담 제공

- https://enterprise.kt.com/bt/mediareport/3376.do

### 4.2 상담원 업무 환경 및 만족도 개선

**1) 업무 부하 및 스트레스 감소**

- 수십 개의 창을 띄워놓고 검색하는 비효율성에서 벗어남
- 일일이 타이핑하던 상담 요약 업무가 자동화되어 업무 피로도 감소

**2) 심리적 보호 및 케어**

- 악성 민원이나 감정 노동에 대한 객관적 데이터(감정 분석)를 확보하여, 무조건적인 친절 강요가 아닌 합리적인 보호 조치 및 피드백 근거 마련

**3) 신입 상담원의 빠른 적응**

- 실제 사례 기반의 페르소나 시뮬레이션을 통해 안전한 환경에서 실무 경험

### 4.3 고객 경험 혁신

**1) 대기 시간 없는 정확한 답변**

- 복잡한 질문에 대한 답변이나 정부 정책까지 즉각적으로 정확한 안내

**2) 인간적 교감과 신뢰**

- 딱딱한 기계음(ARS/챗봇)이 아닌, AI의 지원을 받아 여유가 생긴 전문 상담원과 소통하며 정서적 만족감과 기업 신뢰도 회복

## 6. 성과 지표

### 6.1 STT (Speech-to-Text)

| 성과 지표 | 측정 방법 (Metric) | 목표치 | 측정 기준 | 비고 |
|-----------|-------------------|--------|----------|------|
| 인식 정확도 | WER (Word Error Rate) | 0.1 미만 | 잘못 인식한 단어 / 총 단어 수 | 금융 도메인 용어 기준 |
| 실시간성 | RTF (Real Time Factor) | 0.5 이하 | 처리 시간 / 음성 재생 시간 | 지연 없는 텍스트 변환 |

**WER 계산 방법**:

```
WER = (S + D + I) / N

S (Substitutions): 잘못된 단어로 대체된 단어의 수
D (Deletions): 인식하지 못한 단어의 수
I (Insertions): 잘못 삽입된 단어의 수
N (Total Words): 참조(기준) 문장에 있는 총 단어의 수
```

### 6.2 RAG (Retrieval-Augmented Generation)

| 성과 지표 | 측정 방법 (Metric) | 목표치 | 측정 기준 | 비고 |
|-----------|-------------------|--------|----------|------|
| 답변 신뢰성 | RAGAS Faithfulness | 0.9점 이상 | 생성된 답변 중 검색된 문맥으로 추론 가능한 주장 비율 | LLM 자체 평가 + 샘플링 휴먼 검증 (월 100건) |
| 검색 정확도 | Recall@3 (Top-3 재현율) | 90% 이상 | 상위 3개 결과 내 정답 문서 포함 여부 | 정답 문서가 Top-3 내 존재 |
| 응답 속도 | End-to-End Latency | 3초 이내 | 질문 입력 ~ 답변 출력 시간 | 사용자 대기 시간 최소화 |

**RAGAS Faithfulness 측정 방법**:
1. LLM이 생성한 답변의 각 주장(claim)을 추출
2. 검색된 문맥(context)에서 해당 주장을 뒷받침할 수 있는지 LLM이 자체 평가
3. 뒷받침 가능한 주장 수 / 전체 주장 수 = Faithfulness Score
4. 매월 100건 샘플링하여 휴먼 검증으로 보정

### 6.3 후처리 (Post-processing)

| 성과 지표 | 측정 방법 (Metric) | 목표치 | 측정 기준 | 비고 |
|-----------|-------------------|--------|----------|------|
| 요약 품질 | ROUGE-L Score | 0.45 이상 | 전문가 요약문과의 단어·문장 겹침 비율 | 핵심 내용 포함 여부 |
| 분류 정확도 | Macro F1-Score | 0.9 이상 | Precision과 Recall의 조화 평균 | 상담 카테고리 자동 분류 |

### 6.4 비즈니스 임팩트

| 성과 지표 | 측정 방법 (Metric) | 목표치 | 측정 기준 | 비고 |
|-----------|-------------------|--------|----------|------|
| 업무 효율 | AHT 단축률 | 30% 단축 | (기존 AHT - 개선 후 AHT) / 기존 AHT | AHT = 통화 시간 + 후처리 시간 + 대기 시간 |
| 후처리 시간 | ACW 단축률 | 30% 단축 | (기존 ACW - 개선 후 ACW) / 기존 ACW | ACW = 통화 후 후처리 작업 시간 |

**측정 방법**: 시뮬레이션 테스트 기준

## 7. 프로젝트 관리 및 협업 프로세스

### 7.1 WBS (Work Breakdown Structure)

#### Phase 1: 요구사항 분석 및 설계 (2주)

- 1.1 도메인 조사 및 Use Case 정의
- 1.2 데이터 수집 계획 수립
- 1.3 시스템 아키텍처 설계
- 1.4 기술 스택 선정

#### Phase 2: 데이터 준비 (2주)

- 2.1 카드사 공개 데이터 수집 (FAQ, 약관, 정책)
- 2.2 데이터 전처리 및 정제
- 2.3 벡터 DB 구축

#### Phase 3: 핵심 기능 개발 (4주)

**3.1 STT 모듈 구현 및 최적화**

**3.2 RAG 시스템 구현**
- 3.2.1 Embedding 모델 선정 및 파인튜닝
- 3.2.2 검색 알고리즘 구현
- 3.2.3 LLM 통합 (GPT-4 또는 Claude)

**3.3 후처리 모듈 구현**
- 3.3.1 요약 기능
- 3.3.2 카테고리 분류

#### Phase 4: 통합 및 테스트 (2주)

- 4.1 시스템 통합
- 4.2 성능 테스트 (WER, Recall, Latency 등)
- 4.3 사용자 테스트 (시뮬레이션)

#### Phase 5: 배포 및 운영 (1주)

- 5.1 배포 환경 구축
- 5.2 모니터링 시스템 구축
- 5.3 문서화

### 7.2 팀 협업 방법 및 규칙

#### 7.2.1 역할 분담

- **PM (Project Manager)**: 일정 관리, 이슈 트래킹
- **데이터 엔지니어**: 데이터 수집, 전처리, 벡터 DB 구축
- **백엔드 개발자**: RAG 시스템, STT 통합, API 개발
- **프론트엔드 개발자**: 상담원 UI/UX 구현
- **QA/테스터**: 성능 테스트, 사용자 테스트

#### 7.2.2 회의 주기

- **Daily Standup**: 매일 오전 10시, 15분 (진행 상황 공유)
- **Weekly Sprint Review**: 매주 금요일 오후 3시 (주간 목표 검토)
- **Biweekly Retrospective**: 격주 금요일 오후 4시 (개선 사항 논의)

#### 7.2.3 의사결정 프로세스

1. 이슈 발생 시 GitHub Issues에 등록
2. 관련 팀원 태그 및 논의
3. PM 최종 결정 후 마일스톤 업데이트

### 7.3 작업 관리 툴 및 도구

| 도구 | 용도 | 비고 |
|------|------|------|
| **GitHub** | 코드 버전 관리, 이슈 트래킹 | Main repository |
| **Notion** | 문서화, 회의록, 지식 베이스 | 팀 Wiki |
| **Slack** | 실시간 커뮤니케이션 | 채널별 분리 (#dev, #data, #design) |

### 7.4 기술 스택

#### 7.4.1 프론트엔드

- **Framework**: React.js
- **State Management**: Redux
- **UI Library**: Material-UI

#### 7.4.2 백엔드

- **Framework**: FastAPI (Python)
- **Database**: PostgreSQL (메타데이터), ChromaDB/Pinecone (벡터 DB)
- **LLM**: OpenAI GPT-4 Turbo 또는 Anthropic Claude Opus

#### 7.4.3 STT

- **Service**: Google Cloud Speech-to-Text 또는 Whisper API
- **언어 모델**: 한국어 최적화 모델

#### 7.4.4 RAG

- **Embedding**: OpenAI text-embedding-3-large
- **Vector Search**: FAISS 또는 Pinecone
- **Retrieval Strategy**: Hybrid Search (Keyword + Semantic)

#### 7.4.5 배포 및 인프라

- **Cloud**: AWS (EC2, S3, Lambda)
- **Container**: Docker
- **CI/CD**: GitHub Actions
- **Monitoring**: CloudWatch, Grafana
