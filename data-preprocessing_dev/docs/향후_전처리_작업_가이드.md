# 향후 전처리 작업 가이드

**작성일**: 2026-01-13  
**목적**: Backend/RAG 개발 중 전처리 개선이 필요할 때를 위한 워크플로우 가이드

---

## 1. 개요

Backend 개발, RAG 구현, 프론트엔드 연결 과정에서 전처리 개선이 필요할 수 있습니다.  
이 문서는 그런 상황에서 전처리 작업을 진행하는 방법을 안내합니다.

---

## 2. 전처리 작업이 필요한 경우

### 2.1 일반적인 시나리오

1. **RAG 개발 중**
   - 임베딩 품질 문제 발견 → 전처리 개선 필요
   - 청킹 전략 변경 → 전처리 스크립트 수정 필요
   - 검색 결과 품질 개선 → 키워드 사전 확장 필요

2. **프론트엔드/DB 연결 중**
   - 데이터 구조 불일치 발견 → 전처리 스크립트 수정 필요
   - 새로운 필드 추가 필요 → 전처리 스크립트 확장 필요
   - 데이터 형식 변경 필요 → 전처리 로직 수정 필요

3. **키워드 사전 개선**
   - 검색 품질 개선을 위한 키워드 추가/수정
   - 동의어, 유사어 확장
   - 패턴 매칭 규칙 개선

---

## 3. 워크플로우

### 3.1 기본 원칙

**핵심 원칙**: 모든 전처리 작업은 `data-preprocessing_dev` 폴더에서 진행하고, 테스트 완료 후 `data-preprocessing`으로 동기화합니다.

**참고**: [개발 환경 동기화 규칙](../../../docs/00_rules/03_개발환경_동기화_룰.md)

### 3.2 작업 순서

#### Step 1: 문제 파악 및 계획

1. **문제 확인**
   - RAG/DB 연결 중 발견된 문제
   - 데이터 구조 불일치
   - 검색 품질 개선 필요

2. **해결 방안 계획**
   - 어떤 전처리 스크립트를 수정해야 하는지
   - 어떤 데이터를 재처리해야 하는지
   - 테스트 방법

#### Step 2: 전처리 수정 (data-preprocessing_dev)

1. **브랜치 생성** (선택사항)
   ```bash
   cd data-preprocessing_dev
   git checkout -b feat/preprocessing-improvement
   ```

2. **스크립트 수정**
   - `data-preprocessing_dev/preprocess/teddycard/`에서 작업
   - 기존 스크립트 수정 또는 새 스크립트 작성
   - `config.py` 사용 권장 (경로 관리)

3. **테스트 실행**
   ```bash
   cd data-preprocessing_dev/preprocess/teddycard
   python 00_analyze_document_lengths.py  # 예시
   ```

#### Step 3: 결과 검증

1. **출력 데이터 확인**
   - `data-preprocessing_dev/data/teddycard/`에서 결과 확인
   - 데이터 구조, 품질 검증

2. **DB 적재 테스트** (필요한 경우)
   - `backend_dev/app/db/scripts/`에서 테스트
   - 데이터 적재 확인

#### Step 4: 동기화 및 커밋

1. **파일 복사**
   ```bash
   # 수정된 스크립트를 data-preprocessing으로 복사
   cp data-preprocessing_dev/preprocess/teddycard/*.py data-preprocessing/preprocess/teddycard/
   ```

2. **경로 수정** (필수)
   - 하드코딩 경로: `data-preprocessing_dev` → `data-preprocessing`
   - `config.py` 기본값: `'dev'` → `'prod'`
   - 문서 경로 예시 수정

3. **검증**
   ```bash
   cd data-preprocessing
   grep -r "data-preprocessing_dev" preprocess/teddycard/
   # 경로가 없어야 함
   ```

4. **커밋 및 PR**
   ```bash
   cd data-preprocessing
   git checkout -b feat/preprocessing-improvement
   git add preprocess/teddycard/
   git commit -m "feat: 전처리 스크립트 개선 (문제 해결)"
   git push origin feat/preprocessing-improvement
   # GitHub에서 PR 생성
   ```

## 4. 브랜치 전략

### 4.1 브랜치 유지

**현재 브랜치**:
- `feat/data-merge`: 통합 전처리 (현재 상태 유지, 참고용)
- `feat/preprocessing-hana`: 하나카드 전처리 (참고용 유지)

**새로운 전처리 작업**:
- `feat/preprocessing-improvement`: 전처리 개선 작업
- `feat/preprocessing-keywords`: 키워드 사전 개선
- `feat/preprocessing-rag-optimization`: RAG 최적화를 위한 전처리

### 4.2 브랜치 삭제 정책

**권장**: 프로젝트 종료 전까지 브랜치 유지
- 참고용으로 유용
- Git은 커밋 히스토리를 보존하므로 삭제해도 복구 가능
- 하지만 삭제하지 않는 것이 안전

**복구 방법** (브랜치 삭제 후):
```bash
# 커밋 해시로 복구
git checkout -b feat/data-merge d8f6d64

# 원격 브랜치로 복구
git checkout -b feat/data-merge origin/feat/data-merge
```

## 6. 주의사항

### 6.1 경로 관리

**⚠️ 중요**: 동기화 시 반드시 경로 참조를 프로덕션 경로로 수정해야 합니다.

**권장**: `config.py` 사용
```python
# ✅ 권장: config.py 사용
from config import OUTPUT_DIR, DATA_DIR

# ❌ 지양: 하드코딩
OUTPUT_DIR = BASE_DIR / "data-preprocessing_dev" / "data" / "teddycard"
```

**상세 가이드**: [개발 환경 동기화 규칙](../../../docs/00_rules/03_개발환경_동기화_룰.md)

### 6.2 데이터 재처리

전처리 스크립트를 수정한 경우:
- 기존 데이터를 재처리해야 할 수 있음
- 재처리 전 백업 권장
- 재처리 후 DB 적재 필요

### 6.3 팀원과의 협의

전처리 변경이 팀원의 작업에 영향을 줄 수 있는 경우:
- 팀원과 사전 협의
- 변경 사항 문서화
- 영향 범위 확인
